# 思维模型决策工具 · v2.5

**遇到难题，先一步步看清，再找到处理办法。**

把工作、生活、学习或合作中的困惑告诉 AI。它会通过追问帮你说清问题，选择合适的思维工具组成工具箱，带你从多个角度分析，最后给出**解决思路、实施步骤和可保存的 HTML 行动计划**。

你不用先学思维模型，也不用先列好选项。从一句“我最近有件事想不明白……”就能开始。

**当前版本：2.5.0** · 156 个鬼子不言思维工具 · 100 个万维钢工具来源条目 · 面向支持技能或完整资料读取的 AI 智能体

[开始使用](#开始使用) · [完整操作示范](#操作示范) · [会得到什么](#你会得到怎样的解决方案) · [卡住了怎么办](#卡住了怎么办)

本次新增 **TM-156 决策树**：遇到“直接做，还是先测试再决定”的难题，把行动和信息出现的先后画清楚，从各分支的可能结果往回比较，形成“看到什么情况，就做什么”的行动规则；同时检查测试的信息价值、费用与等待代价，以及不能突破的损失上限。缺少可靠概率时先列待核实条件，不编造数字。

比如你说：“我想办一场活动，要直接投入，还是先找少量用户试一下？”助手会先问清目标和限制，再判断测试能否改变后续行动、是否值得付出代价。**你只需讲问题，不用先知道模型名称；先测试也不一定比直接做更好。**

## 怎样帮助你解决难题

**说出困惑 → 逐轮追问 → 看清问题 → 组建工具箱 → 综合解决方案 → 实施与反馈。**

| 过程 | AI 会做什么 | 你需要做什么 |
|---|---|---|
| 说出困惑 | 接住当前情境，不要求你先写成完整需求 | 用自己的话讲一件困扰你的事 |
| 逐轮追问 | 默认每轮一个关键问题，等你回答后再继续；提问也可以借助思维工具 | 讲真实经历，不知道就说不知道 |
| 看清问题 | 理清发生了什么、你想改变什么，以及事实、推断、限制和未知 | 纠正误解，确认你真正看重的事情 |
| 组建工具箱 | 围绕不同子问题选择互补工具，说明先看什么、再分析什么 | 不用选模型，也不必记住术语 |
| 形成方案 | 把各工具的分析结果接起来，比较可行路径，说明推荐依据 | 核对方案是否符合你的目标和条件 |
| 实施与反馈 | 给出先后步骤、资源安排、完成标志及调整条件；根据新反馈更新 | 执行自己决定采取的步骤，再带着结果回来 |

例如，“总是学了不会用”“合作总要我催”“项目卡住了却找不到原因”，都可以使用。它也能帮助比较选择，但不要求每个问题都是二选一。

**全面分析按问题需要展开。** 目标与价值、事实与原因、资源与约束、参与者、后续影响、可行路径、执行反馈，相关的视角都要顾及。简单问题可以只用一个工具，复杂问题可以组合多个；没有固定的模型数量上限，也不为了显得全面把所有工具都用一遍。

已有信息足够时，直接分析；出现关键缺口时，再追问。你随时可以要求先给阶段性方案或暂停，不需要固定答满几轮。

## 开始使用

这是一个 **Skill（技能包）**：供 AI 助手读取的流程与资料。你在自己的智能体里对话，GitHub 页面用于下载和查看说明。不同产品的安装方式和文件能力可能不同，先让助手检查即可。

**已安装的用户：** 确认是 **2.5.0** 且能读取资料后，直接跳到[说出第一件困惑](#说出第一件困惑)。不确定版本时用下面第2步检查；旧版请按[更新已有版本](docs/INSTALL.md#更新已安装版本)备份、保留本地修改后升级。GitHub 更新不会自动更新你的副本。

### 1. 让你正在使用的智能体安装或加载

把下面整段文字复制到它的**对话输入框**并发送。适用于不同品牌的智能体，不限于 Codex。

```text
请帮我安装或加载“思维模型决策工具” thinking-model-decision：
https://github.com/sushengs-creator/thinking-model-decision/tree/main/skills/thinking-model-decision

先检查当前环境：支持 Skills 就按本产品方式安装完整技能目录；
不能安装但能读取完整目录，就在本次会话加载入口及所需资料。
若已有版本，先备份并保留我的新增模型与修改，再更新。
不清楚产品或版本时再问我，不要猜测安装目录或菜单。
完成后实际读取 SKILL.md、一张模型卡和对应运行工具，
告诉我版本、采用的方式、下次如何调用，以及能否生成 HTML 文件。
若无法完成，请说明具体缺口与下一步，不要声称已经安装。
```

不能自动安装时，可[下载 v2.5.0 独立技能包](https://raw.githubusercontent.com/sushengs-creator/thinking-model-decision/main/dist/thinking-model-decision-v2.5.0.zip)。解压后，按当前产品的技能导入或工作区文件入口提供**完整的 `thinking-model-decision` 文件夹**，不要只复制 `SKILL.md`。

<details>
<summary>下载打不开、产品不支持 Skills，怎么办？</summary>

- 直链打不开：用[完整仓库备用下载](https://codeload.github.com/sushengs-creator/thinking-model-decision/zip/refs/heads/main)，解压后在 `dist` 中找到 `thinking-model-decision-v2.5.0.zip`。
- 产品接受 ZIP：按其导入格式要求使用；接受工作区目录：提供完整文件夹。具体见[手动安装与会话加载](docs/INSTALL.md#手动安装与会话加载)。
- 只能收聊天文字、无法读取完整资料：暂时不能运行完整工具库。只发一个 GitHub 链接不等于安装。
- 仅本次会话加载：换会话后需要重新提供目录。原生安装能否跨会话调用，取决于产品与安装范围。

</details>

助手应说明版本、安装或加载方式、实际读取的资料和下次调用方法。只有一句“安装成功”或一个技能名称，还不够。

应读到 **2.5.0** 及“可逆决策”卡，并能依据资料解释边界。这个检查确认当前会话可以读取资料，不代表所有客户端或未来会话都已验证。

</details>

### 3. 说出你的第一件困惑

安装或加载完成后，可以直接发送：

```text
请用思维模型决策工具帮我。
先每轮问我一个关键问题，等我回答后再继续。
问题清楚后，选择合适的工具箱，给出解决思路、实施步骤和 HTML 行动计划。
我的困惑是：……
```

把最后一句换成自己的情况即可，例如“我们合作做一件事，总要我催，我不知道问题出在哪里”。之后正常对话，不必每一轮重发整段口令。有技能菜单的产品，也可以选中技能后直接讲问题；专用调用语法见[调用说明](docs/INSTALL.md#安装后如何调用)。

还可以直接复制这个具体例子，再换成你自己的情况：

```text
请用思维模型决策工具帮我理清：
我准备办一场活动，纠结是直接举办，还是先小规模测试再决定。
先每轮问我一个关键问题，等我回答后继续。
请帮我看清不同信息会怎样改变后续行动，核对费用、时间和能承担的损失。
没有依据的概率请标为待核实，最后给我解决思路、实施步骤和 HTML 行动计划。
```

## 操作示范

下面是**虚构教学案例**，展示 v2.0 怎样从困惑走到方案，不是真实用户记录或效果保证。主题是：**“我们三个人做社区每周通讯，总要我催，还是返工，怎么办？”**

### 第一步：逐轮追问，把问题说清楚

下表展示连续对话，实际使用时助手应每轮等待回答，不会一次把问题全部抛给你。

| 轮次 | 助手问 | 示例用户回答 |
|---|---|---|
| 1 | 现在最困扰你的是交付经常延误，还是必须一直盯着才能推进？ | 两个都有，但我更希望大家能自己接上工作。 |
| 2 | 最近一次返工，具体卡在什么地方？ | 有人用了旧模板，有人不知道数字去哪查。群里链接很乱，最后都等我确认。 |
| 3 | 哪些事项必须由你确认，哪些可以由他们自己决定？ | 发布前我负责核对；版式和分工可以商量。我能提议，不能替别人承诺时间。 |
| 4 | 本周能为改流程额外投入多少时间？ | 三人合计90人分钟，已用10；正常写作另有安排。不花钱、不换软件，五天后发布不能耽误。 |

追问时可以借助 **WW-9.7 立题**，把“怎样催得更有效”转为：**怎样让成员取得正确资料、在清楚的权限内自行接续，同时守住发布质量？**

这时已知的线索是旧模板、资料入口混乱和权限理解不清。工作量过大或技能不足仍可能参与造成问题，不能直接认定成员不负责，也不能把当前线索当成唯一根因。

### 第二步：组建工具箱，让分析相互接续

助手先说明路线：“先查资料怎样交接，再梳理决定权限，检查反复返工的可能机制，最后设计有限的验证。”你无需自己点名下面这些工具。

| 工具 | 解决什么子问题 | 得到什么，怎样影响方案 |
|---|---|---|
| **TM-129 交互记忆系统** | 谁知道、去哪里找、拿到后能否核实并使用？ | 整理当前模板、数字来源、口径和待确认维护人，给后续任务简报提供可靠入口。 |
| **WW-7.6 指挥官意图** | 什么算完成，哪些事能自己决定？ | 写一页任务简报，说明质量要求、自主范围和何时协商；具体分工仍须各方接受。 |
| **TM-083 反馈回路** | 为什么催过、改过，下次还会发生？ | 检查“赶工是否挤掉规则更新”等可能链条；没有证据的箭头保留为假说，避免只靠增加催促。 |
| **TM-077 可逆决策** | 可以在哪个范围内先尝试？ | 限于内部副本演练，保留正式稿与发布权限，写清停止条件；已花时间无法收回。 |
| **TM-062 信息价值** | 试完要知道什么，才能决定下一步？ | 检查接手者能否找到正确版本、解释一个数字、知道何时协商；不同卡点对应不同改法。 |

这些工具共同形成一条路径：**找到可靠资料 → 明确任务边界 → 检查反复原因 → 限定尝试范围 → 用结果调整。** 这不是固定套餐；真实情况不同，工具和顺序也应改变。

### 第三步：汇成一套方案，并给出实施步骤

**本例当前建议：先提议整理一个可靠入口和一页任务简报，在内部副本演练一次，再决定是否继续采用。**

正式发布继续原有安排。若相关人尚未同意，就先完成自己能准备的部分，不擅自分派他们的时间；如果证据表明真正卡在工作量或知识，则转向相应问题。

| 顺序 | 建议行动 | 本例剩余时间分配 |
|---|---|---:|
| 1 | 用户核对一处真实返工、模板和数字依据 | 8人分钟 |
| 2 | 用户草拟资料入口与一页任务简报 | 12人分钟 |
| 3 | 提议三人各用10分钟讨论分工与演练意愿 | 合计30人分钟 |
| 4 | 获得同意后，一人试做、一人观察记录 | 两人合计18人分钟 |
| 5 | 用户查看结果，提出保留、修改或停止建议 | 7人分钟 |
| 缓冲 | 邀请、短确认、必要补查 | 5人分钟 |

**8＋12＋30＋18＋7＋5＝80人分钟，加上已经使用的10，合计90。** 这是投入上限，不保证全部完成。超时就缩减或停止；不能挤占正式发布，也不能把本周余额自动当成下周资源。后续推广需重新核对时间和参与者意愿。

最终报告还会写清：**找不到资料就修入口；能找到但不会解释就补知识；资料和权限都清楚仍做不完，就改查工作量。** 让试做结果真正改变后续方案。

## 你会得到怎样的解决方案

完成分析、交付阶段性方案或更新已有方案时，默认提供一份可以独立阅读的 **HTML 行动计划**，并在对话中告诉你当前建议和第一步。它应该回答：

- **现在怎样理解这件事？** 哪些是事实、哪些是推断，还有什么不知道。
- **为什么这样处理？** 用了哪些工具，得到了什么分析成果，为什么推荐这条路径。
- **接下来具体做什么？** 谁来做、先后顺序、时间和费用、前置条件、完成标志。
- **不符合预期怎么办？** 哪些信号意味着要暂停、换方法或重新分析。

能生成文件时，下载 `.html` 后用浏览器打开，可离线阅读和打印。链接显示源码时，另存为 `.html`；GitHub 文件页也可使用 **Download raw file**。详细步骤见[报告保存方法](docs/USAGE.md#报告怎样打开与保存)。

不能生成文件时，助手应提供可保存的 HTML 源码，不能编造下载链接。你也可以说：“这次先用聊天文字给我行动计划，不生成文件。”追问尚未结束时，不会每轮都生成报告。

## 做完之后，怎样继续

在同一对话中，把真实行动和反馈告诉助手：

```text
请根据上次行动计划继续。
我实际做了……，花了……时间，得到的反馈是……。
请说明哪些判断改变、哪些仍然成立，调整工具箱和下一步，保留旧版并更新 HTML。
```

沿用上面的案例：原计划尚未执行时，如果本周又为改流程投入20人分钟，剩余额度就从80变为60人分钟，方案也需要调整；尚未执行不能写成“执行后无效”。工具会根据你提供的信息更新，不会自动知道线下发生了什么。换新对话时，请附上旧报告或摘要；仅会话加载的用户还需重新提供技能目录。

## 其他情况怎么说

| 你的情况 | 可以直接发送 |
|---|---|
| 说不清哪里不对 | “我最近一直很忙却没进展，请先一步步帮我看清。” |
| 已经有充分材料 | “根据这些背景直接给方案，把未知和成立条件写清楚。” |
| 暂时不想再回答 | “先给阶段性计划，告诉我现在可以做什么。” |
| 需要比较选择 | “先帮我明确目标和限制，再比较这几个选择。” |
| 想暂停 | “今天先暂停，不用继续分析。” |
| 想复盘 | “这是原报告、实际行动和结果，请区分判断、执行与环境变化。” |

## 卡住了怎么办

| 遇到的情况 | 下一步 |
|---|---|
| AI 打不开仓库，或下载后找不到技能 | 提供完整目录，按[安装指南](docs/INSTALL.md)检查读取方式；云端助手不一定能读取你电脑里的文件。 |
| 一次问很多问题、只讲模型名 | 说“先只问一个关键问题，等我回答；分析时说明工具得到了什么具体结果”。仍不符合时，先核对是否读到了当前版本的技能入口。 |
| 替你猜了目标、事实或价值排序 | 说“这不是我确认的信息，请改为未知，依据我的实际回答继续”。 |
| 一直追问，迟迟不给结果 | 说“根据已有信息给阶段性方案，缺少的信息用条件分支处理”。 |
| 方案太长、第一步不清楚 | 说“先告诉我现在最值得做的一步、理由和完成标志，详细分析放后面”。 |
| HTML 打不开或保存不便 | 说“先在聊天中给我完整行动计划”；文件保存方法见[使用指南](docs/USAGE.md#报告怎样打开与保存)。 |

## 资料、来源与维护

**v2.5.0 包含156篇鬼子不言思维模型原文、156张操作卡、156个逐项设计的运行工具，以及100个万维钢工具来源条目。** TM 是作者模型编号，WW 是万维钢工具编号。两套资料平等参与选择，存在机制重叠，不把256个来源条目算成256个互不重复、全部验证过的模型。

本次重构增加了提问工具箱、互补工具编排、分析成果交接、综合方案和整体资源核算。原文与卡片保留，运行工具单独维护输入、操作、成果、边界与验证范围。以后每新增一篇文稿，会按流程补齐对应工具、目录和试跑记录。日常用户无需了解维护细节。

本工具采用 [Agent Skills 开放格式](https://agentskills.io/specification)，面向能够安装技能或完整读取资料的智能体，不限品牌。各产品能力与入口有差异，未逐一验证所有客户端。无需额外的专用 API Key；模型服务的账号和额度由你所用的平台提供。
