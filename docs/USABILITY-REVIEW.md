# 首次使用与跨 Agent 审查

审查日期：2026-10-09。对象为 `thinking-model-decision` 1.6.0 的入口、引用流程、公开说明和安装包。本轮修改文档与分发方式，未修改模型内容或核心决策流程，因此技能版本保持 1.6.0。

## 本轮解决的问题

| 原有问题 | 本轮修改 | 用户获得什么 |
|---|---|---|
| 首页混合安装、版本历史和维护说明，首次使用路径不突出 | 首页按安装或加载、读取检查、首次提问、查看与更新报告组织；历史移入独立页面 | 从对话框发送哪段话开始，后面每步都有明确动作 |
| 写了支持不同 Agent，却仍需用户自己判断能力 | 先让当前智能体检查环境，再区分原生 Skills、工作区会话加载和无法完整读取资料三种情况 | 不必先知道品牌目录或专用命令，也不会把临时加载误当成持久安装 |
| 下载整个仓库后还要找技能子目录 | 提供一个顶层技能目录的独立 ZIP，以及明确的目录图 | 能直接取得完整技能包；导入格式仍按当前产品要求确认 |
| “已安装”的回执无法证明模型资料可用 | 检查口令要求实际读取入口与 TM-077，说明版本、卡片边界、读取来源和使用范围 | 可以识别只下载、只读 README 或仅当前会话可用等情况 |
| 有示例，但首次提问、回答、输出与续接分散 | 首页保留紧凑的完整案例，详解单列，配可下载 HTML | 看懂怎样参与对话、何时得到结果、如何带着实际结果继续 |
| HTML 文件交付容易被误读为所有环境都能生成附件 | 区分实际文件、可保存源码与用户要求的聊天文字，补充打不开时的求助口令 | 能力不足时仍能得到内容，不依赖不存在的下载链接 |
| 使用指南的维护示例还用已占用的模型编号 | 替换为用户实际新模型编号占位符 | 减少将示例误当作可覆盖编号的风险 |

## 已完成的检查

### 文档任务检查

另一审阅代理独立读取首页、安装、使用与案例四份文档，逐项尝试回答以下八个首次使用问题。八项均能从文档中找到具体动作；另发现两处只提原生安装的措辞，已统一补上会话加载路径。

1. 它是什么、在哪里使用、会得到什么？
2. 不知道自己的智能体是否支持技能，下一步怎么做？
3. 产品只接受 ZIP，下载什么，目录结构怎样处理？
4. 智能体只说“已安装”，如何确认资料可读？
5. 面对自己的真实困惑，第一条消息怎么写？
6. 如何回答追问，不想再回答时如何获得阶段性结果或暂停？
7. 只看到 HTML 代码、打不开附件或不想处理文件时怎么办？
8. 条件变化、行动后复盘或换对话时怎样继续？

这是文档任务检查，不是真实新用户招募实验，也不是各产品界面的安装实测。

### 技能规则与受限能力响应

检查入口及引导、模型路由、报告和能力不足时的处理规则。普通分析已有直接读取目录和卡片的路径，Python 不是前置依赖，`agents/openai.yaml` 是可选元数据。本轮未为文档问题添加重复的核心流程规则。

另外实际生成并审阅了两条响应，详见[输入、答复和检查记录](checks/usability-response-trials.md)。

| 场景 | 实际检查结果 |
|---|---|
| 没有原生技能注册、只读目录、不使用 Python；用户担心学习难以坚持 | 根据已读规则只问一个主要问题，等待回答，没有先列模型或编造后续对话 |
| 可以读取资料、不得生成文件；用户要求直接给文字报告 | 实际读取 TM-077 与 TM-062，直接比较三种选择，保留未知并解释模型作用；没有追问、伪造文件链接或突破三小时时间约束 |

能力限制通过本轮任务指令施加，并核对实际使用的工具；没有物理移除宿主平台的功能。这两条响应不能代表所有输入、多轮流程或其他品牌产品均验证通过。
