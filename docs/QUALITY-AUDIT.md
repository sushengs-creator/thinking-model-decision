# 按高质量 Skill 文档逐项审阅

日期：2026-09-30。基线：v1.2.0；修订：**v1.2.1 / revision 6**。

依据用户提供的《从0到1写出高质量Skill，先设计触发，再设计流程》（三栖有话说，文档显示日期2026-05-29）检查。以下18项是对文章标准的归纳，页码为PDF实际页序，并非官方认证量表。已提取并视觉核对18页；第5、10页代码示例原本右侧截断，第18页为空白，未补造截断内容。PDF SHA-256：`613e091887dd00f675230f66143e355b64a440a73e6a2c91fdd59910f4262097`。本仓库不分发该PDF。

检查发现两个可复现缺陷：来源核对失败后残留旧的通过报告，以及验证附录在单独安装后有死链。其余修改用于澄清范围、把已有报告要求落实为交付前复核，并补齐验证证据。原有逐步追问、报告路径和125篇用户模型、100个万维钢工具保留。

## 先用任务卡说明它做什么

| 项目 | 本工具的约定 |
|---|---|
| 重复任务 | 帮使用者将模糊困惑澄清为可比较的决定，交付有依据、可行动、可更新的决策报告 |
| 触发 | “帮我理清困惑”“比较方案”“给决策报告”；更新或复盘决策；明确维护本工具的思维模型文稿、卡片或流程 |
| 输入 | 一句话困惑也能开始；利用已有事实、目标、约束和选项，逐轮补最关键的缺口 |
| 输出 | 当前建议及前提、方案比较、模型如何改变判断、下一步、风险和修正条件；维护任务另交代保存及校验状态 |
| 失败信号 | 反复问已回答的问题；资料足够却不给报告；虚构事实或概率；建议违反硬约束；只堆模型名；脚本失败仍声称通过；维护仅给草稿却称已安装 |
| 停止或降级 | 用户暂停则停止；只想倾诉不强推分析；证据不足给有条件报告；不能读取/保存/校验则说明实际完成范围 |

这是设计与审阅用任务卡，不要求普通读者先填表。

## 两个缺陷怎样复现、怎样修复

### 来源核对失败，旧报告仍显示通过

v1.2.0 在同一 `--out` 目录先成功核对，再用不存在的源文件运行，第二次返回 traceback/exit 1，旧 `wan-source-audit.json` 仍为 `pass:true`。缺根目录、坏UTF-8、索引为`[null]`也会崩溃，无法区分“内容不一致”和“核对没执行完”。

v1.2.1 保持100条、字节、索引和整体框架的比对规则，添加输入形状检查及预计错误处理。失败输出当次 `pass:false/status:error` JSON；可写的指定目录同步刷新JSON/Markdown失败结果。参数未完成解析或目录不可写时可能无法刷新，因此必须检查当次stdout及退出码；输出错误由 `report_write_errors` 说明。

[自包含测试脚本](../skills/thinking-model-decision/scripts/test_audit_wan_source.py)在临时目录构造虚构100条库，覆盖正常、内容/框架差异、旧成功刷新、编码、缺目录、坏JSON/索引、输出写失败和参数错误。测试不需要私人附件。

### 单独安装后的历史验证链接失效

旧 `references/evaluation/results-v1.1.1.md` 使用 `../../../../docs/SKILL-REVIEW.md`，在仓库内存在，但单独安装Skill目录后越出安装包。现改为公开仓库的HTTPS链接，保留历史版本和测试结论。运行必需资料仍都在Skill目录内。

## 本轮验证的边界

完整输入、输出与逐项审阅见[验证记录](../skills/thinking-model-decision/references/evaluation/results-v1.2.1.md)。选择测试属于独立模拟：两条含糊请求仍需结合上下文辨别；尤其“上次报告”可能不是决策报告，不能凭这组测试保证所有客户端都正确触发。发现范围不明时应先读取可见报告或用一个问题确认。

本轮没有宣称225条来源均已验证现实效果，没有把词面检索改称语义检索，也没有验证所有AI客户端。后续每次新文稿继续执行原维护流程；真实读者出现问题时保留匿名请求与原回复，先判断是触发、事实、选型、推理还是执行问题，再修相应部分。
