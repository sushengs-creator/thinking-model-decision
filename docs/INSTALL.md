# 安装、加载与检查

本指南面向不同品牌的 AI 智能体。你可以继续使用自己熟悉的产品；先让它检查是否支持原生 Skills，或是否能在当前工作区读取完整资料。**安装位置、导入格式和调用命令由当前产品决定，没有一条路径适用于所有智能体。**

新用户先按[首页的四步操作](../README.md#开始使用)开始。这里只处理自动安装失败、手动导入、会话加载及后续更新。

<a id="选择加载方式"></a>

## 先确认采用哪种方式

| 当前环境能做什么 | 使用方式 | 换对话后怎样办 |
|---|---|---|
| 原生支持 Skills，允许安装或导入资源包 | 按产品规则安装并启用完整目录 | 按安装范围使用；有的只对当前项目有效，新会话仍需确认可发现 |
| 没有 Skills 功能，但能按路径或文件标识完整读取目录和引用资料 | 把完整目录放在可访问的工作区，明确要求本次加载 | 重新提供目录位置；不将这称为持久安装或自动发现 |
| 只能接收聊天文字或附件摘要，不能访问所需完整资料 | 暂不能运行完整模型库 | 使用能提供完整资料访问的环境；不要把粘贴 README 当成安装 |

这些是能力判断，不是品牌白名单。只要智能体能按需取得入口和引用资料，就有相应的使用路径；某个产品是否提供这些能力，需要在实际环境中核对。

## 让智能体自动处理

把下面整段发送到当前智能体的对话框。

```text
请帮我使用 thinking-model-decision（思维模型决策工具）：
https://github.com/sushengs-creator/thinking-model-decision/tree/main/skills/thinking-model-decision
请先检查当前产品与工作区的能力，优先按本产品的原生 Skills 方式安装完整目录。
若不支持原生安装，但能读取完整目录，请说明怎样在本次会话加载。
若已经安装，请先备份、保留我的新增模型和修改，再决定怎样更新。
不要把某个产品的安装目录或命令当成通用标准；无法核实入口时不要猜测。
完成后实际读取 SKILL.md 与一张模型卡，报告读取结果、版本、使用范围及调用方式。
没有完成的步骤请明确列出，并给我当前环境可执行的下一步。
```

如果当前产品需要你点击界面导入，智能体应说明这个必要步骤。它不能操作界面、无法联网或没有写入权限时，仍可指导手动操作；这些限制不能被描述成已经安装成功。你不需要为本技能另外申请专用 API Key，但所用平台可能要求自己的账号和额度。

<a id="手动下载与加载"></a>

## 手动安装与会话加载

### 下载什么

直接[下载独立技能包 v1.7.0](https://raw.githubusercontent.com/sushengs-creator/thinking-model-decision/main/dist/thinking-model-decision-v1.7.0.zip)。这是技能目录的 ZIP，包含全部模型资料、模板、工具脚本和署名说明；[SHA-256 校验值](../dist/thinking-model-decision-v1.7.0.zip.sha256)供需要核对文件的用户使用。

解压后应该得到下面的结构。顶层只有一个 `thinking-model-decision` 文件夹，`SKILL.md` 就在这个文件夹内。

```text
thinking-model-decision/
├── SKILL.md
├── references/
├── assets/
├── scripts/
├── agents/
├── NOTICE.md
└── README.md
```

独立包直链无法访问时，可以使用[完整仓库 ZIP 备用下载](https://codeload.github.com/sushengs-creator/thinking-model-decision/zip/refs/heads/main)。解压后进入 `dist`，取出里面的 `thinking-model-decision-v1.7.0.zip` 即可；也可以直接取出 `skills/thinking-model-decision` 技能目录。完整仓库还包含网站说明与维护文件，不要把仓库外层文件夹当成技能目录。

### 有技能导入入口

1. 在当前产品的 Skills/技能导入功能中，按它的要求选择下载包或解压后的目录。
2. 本站 ZIP 包含一个顶层技能文件夹。若产品要求 ZIP 根层直接出现 `SKILL.md`，打开解压后的文件夹，将里面的完整内容重新压缩后导入；不要只选择 `SKILL.md`。
3. 按产品要求启用、刷新或开启新会话，然后进行下方的读取检查。导入包格式、体积限制和具体按钮名称以该产品当前文档为准。

如果不清楚入口，可以对当前智能体说“我使用的是【产品名称和版本】，已下载技能包，请根据当前官方说明告诉我导入入口和需要的 ZIP 结构”。

### 采用目录安装

让当前智能体确认它真正扫描的技能目录，将整个 `thinking-model-decision` 文件夹放进去。最终应是下面这样的层级。

```text
当前产品确认的技能目录/
└── thinking-model-decision/
    ├── SKILL.md
    └── references/ ...
```

不要多套一层仓库目录。跨客户端的 `.agents/skills/` 是一种常见约定，但仍要确认当前产品会扫描它；不把 `.codex/skills/` 或任何品牌目录当成统一路径。开放格式规定的是技能包内容，具体发现和加载方式由客户端实现。[格式规范](https://agentskills.io/specification) · [客户端接入说明](https://agentskills.io/client-implementation/adding-skills-support)

### 没有技能安装入口，但可以读工作区文件

把完整目录放进智能体能够访问的工作区，或按产品支持的方式提供完整文件。云端智能体不能因为你在电脑上解压了文件，就自动读到它；仅上传 ZIP 也不意味着它会解压和读取内部资料。

确认文件已在当前环境可见后，发送下面这段话，把方括号替换成实际可访问的位置。

```text
请在本次会话使用【完整技能目录的位置】中的 thinking-model-decision。
先读取 SKILL.md，再按需读取目录中的引用资料；不用一次加载全部模型。
先验证能否读取 references/cards/TM-077.md。若读取失败，请指出缺口。
读取成功后，按该技能帮我逐步梳理问题。我的困惑是【写实际问题】。
```

没有本地路径概念的产品，可以提供它支持的文件标识或资源入口。只获得文件摘要、无法取得所需全文时，不能声称完成了模型调用。该方式仅加载到本次会话；下一次重新提供可访问资料，或使用产品支持的项目资源功能。

<a id="确认是否可用"></a>

## 检查成功的标准

**看到“已下载”还不够。** 让智能体实际读取入口与模型卡，再进行一次对话试用。

```text
请检查 thinking-model-decision 在当前会话是否可用。
实际读取 SKILL.md、references/library-state.json 和 references/cards/TM-077.md，
报告入口与库状态的版本是否一致、这张卡的名称和一条真实使用边界。
说明你从哪个目录或资源入口读取，是原生安装还是仅本次加载。
无法读取就明确说失败，不要根据网页介绍猜测。
```

本版本应读到入口与库状态均为 `1.7.0`，模型卡为“可逆决策”。后续发布时以对应版本为准。这个检查证明当前会话能够访问相关文件，不等于所有模型行为、所有客户端和新会话自动发现都已验证。

随后试着发送“请用思维模型决策工具帮我梳理，我想学数据分析，但不知道要不要报课”。它通常会先询问一个影响判断的问题，等待你回答。只会重复技能名称、不能读取资料或一直输出模型名单，都不算完成使用检查。

## 安装后如何调用

最容易记的方式是自然语言。

```text
请用思维模型决策工具，帮我一步一步理清这个问题。【写你的困惑】
```

这是表达使用意图的方法，实际加载取决于当前产品的发现能力。产品有技能菜单时可以先选中 `thinking-model-decision`；没有自动发现时使用上面的会话加载请求。

某些产品有专用语法，例如 Codex 的 `$thinking-model-decision`。该语法只作为对应产品的例子，不要求其他智能体支持 `$`，也不要求安装 `skill-installer` 或 OpenAI 组件。`agents/openai.yaml` 只提供可选界面元数据。

<a id="报告怎么拿到"></a>

## 文件和脚本能力不足怎么办

| 能力缺口 | 可以继续做什么 |
|---|---|
| 没有 Python 或终端 | 直接读取目录、模型卡和原文完成普通决策分析；不要为了使用技能先安装 Python |
| 不能生成文件或附件 | 给完整 HTML 源码及保存方式，或按你的明确要求直接给聊天文字报告 |
| 没有浏览器预览 | 可以给实际生成的文件，但应说明未做显示检查 |
| 无法联网 | 分析已有材料，把需要当前外部事实的条件标为待核实 |
| 不能读取模型资料 | 说明缺少哪些文件，可以先做一般澄清；不能宣称已经使用本模型库 |

报告保存方法见[使用指南](USAGE.md#报告怎样打开与保存)。

<a id="更新已安装版本"></a>

## 更新已有版本

更新前先保留你的新增模型和修订。可以这样请求。

```text
请检查当前 thinking-model-decision 与仓库最新版本的差异：
https://github.com/sushengs-creator/thinking-model-decision
先备份我的新增文稿、模型卡和本地修改，在临时位置准备新版。
比较差异并保留有效修改，完成可用的校验后按当前产品方式更新和重新加载。
请说明更新的位置、版本、资料读取结果和未完成的步骤。
```

备份放在自动发现范围以外，避免两个同名技能同时出现。仓库更新不会自动改动你已安装的副本；只修订 README 等文档时，通常无需重装技能。更新技能不代表允许上传你的个人报告或新增文章。

## 给维护者的完整性检查

普通用户不需要运行命令。维护者有 Python 3.9 以上版本及命令执行能力时，可运行下面的标准库脚本，路径替换为实际技能目录。

```sh
python3 "<技能目录>/scripts/library.py" validate
```

脚本从自身位置定位资料，与当前工作目录无关。未运行时应说明未运行，不把复制文件算作校验通过。

仓库维护者更新分发包时，在仓库根目录运行 `python3 scripts/package_skill.py`。它读取技能版本，生成独立 ZIP 和校验值；发布前核对解压文件与源目录一致，再同步文档中的版本链接。当前原生客户端覆盖情况与检查范围见[本轮审查记录](USABILITY-REVIEW.md)。
