# v2.0：从困惑到解决方案

这次升级的目标是：一个人遇到身边的难题，不用先懂思维模型，就能在逐轮对话中看清问题，借助互补工具形成完整思路，并拿到可以执行、可以根据反馈修正的方案。

## 使用流程

**说出困惑 → 逐轮追问 → 问题地图 → 工具箱分析 → 综合解决方案 → 实施步骤 → 根据反馈更新。**

这不是不可回头的流水线。问题已经清楚可以直接分析；分析发现关键未知可以再问；用户需要阶段性结果就先给有条件的方案；要求暂停就停止。用户不必先列选项，理解原因、改善学习和安排合作同样可以使用。

## 这次改了什么

| 层次 | v2.0 的改变 | 对用户有什么用 |
|---|---|---|
| 对话 | 提问也可调用立题、证据辨别、职责或行动阻力等工具 | 每个问题都有明确用途，不填长问卷、不被诱导 |
| 编排 | 按需要组建工具箱，取消固定“1主＋3辅”上限 | 复杂问题能覆盖关键视角，简单问题仍保持简洁 |
| 工具 | 142个 TM 各有输入、转换、分支、最小成果和交接规则 | 从理解概念走到实际分析，不只附模型标签 |
| 两库协作 | 100个 WW 条目平等参与选型 | 用最合适的机制，不要求两库每次都出现 |
| 综合 | 工具产物接续，处理分歧，汇成一条解决路径 | 无需用户自行拼接几份模型分析 |
| 行动 | 合并资源预算，明确依赖、完成标志和更新条件 | 看得清先后顺序，也知道何时该改变计划 |
| 交付 | 默认独立 HTML，首屏呈现建议、第一步和关键条件 | 可保存、离线阅读和打印，详细依据仍可检查 |
| 维护 | 原文、卡、运行文件分别登记指纹和验证范围 | 后续新增一篇可以增量迭代，修改后能识别陈旧运行文件 |

## “全面”怎样实现

先看与问题有关的目标与价值、事实和原因、资源与约束、参与者和系统、时间与连锁影响、路径与取舍、执行与反馈。它们是检查视角，不是强制使用七个模型。每个入选工具必须说明：解决什么子问题，使用什么输入，得到什么成果，怎样改变后面的方案。

例如某个工具提出试行，另一个工具发现反馈比退出期限更晚，最终方案必须改变试行范围、承诺点或信息渠道；不能把两段分析并排放着，再说“综合考虑”。同一机制来自两个作者也不是两份独立证据。

## 资料架构

保留一个技能入口，按需读取资源，不拆成142个互相竞争的独立技能。原文保留出处，卡片解释机制与边界，运行文件描述操作，目录负责召回。WW 原始正文保持来源边界，公共规则负责当前对话节奏和交付。

## 怎样判断这次升级做到了什么

先检查文件、链接、来源指纹、版本与分发包，再实际执行适用和易误用请求，以及不提示工具名的完整入口场景。真实模拟输出与后续评审分开保存，失败不能被删掉或改写成首次通过。具体数量、发现和限制见 [v2.0 验证记录](../skills/thinking-model-decision/references/evaluation/results-v2.0.md)。

模拟记录能够检查某些行为，不能证明所有问题都有效，更不能代替现实结果或所有客户端的实机测试。正式版本和安装状态以实际目标读回为准，不以“已上传文件”或计划文字推断完成。

## 以后新增一个模型怎么办

用户提供新文稿并要求入库 → 保留原编号和原文 → 复核卡片 → 设计该机制的运行工具 → 登记任务信号、角色、成果和指纹 → 实际试跑适用与误用场景 → 更新目录、版本、包与已授权安装目标。保留用户本地新增内容、修改和私人案例，不自动上传。
