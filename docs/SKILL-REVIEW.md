# 公开版 Skill 检查与修订

检查日期：2026-09-30。检查基线：v1.1.0；修订版本：v1.1.1。

结论：原版具备标准 Skill 的入口、按需读取资料、模型检索、逐步澄清和报告交付结构。公开使用需要补齐两处边界：维护目标的范围，以及能力不足时的交付状态。本次保留核心流程和全部知识内容，集中澄清这些规则。

## 按哪些方面检查

| 检查项 | 结果 |
|---|---|
| 技能发现与入口 | 名称、描述、SKILL.md 结构有效；界面元数据与功能一致。显式调用名为 `$thinking-model-decision` |
| 按需读取资料 | 入口提供工作规则；对话、报告、维护分别引用参考；选型时再读取相关卡片和原文，不把整个模型库一次塞入上下文 |
| 对话推进 | 已有逐轮追问、真实回答、事实与推断区分、目标校准和停止条件；本次增加集中调用表，便于执行和检查 |
| 读者控制权 | 直接报告、阶段性报告、修改报告、复盘各有路径；明确暂停本身不触发报告 |
| 模型使用 | 先读机制与边界，再解释模型实际改变的判断；不要求两套库都出现，不凑模型数、不捏造概率 |
| 维护和验证 | 原文、卡片、索引、版本及验证证据已分离；本次限定修改目标，并区分草稿、已保存与已校验 |

## 两项需要修复的问题

| 问题 | 对公开读者的影响 | 本次修订 |
|---|---|---|
| 维护流程无条件要求同步安装目录和交付副本 | 读者只想在一个仓库试改，也可能影响稳定安装版，或触发无关目录的权限申请 | 只修改本次指定或正在维护的目标。只有任务包含安装、同步或发布时，才处理相应目标 |
| 缺少能力时的完成状态没有写清楚 | 只读客户端可能只能给草稿，却让读者以为模型已保存、校验并可用 | 日常分析可直接读资料；联网、写入、命令执行分别对应不同能力。未读取、未保存、未运行校验均须如实说明 |

这两项来自静态指令审查，说明的是规则可能引起的误用；本次未观察到真实读者遭遇这些后果。

## 一并澄清的调用规则

1. **新问题**：说出困惑，默认每轮一个主要问题，收到回答后继续。
2. **进入分析**：待决定事项、目标、关键限制及可比较选项清楚，剩余未知能保留为条件时，就停止常规追问，不另设分析审批。
3. **直接或阶段性报告**：按用户要求利用现有材料交付；缺失信息写成条件，不虚构答案。
4. **暂停**：停止推进；只有同时要求阶段性结果时才出报告。旧版措辞把暂停与要求报告放在一起，本次消除这一歧义；旧版暂停试跑本身正常。
5. **更新或复盘**：依据当前可见的报告与资料处理；看不到旧报告时索取报告或摘要，不声称记得不存在的上下文。
6. **维护模型**：明确要求入库、修订或迭代才写入。仅发文章或要求审稿不触发维护；本地修改不自动发布。

首页提供可复制的常用说法，详细步骤见 [使用指南](USAGE.md)，机器执行入口见 [SKILL.md](../skills/thinking-model-decision/SKILL.md)。规则一致，但无需让普通读者先阅读维护文件。

## 验证与局限

本次包括标准结构检查、模型库完整性检查、知识资产指纹比较、文档链接核对及独立模拟回复审阅。具体输入、输出、范围和结果见 [v1.1.1 验证记录](../skills/thinking-model-decision/references/evaluation/results-v1.1.1.md)。

模拟回复和静态检查不能保证每个模型、客户端或真实决策场景都表现相同。后续优先收集读者的匿名问题、实际回复与期望差异，再以最小复现案例修订；不以增加追问轮数、模型数量或规则篇幅作为升级目标。
