# 使用指南：从一件纠结的事，到一份可以行动的决策报告

思维模型决策工具是一套供 AI 助手读取和执行的技能。你可以从一句“我很纠结”开始，让它逐步帮助你理清问题、比较选择，最后默认交付 HTML 下一步行动计划。你不需要先学会模型名称，也不必把材料整理成一份完整问卷。

它面向所有支持 Agent Skills、能够读取完整技能包及相关资料的 AI Agent，核心流程不依赖 Codex 或 `skill-installer`。各产品的安装目录、导入方式和调用命令可能不同；使用当前 Agent 的规则即可。本仓库本身不提供独立的聊天网页或 AI 服务。安装与能力要求请看 [安装指南](INSTALL.md)。

日常分析不要求 Python：助手能读取目录和模型卡即可。核实最新事实还需要联网；无法联网时，报告应标出待核实条件，继续分析有依据的部分。无法读取技能资料时，助手可以先帮你澄清问题，但不能声称已经使用库里的模型。

新增或修订模型需要写入你指定的目录，运行维护校验需要命令执行能力及 Python 3.9 以上版本。能力不足时可以先交付草稿，但必须说明哪些步骤尚未执行；草稿、保存成功和校验通过是不同状态。仅修改一个本地副本，不会自动修改其他安装版或发布到 GitHub。

## 1. 什么问题适合拿来聊

当困难在于“怎么判断、怎么选择、怎么行动”，而不只是缺一个事实时，可以使用它。

| 你遇到的情况 | 可以这样开口 |
|---|---|
| 事情很多，却说不清真正卡在哪里 | “最近工作越来越忙，但感觉没有进展，帮我理清最需要解决的事。” |
| 几个目标互相冲突 | “我想学习新技能，也想保留陪伴家人的时间，不知道怎么安排。” |
| 在几个方案之间反复犹豫 | “这个项目是现在做、缩小范围做，还是再等一等？” |
| 已有判断，又出现了新信息 | “我原本打算选 A，但刚知道一个新情况，想重新判断。” |
| 不知道该继续调查还是先动手 | “我搜了很多资料，还是不敢决定，哪些信息真的值得继续查？” |
| 做过决定，想知道哪里需要改进 | “这是当时的判断和后来的结果，帮我复盘。” |

简单事实查询、翻译、格式转换、仅润色文章、机器学习建模和练习题纠错通常不需要启动这套流程。“新增模型”指明确要求维护本工具的思维模型文稿或卡片；语义不明时先厘清任务。你也可以直接说“我今天只想把这件事讲一讲”，暂时不进入分析。

## 2. 第一次使用，直接复制这段话

```text
请使用 thinking-model-decision（思维模型决策工具）帮助我。

我最近在纠结：……

请先利用我已经提供的信息，每轮问一个最关键的问题，等我回答后再继续。
问题清楚后，帮我比较方案，给出一份 HTML 下一步行动计划，包含建议、依据、执行安排和调整条件。
我不知道的地方请保留为未知，不要替我补答案。
```

省略号处写你现在的困惑即可。你也可以只说：

> 用思维模型决策工具陪我理一理：我不知道这个项目还该不该继续做。

如果你的 Agent 有技能选择菜单或显式调用命令，也可用它选中 `thinking-model-decision`。Codex 的 `$thinking-model-decision` 是一种产品语法，不要求其他 Agent 使用同一前缀。若当前产品不提供技能发现，只能读取你指定的文件，可先让它读取完整目录中的 `SKILL.md` 并按需读取参考资料；这属于本次会话加载，不等于已经持久安装。

如果已经有背景材料、备选方案、截止时间或不能接受的后果，可以一起提供；缺少这些也能开始。材料里可以用“公司 A”“同事 B”等代称，只保留影响判断的内容。

### 怎样调用万维钢的工具

本技能已包含用户提供的万维钢 Skill 中全部100个工具和整体方法框架，无需再安装或手动切换另一套技能。你不必知道工具名称，助手会在两套来源中按问题选择；万维钢工具可以独立作为主工具，也可以补充或反证其他模型。

想指定一个方向时可以说：“请用这个决策工具帮我判断团队哪些能力值得自研、哪些可以采购。”想点名工具时可以说：“请用万维钢的沃德利地图帮我分析，并检查它是否适合当前问题。”助手仍需读取具体机制，说明哪些判断因此改变。

完整收录表示100条都可查找和使用，不表示一次必须运行100条。默认仍是逐步澄清、少量适用模型、最后给报告。没有合适模型就保留一般分析，不为展示覆盖范围硬套概念。范围和来源核对见 [万维钢融入说明](WAN-INTEGRATION.md)。

## 3. 对话会怎样一步一步推进

助手先从你已经说过的内容中找出最影响判断的缺口。默认每轮问一个主要问题，必要时再附一个紧密相关的小问题，等你真实回答后才继续。

它可能逐步确认：

- 眼下究竟要决定什么，而不只是发生过什么；
- 你最希望改变什么，以及目标之间的优先顺序；
- 时间、资源和不能接受的后果；
- 现有选择，以及是否存在可行的过渡安排；
- 哪些是直接观察到的事实，哪些是推测或尚未确认的信息。

这些是对话方向，不是必须按顺序填完的表格。你已经说清楚的内容不应反复询问；回答“不知道”也有用，它会帮助判断接下来应补事实，还是保留条件继续分析。

### 一个虚构的简短示例

**以下人物、条件和问答全部为虚构，仅演示使用过程，不是实际用户记录，也不表示所有问题都应得到相同建议。**

**使用者：** 我想学数据分析，已经看了好几门课，但一直决定不了要不要报名。

**助手：** 你看过不少课程，但还没找到决定的依据。你希望学会数据分析后，先解决哪一件具体的事？

**使用者：** 我每个月都要整理一份活动数据，希望能自己看出哪些活动值得继续做。

**助手：** 现在有了一个具体目标：改善每月的活动分析。你能稳定投入多少学习时间？

**使用者：** 每周最多三小时。我看中的系统课每周要八小时，暂时也挤不出更多时间。

**助手：** 这门课的时间要求超过了你的稳定投入。除了报名系统课，你还有什么可以先试的学习方式？

**使用者：** 有一份短教程，可以拿去年的一张数据表跟着做。我还没有试。

这时，主要目标、时间约束和可比较的选项已经出现。助手可以先简短归纳，再进入分析，不必为了凑够轮数继续提问：

> 目前要决定的是：怎样在每周三小时以内，开始改善活动数据分析。可以比较报名系统课、先用短教程做一份实际分析，以及暂时维持现状。短教程是否足以解决问题还不清楚，但可以通过一次有边界的尝试获得信息。

在这个虚构情境中，报告可以用 **TM-077 可逆决策** 检查哪些投入可以分步进行，再用 **TM-062 信息价值** 判断先试教程能否帮助决定后续投入。它们应改变具体判断，例如先检验“时间是否够用、能否做出有用分析”，而不是只在结尾列出两个模型名。

实际使用时，助手必须等你回答，不能为了把流程写完整而替你编造后续经历。你也不必照着示例回答。

## 4. 什么时候会结束追问，给出报告

没有固定的提问轮数。通常满足下面几项就可以进入报告：

- 已经能说清此刻要做的决定；
- 主要目标、期限和硬约束足够明确；
- 有可以比较的选项，或能提出候选并标明其可行性仍待确认；
- 剩余未知可以通过条件分支、核实行动或后续观察处理。

进入分析前，助手会简短归纳它对问题的理解。如果归纳只是复述你明确提供的内容，就直接继续；如果含有会改变建议的重要推断，才需要请你修正。你不必再经历一次“是否同意开始分析”的确认。

如果后面发现一个真正影响结论的缺口，助手仍可以补问，并说明这项信息为什么重要。信息不可能完全齐备，但这不妨碍先形成有边界的判断。

## 5. 一份报告应该包含什么

每次分析完成后，默认生成可离线打开、可打印的 HTML「下一步行动计划」。对话中给出简短结论和文件链接，你不必再次要求排版或回翻问答。文件保存在本次任务的输出目录；你也可以指定目录和文件名，不需要提供真实姓名。

澄清过程中的每轮提问不生成文件。阶段性建议和已有报告更新也默认交付 HTML；若明确要求只用聊天文字、其他格式或不生成文件，工具会遵从。没有文件写入能力时，会提供完整 HTML 源码和保存方法，并说明尚未保存，不能虚构下载链接。

| 报告内容 | 你应该能看清的事情 |
|---|---|
| 当前建议与前提 | 眼下建议选什么或先做什么；哪些条件成立时才适用 |
| 问题定义 | 最终解决的是哪个问题；目标顺序、范围、期限和硬约束是什么 |
| 事实、假设与未知 | 哪些来自你的陈述或文件，哪些经过外部核实，哪些仍是推断 |
| 模型与方案比较 | 使用了哪些模型，各自改变了什么判断；合理备选和维持现状各有什么收益、成本与后果 |
| 行动安排 | 第一步及后续做什么、为什么做、由谁做、何时或在什么条件下做、需要什么前提、怎样才算完成，以及何时调整或停止 |
| 风险与更新条件 | 什么可能导致失败；出现什么证据后应该继续、调整、暂停或退出 |
| 必要核实与复盘 | 还缺哪几项真正影响决定的信息，以及什么时候值得再看一次 |

通常使用一个主模型，最多再加三个补充或反证工具。模型数量多，不代表分析更深入；如果没有合适的模型，也可以直接分析问题或补充事实。

小决定可以用短版 HTML，复杂选择可以用表格或决策树，不固定章节数量。每项关键行动应连接到事实、约束或已解释的模型；不硬给每行贴一个模型名。无论长短，报告都应区分依据和假设，不应编造精确概率、评分、成本或他人的承诺。

## 6. 我已经想清楚背景了，能直接要报告吗

可以。如果已经有足够材料，直接提供即可。你也可以明确要求跳过常规问答：

```text
请使用思维模型决策工具，直接根据以下材料给我一份决策报告。

待决定的事：……
我的目标和优先级：……
可选方案：……
已知事实、期限和约束：……

请区分事实、假设与未知。材料不足的地方用条件分支处理，
如果还不能可靠地做最终选择，请明确说明原因，并给出现在能做的行动。
```

这些栏目是可选的表达辅助，不是启动要求。直接要报告也不意味着助手可以替你补全未知事实。

### 没时间继续聊，就先要阶段性报告

```text
我现在没有时间继续补充了，请先给一版阶段性报告：
把现在就能决定和执行的部分、需要核实后再决定的部分分开。
只保留最必要的核实任务。
```

阶段性 HTML 行动计划应交付已经成立的判断和可行动的部分。如果缺少决定性信息，它可以暂不推荐最终选项，但仍应说明怎么核实、如何降低当前损失，以及新信息将改变哪一项判断。

如果只是想停下来，直接说“今天先暂停”，助手应停止追问和分析，简短回应即可。暂停并不自动要求出报告；想保留阶段性结果时，再加一句“请先给我目前的阶段性报告”。

## 7. 报告出来后，条件变了怎么办

在同一对话中直接补充变化即可，不用重新讲一遍全部背景：

```text
补充一个变化：我每周可投入的时间从三小时变成了六小时。
请更新上面的报告，说明哪些判断改变了、哪些仍然成立，
并重新检查下一步安排。
```

如果变的是目标，而不只是事实，也可以直接说：

> 我现在更看重能长期坚持，短期完成速度排在后面。请按这个优先级重新比较。

助手应先更新问题定义和比较标准，再修改受到影响的建议；不能只在旧结论后面补一句例外。它也应交代旧建议是否仍适用，并交付更新后的 HTML。文件会注明变更原因，保留可回溯的旧版；你可以要求更新同名文件，助手会先备份。

如果换了一个新对话，最好贴上原报告，再补充变化，这样可以保留当时的事实、假设和判断依据。不要假定不同对话会自动共享完整背景。

### 想复盘时，保留当时的判断

```text
请复盘这份决策报告。

这是当时的报告：……
我实际采取的行动：……
后续出现的新信息和结果：……

请分别检查事实、模型选择、推理、执行和环境变化，
不要只根据最后结果的好坏评价当时的决定。
```

复盘的目的，是找到下一次可以改进的判断或行动。一次结果不好，可能来自执行偏差或环境变化；一次结果好，也不自动证明当时的依据充分。报告可以提出复盘时点，但不会因此自动创建提醒或持续监控。

## 8. 有了新文章，怎样继续扩充模型库

你可以提供尚未发布的本地文稿，也可以提供文章链接。明确说“请迭代入库”，就会进入维护流程；无需重新提交已经收录的全部文章。

新增文章可以这样说：

```text
这是思维模型 127 的终稿，请在现有 thinking-model-decision 技能中迭代入库。
请保存原文，提炼可用于决策的模型卡，检查与已有模型的关系，
试跑一个适用场景和一个容易误用的场景，完成校验后告诉我结果。
```

修订已有文章可以这样说：

```text
这是思维模型 054 的修订稿，请更新已有条目，保留原编号和历史版本，
重新检查模型卡、关联关系和受影响的使用场景。
```

一次完整迭代不只是把文章放进文件夹。它需要保留来源、提炼机制和使用边界，让日常问题能够找到新模型，并检查实际调用是否合适。完成后，你应收到简短回执，包含新增或修订的编号、主要变化、实际验证结果、当前数量和版本。

如果链接无法读取，助手应说明缺少什么，不应只凭标题补写文章。新文章也不会自动使原有知识和全部场景重新获得验证。工具不会自动监控你将来发表的内容；下一次有新稿时，再提供文稿并发起迭代即可。

维护细节见 [模型入库、修订与复盘](../skills/thinking-model-decision/references/maintenance.md)。

## 9. 使用边界与个人信息

**模型帮助判断，决定仍由你作出。** 工具不替你规定人生目标或价值排序。目标有价值，也不等于某条实现路径一定可行。

**知识条目不是自动核实过的现实证据。** 当前 1.5.0 版本包含 132 篇原文、132 张操作卡和 100 个万维钢工具条目。两套来源存在重叠，不能理解为 232 个互不重复且全部经过验证的模型。已有检查和模拟试跑也不等于真实世界效果已经得到证明。

**需要最新事实时，应另外核实。** 法律、医疗等高风险问题，以及会变化的政策、价格或外部条件，不能只靠库里的文章得出结论。模型可以帮助整理问题和证据，不能替代相应的专业判断。来源和验证范围见 [来源说明](../skills/thinking-model-decision/references/source-notes.md) 与 [当前库状态](../skills/thinking-model-decision/references/library-state.json)。

**不是所有选择都能低成本试错。** 重大的一次性决定、不可恢复的损失和迫近的期限，需要先处理当前约束，不能一概包装成“先试试看”。

**你的私人案例不会默认写回通用模型库。** 与当前问题相关的雇主、城市、收入、股权、家庭和案件材料等信息，留在当前任务及其报告输出目录中。未经你明确要求，不应写进可复用技能包，也不应写入长期记忆。维护和复盘需要保留测试时，只提取可复用的失误模式及匿名化场景。

这项约定限制的是技能的写回行为；聊天记录的保存、访问权限和数据处理仍由你所用的 AI 工具及其设置决定。公开分享报告或贡献材料前，应检查是否仍含个人或第三方信息。

## 怎样判断这次回答是否完成

信息已足够或你要求先出报告时，回答应包含建议与前提、可比较的备选、关键依据、下一步和修正条件；不能停在一串模型名称或无限追问。助手交付前应核对行动是否符合你的硬约束，未核实信息是否仍标作未知。默认交付的 HTML 应能打开，包含本次内容，且没有模板占位符；如果无法保存或预览，助手应说明具体限制。即便你很着急，也可以拿到简短的条件判断。

想反馈问题时，可提供匿名的原始请求、实际回答和不符合预期的地方。维护者会区分“没调用到技能”和“调用后做错”，分别修入口或流程；完整检查见 [质量审阅](QUALITY-AUDIT.md)。
