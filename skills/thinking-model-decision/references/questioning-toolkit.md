# 提问也可以使用工具

本文件服务于澄清阶段，和 [引导对话](guided-dialogue.md) 配合。每次只处理最有价值的一个缺口：承接新信息 → 选择能改变判断的未知 → 读相关工具 → 转成日常问题 → 等待真实回答 → 说明回答改变了什么。不向用户整张发出下表。

| 当前缺口 | 可读的工具 | 一轮问题示例 | 回答怎样改变后续 |
|---|---|---|---|
| 故事很多，不知先处理什么 | [WW-9.7 立题](wan-tools/WW-9.7.md) | 这件事里，你现在最想先改变或弄清哪一部分？ | 确定问题边界，避免代替别人解题 |
| 多个愿望相互冲突 | [WW-9.2 目标函数](wan-tools/WW-9.2.md)、[TM-064](tools/TM-064.md) | 如果眼下只能先改善一件事，你最希望哪件发生变化？ | 由用户确定优先级，不替其规定价值 |
| 两个选项都不理想 | [TM-143](tools/TM-143.md) | 让你觉得只能这两种做法的条件，是怎样确认的？ | 核查二选一是否成立；允许答案是条件确实不能改变 |
| 观察和动机推断混在一起 | [TM-050](tools/TM-050.md)、[WW-1.1](wan-tools/WW-1.1.md) | 哪个具体言行让你形成这个判断？ | 分开事实、解释与待验证处 |
| 问题过大、原因混成一团 | [TM-103](tools/TM-103.md) | 最近一次，这件事具体卡在哪个环节？ | 选出能检验的子问题，而非逼用户一次解释所有原因 |
| 有先后关系，却不清楚因果 | [WW-3.3](wan-tools/WW-3.3.md)、[TM-083](tools/TM-083.md) | 你改变做法之后，对方实际有什么反应？ | 区分预期、真实反馈和其他解释 |
| 方案看似好但可能承受不起 | [WW-1.4](wan-tools/WW-1.4.md)、[TM-077](tools/TM-077.md) | 你最不能接受哪一种后果？ | 先确定不能越过的边界，再估计试验规模 |
| “自己的事”和“别人的事”含混 | [TM-142](tools/TM-142.md) | 在这件事上，你已经作过什么承诺？ | 保留既有职责，再区分选择权和共同协商部分 |
| 想做却一直未开始 | [TM-132](tools/TM-132.md) | 最近一次准备开始却没开始，当时具体发生了什么？ | 判断提示、能力、机会或意愿哪一处需要进一步核实 |
| 学过但不会用 | [TM-121](tools/TM-121.md)、[TM-120](tools/TM-120.md) | 你希望自己在什么真实场景里，独立完成哪件事？ | 将“学会”变成可观察表现，再区分练习与迁移问题 |
| 不知道是否继续追问 | [TM-062](tools/TM-062.md) | 内部检查：这个未知的不同答案会改变方案吗？ | 无影响就不再问；能改变才确定最便宜的获取方式 |

这些只是候选，不是固定题库或正式模型名称表；实际名称、机制和边界以具体条目为准。使用提问工具前读其运行文件或 WW 正文。只用一个提问动作澄清了目标，不等于已经完整运行该工具；最终报告可以说明其澄清作用，不夸大完成程度。

不要问“你是不是因为害怕而不行动”“所以对方就是不负责任吧”。这些问题先塞入结论，再索取赞同。改问具体事件、行为和可观察的差异，允许对方给出相反答案。用户情绪值得回应，但不能充当他人动机的证据。

用户说不清时给一个短小的中性示例或两三个方向，保留自由回答；不要让示例成为唯一正确答案。问题地图足够支持有条件的分析就推进，分析发现关键缺口再返回提问。不要为凑齐表格而耗尽用户耐心。
