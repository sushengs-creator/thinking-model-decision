# 决策报告交付规范

信息足以支持当前判断或用户要求先出一版时，交付自包含的决策报告。默认在当前对话中给出，用户不必回翻逐轮问答。需要下载、归档或排版时再按要求保存到当前任务的输出目录；真实个人报告不写进可复用技能包。

## 报告需要回答的问题

先给当前建议，再展开必要证据。下面是报告的内容要求，可按复杂度合并为简短段落或表格，不要求逐字套用标题。

1. **当前建议与前提**：眼下选什么、先做什么、为何。信息不足时标明“阶段性”或“有条件建议”，说明哪个未知会阻止最终判断。避免无依据的百分比或精确评分。
2. **问题定义**：用一句话重述需要决定的事，交代用户的目标排序、硬约束、期限与范围。若开始时的问题在对话中得到修正，说明最终解决的是哪个问题。
3. **事实、假设和未知**：列出真正影响选择的材料，注明来自用户陈述、提供文件或外部核实；用户说过不等于已独立证实。关键未知解释会影响哪项判断，不罗列无关的资料需求。
4. **模型分析与方案比较**：通常一个主模型，至多三个补充或反证工具。引用实际读取的 ID、名称与相关来源，说明该模型如何改变问题表述、比较标准或动作。比较合理备选及有意义的基准，给出收益、代价、依赖与不可恢复后果；适合比较时用表格，不编造数字。检验一个有竞争力的替代解释或方案，不把推断直接写成根因。
5. **行动计划**：给出可执行的第一步和随后安排；明确做什么、何时或什么触发下做、怎样观察结果。只使用已知或标为建议的责任人、时间、成本和资源，不虚构他人承诺或代用户对外执行。
6. **风险与修正条件**：最值得注意的失败路径、何时继续/调整/暂停/退出，以及出现什么新证据会推翻建议。区分可以撤回的试验和一次性决定，不能把所有选择都包装成可逆试错。
7. **待确认事项与复盘**：如仍有关键缺口，给出最少必要核实任务；有合适时点或信号时提出复盘建议。不要在报告末尾再发一套大问卷，也不要未经请求设置提醒或监控。

若用户没有提供日期，不捏造决定日或最后期限；需要报告日期时使用实际生成日期。跟踪修订时可以在当前对话注明“修订版”及变更原因，不把软件版本号当报告日期。

## 简版与阶段性报告

小决定可以精简为：建议与前提、问题及关键事实、备选比较和模型作用、下一步与更新条件。规模缩小，信息层次仍应清楚。

阶段性报告应把“现在就能做的”“取决于待核实条件的”分开；有必要时明确暂不能可靠地做出最终选择，同时交付信息核实或降低损失的行动。不能因一项信息缺失而把全部内容留空，也不能为了完成报告假装已有定论。

## 后续信息怎样接入

新证据、目标或约束到来后，更新问题定义、受影响的方案比较和行动，简述“什么信息变了 → 哪个判断随之变化”。保持仍成立的部分，明确旧建议是否继续适用。决策由用户作出，报告支持其判断，不替其规定人生目标。
