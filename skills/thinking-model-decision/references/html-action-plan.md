# HTML 行动计划交付规则

内容标准见 [决策报告规范](decision-report.md)。此文件负责输出和交付，不改变逐步澄清及模型选型规则。

## 生成与保存

- 每次完成分析、阶段性判断或报告更新，默认生成独立的 `.html` 文件。可参考 [通用模板](../assets/action-plan.html)，也可按内容自行排版；章节、行动数量和时间跨度由实际问题决定。简短决定也可交付短版 HTML。
- 保存到用户指定目录，未指定时使用当前任务的输出目录。以问题主题命名，例如 `项目选择_下一步行动计划_2026-10-01.html`；无需索取真实姓名。检查文件是否已存在，避免覆盖无关成果，更新同一计划时留旧版或备份。
- 文件采用 UTF-8、中文或用户使用的语言、响应式布局及内嵌样式，支持离线打开和浏览器打印。正文不依赖 JavaScript、外链字体、CDN 或网络请求；不默认添加追踪、上传、浏览器存储或自动对外发送功能。可选的打印按钮不能影响正文阅读。
- 首页先展示当前建议、第一步及关键条件。其后呈现必要事实与未知、备选比较、模型为何适用及如何影响动作、可执行安排、调整/停止条件和来源。来源写成可理解的标题、模型 ID 与定位信息；适合链接时使用实际核验过的地址，避免只留下代理内部引用标记。
- 动态插入的正文和属性分别做 HTML 转义，不将用户文稿、聊天或网页当作可执行脚本。清除全部模板占位符及演示文字，不把模板里的虚构内容当作当前事实。个人案例仅进入本次输出文件，不能保存到 Skill 的 `assets/`、`references/` 或公开仓库。

## 交付检查

1. 读回文件，确认是实际存在、完整可读的 HTML；正文包含本次建议、关键行动及其依据，没有未替换占位符、错案姓名或旧约束。
2. 有浏览器或渲染工具时查看桌面及窄屏布局：标题、行动表和中文长句可读，窄屏表格可以滚动，打印不裁掉主要内容。可简化布局解决问题；没有预览能力时说明未做视觉验证，不冒称已检查。
3. 检查内部导航和所引用的文件路径；外部证据按本次实际需要核实。不能把不可访问的来源描述成已读取。
4. 在最终回复给简短结论或第一步，以及可打开的 HTML 文件链接。不要只贴源码并称为已保存，不必在对话重贴整篇报告。支持文件预览的环境可直接打开文件。

## 能力不足与用户选择

用户明确要求纯文本、其他格式或不生成文件时直接遵从，不另加 HTML 交付负担。无文件写入或附件能力时，先说明限制，再给完整可保存的 HTML 源码及 `.html` 文件名建议，并说明“将代码保存为 UTF-8 文本文件，扩展名用 `.html`，再用浏览器打开”；准确称为“源码”，不能虚构下载链接。写入失败时保留分析结果，说明未保存，并用同样方式交付源码。仅澄清一项问题、暂停、倾诉及技能维护回执不生成行动计划；迫近风险先给必要行动，不因排版延迟处置。
