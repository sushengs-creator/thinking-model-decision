# TM-151 · 5Why分析法

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
日常、后果较轻且过程可核对的问题反复出现，分析停在症状或“没责任心”时使用。输入最近一次具体偏差、过程与记录、参与者叙述、已有补救、调查权限。先问“最近一次具体哪里不同于预期，有哪些过程能核对？”严重事故和复杂多环节系统不由本工具独立下根因结论。

## 转换与分支
- **界定偏差。** 用时间、数量、对象和要求描述这一次事件；必要补救先行。事实、回忆、推测、冲突分开，保留已有效的防线。
- **把每层回答变成调查单元。** 对候选原因列机制、支持/反对/缺失材料。继续问尚未解释的过程，或问参与者当时看见什么、如何操作；没有依据就记待查，不凑五次、不以人格词收尾。
- **反向查机制，横向查遗漏。** 用“因此”检查链条是否漏环及成立条件；自洽不证明事实。比较出错/没出错的过程，听其他参与者；保留反证和竞争分支。多因素或反馈明显时扩展系统调查，不强行找唯一根因。
- **分发生与检测。** 查什么造成偏差、什么环节可发现，不能因末端发现问题就说所有防线失败。鱼骨方向或假设分支均须继续验证；“没有任务记录”不能单独推出没人做。
- **把已支持部分变成临时措施。** 按风险、证据、成本和新问题选干预点，不选最深就算最好。写负责人、落实证据、结果指标、复查时点与未决调查；实施与改善分别记录。复发、新反证或措施没落实时重开相应环节。

## 最小成果与验收
交付事件差异、因果分支及逐层证据状态、下一核查、暂定改进和执行/结果复查。须明确哪里尚未查清，以及暂停后由谁继续。已有相称措施或证据/权限不足可以暂止，不能宣称根因已经找全；一次没再犯也不能证明因果。汇回主流程HTML方案。

## 边界与接口
五次提问、顺畅故事、可做改进均不等于证实。人格标签不能替代机制，补系统条件不自动免责。不独立用于严重事故定因、心理诊断或问责。复杂问题需要现场、多方、记录和专业调查，增加链条或模型数不能替代。

人格判断过快先交TM-025；需细分中介、共同原因和反馈交WW-3.3；多防线与问责混在一起交WW-6.10，但保留实际调查和适当专业处理。仅按缺口接续。
