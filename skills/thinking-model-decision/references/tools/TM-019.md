# TM-019 · 检查连续结果是否真的改变下一次机制

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
仅因连胜、连败或重复很多次，就认为下一次该反向补偿时用。抽签不放回、规则保底、学习、疲劳等会真实改变后续条件，不能统称独立。输入事件规则、既往序列、基础资料与准备行动；缺口问：“上一次结果之后，下一次的规则、剩余对象或参与者状态有没有变化？”

## 转换动作
1. 从理由中暂时删去“已经连续几次”，看还剩什么支持反转。若只剩轮到、欠我或该平衡，把它标为补偿期待，不将它算作新证据。
2. 核查生成机制：是否放回、是否有保底、设备参数是否稳定、人的能力资源是否改变。独立与否由规则及事实判断，不因事件名称相同就默认成立。
3. 若机制已知、独立且不变，沿用该机制支持的单次判断；长期比例接近基线不需要下一次超额反向。若基础概率未知，不编一个一半；异常连串可提示检查机制或设备，并不保证随后反转。
4. 有真实反馈时说明具体因果路径，例如连续工作造成疲劳，而非用“连着顺总会倒霉”替代。把行动连到当前资源和可承受代价，不为补回过去结果额外加码。

## 最小成果与停点
交付规则核对、机制变化证据、基础资料可靠性和剔除补偿期待后的判断。能说明过去结果究竟通过什么改变未来，或目前没有这种证据，即完成；不以猜中下一次验收。新规则、状态或偏差证据出现时重新分析。

## 工具箱接口
未知机制可交证据更新工具；人的学习或疲劳确实变化时交系统解释。极端观测后自然回落需另查基线与噪声，不能把回归均值解释为下一次必须过度反向。
