# TM-154 · 手段—目的分析

状态：v2运行文件；来源与实际试跑范围以tool-index.json为准。

## 触发和输入
目标清楚却动不了，清单越来越细，或一直补准备条件而没回到原动作。取可验收目的、期限、现状、可用动作、资源与权限；只追问影响下一步的缺口。目标不清先澄清。

## 差距怎样变成下一步
1. 将目的与现状并列，选一个重要且能改变的差距，找能缩小它的动作。把目的与该手段分开，保留可行替代路，不以投入多少判继续。
2. 检查动作前提，分已具备、待确认、缺少。仅缺少的前提设子目标；记清它服务哪个动作、完成标志和返回点。子目标再卡住才往下查，不按任意数量扩写清单，也不假造权限。
3. 动前核整个方案共用资源和其他前提：这一步会用掉什么、堵住什么、可否恢复。局部差距缩小但毁掉总目标时不执行原顺序，改成联做、交错、换法或暂停。各工具不能重复使用同一份时间钱财。
4. 子目标达成后回到原动作，确认仍适用，再做并验收效果。拿到工具、获准使用、实际行动、达到目的四个状态分开；补条件不等于完成目标。
5. 条件补不上、出现依赖循环、超过剩余时间或代价时返回上层目的，重选动作；没有可接受路就说明缺口并停。不要把“这个手段不通”写成“目的不可能”。学习任务另检验为什么有效、换条件能否迁移。

## 最小成果与交接
交付一条目标—差距—动作—前提/子目标—返回点—验收链，及资源冲突与换路条件，给当下在权限内能做的一步。结束于可执行下一步、目标验收、等待外部条件或明确停止，不无限生成任务。

路径开放且目标未定可按需要交WW-5.5；从现有构件开新路交WW-8.3；新手只会解当前题交WW-4.1。多子目标冲突交TM-153验证整套安排，工期另交TM-155。检测到冲突不是已解决；把产物交回整体行动方案与HTML。
