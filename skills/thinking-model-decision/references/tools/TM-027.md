# TM-027 · 检查热门与好评是否能支持自己的选择

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
面对陌生选择，把销量、点赞、排队人数直接翻译成好用或适合自己时用。多数选择可以有信息价值，不能反向只选冷门；紧急处置也不适合机械等待。输入自身任务、看到的社会信号、来源与决定代价；缺口问：“除了很多人选，它需要帮你解决的具体问题是什么？”

## 转换动作
1. 分开他人行动、评价和可核事实：报名数说明有人报名，推荐语说明有人表达体验，任务测试才直接提供相应表现。不能把关注、购买、使用和持续效果合并为一个指标。
2. 核对参考对象是否与本人需求、预算、使用场景相近。年龄或兴趣标签相同不够；对入门者有效的产品可能不满足复杂任务，负面体验也要看条件是否相关。
3. 追溯信号真实性与独立性，检查同源转发、促销、分发机制和可能的刷量。跨平台出现不自动等于独立证据；不确定时保留来源未知，不编造造假结论。
4. 按后果和期限补少量有区分力的材料，如具体差评、试用任务或已完成案例。最后写出一条不依赖热门程度的选择理由；没有时先缩小试用，不照搬固定等一天或找三条的规则。

## 最小成果与停点
交付信号类型、可信度、需求匹配与待核条件。热门只作为线索、选择有与本人任务直接相关的依据，即完成；不必证明多数错误。若参与人数本身创造协作价值，明确把它计为真实条件而非删掉。

## 工具箱接口
评价样本缺退出者时可交样本选择工具；真实候选可交取舍工具。若线索主要来自前人模仿前人的顺序链，转信息级联分析，而不是多收几条同源好评。
