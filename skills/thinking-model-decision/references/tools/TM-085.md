# TM-085 · 瓶颈效应

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
每段都提效、大家都忙，最终完成量却不增加时用。最慢、最忙或排队最长只是线索，不足以认定唯一瓶颈；更不能把人贴成瓶颈员工。需要整体目标、必要环节与替代路、需求、有效能力、等待返工及底线；目标不清时问：“你们最想改善的整体结果是什么，最近一段时间真正完成了多少？”

## 转换动作
1. 画必要依赖并核对任务流，扣掉换型、中断、返工和空等，比较有效能力与需求。约束可在授权、规则或外部需求，不只在工位；临时拥堵与持续容量不足分开。
2. 用积压、闲忙及处理记录提出候选，检查减少该限制能否改善整体结果。可用既有变化或可承受的小幅调整检验；单点改善无效还要查共同约束、幅度不足和观察太短，不能立即排除。
3. 先释放瓶颈已有能力：减少无效占用、中断和返工，让前序按其节奏送入合格任务。非瓶颈不必为了满负荷制造积压；必要安全质量检查应提高有效处理能力，不能简单删掉。
4. 现有能力仍不足再比较扩容或替代路径，核对约束是否已经转移。复测整体完成量、周期、积压与质量，若需求不足先改需求侧；短期波动优先临时资源、预约或节奏调整，避免永久过量配置。

## 最小成果与停止
交付目标、候选约束、证据、共同约束、优先动作、预期整体指标和复测时间卡。证据足以支持一项可观察改动即可完成，不需找出永恒唯一瓶颈。改善后重新识别，质量恶化或任务结构改变立即改判。局部提速不等于整体成果，建议、执行和结果分开。

## 工具箱接口
积压收支不明交存量—流量；等待含反馈滞后交延迟；规则比扩人更可能有效时交杠杆思维；投入取舍交边际成本。瓶颈分析优先解释当前吞吐约束，不代替所有价值和长期能力判断。
