# TM-036 · 让风险异议和替代方案真正进入共识形成

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
团队很快一致，讨论只剩如何执行，风险与替代方案没被正式处理时用。结局差不能倒推出群体迷思，领导先讲话也不是充分证据；关键是共识形成过程。输入发言与决策记录、被跳过警告、可行替代和拍板权限；缺口问：“这个方案最有力的反对理由，后来被怎样回应了？”

## 转换动作
1. 回查哪些风险被讨论、哪些未表达、哪些提出后被压下，明确未表态不等于支持。将“为了团结先不谈”造成的评估缺口单列，而非笼统批评团队文化。
2. 在安全可行渠道收独立判断，主持者后表态，必要时轮换质疑职责。质疑必须能进入记录并得到实质回应，不安排一个人象征性唱反调后照旧推进。
3. 用相同标准回答三件事：最强反对依据、失败最可能的环节、另一条可行路径。对替代方案也查风险，避免把当前方案的缺点与假想替代的优点比较。
4. 把异议采纳或未采纳的理由、剩余风险、负责人和复查触发条件写入决定。硬时限下可缩小决定范围或保留回退，不为充分讨论无限延迟必要执行。

## 最小成果与停点
产物是一份经异议检验的决策记录，含替代路径和停止或复查条件。重要反对意见有回应、未知与责任清楚即可形成决定；不以人人满意或必须出现分歧验收。独立评估后一致可以是健康共识，若质疑者受到惩罚则先修表达机制。

## 工具箱接口
未解决风险交证据或试验工具，剩余路径交取舍工具，决定交执行工具。沉默是否源于意见气候可另查，但不能用一套心理解释替代方案本身的检验。
