# TM-047 · 区分没启动检查与目标规则能力等不同障碍

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
有能力的人反复判断失误，“认真一点”却没帮助，需要定位检查在哪环中断时用。这是功能框架，不是三类人格、三个脑区或临床诊断；熟悉稳定场景可依靠经验。输入一次判断的第一反应、目标、分析记录、知识与环境；关键追问：“当时第一个答案出现后，你接下来实际检查了什么？”

## 转换动作
1. 记录自主反应给出的答案，将其暂列假设，再按后果判断值不值得重开。快速本身不是错；第一反应未经必要检查就被接受，才提示入口可能缺触发。
2. 核查反省功能：究竟要解决什么、用什么标准接受结果，是否已偷换成维护面子或原判断。复杂计算若服务错误目标，增加算力仍可能只是辩护。
3. 查看算法处理与规则是否够用：能否同时维持关键条件、模拟一个真实替代、正确使用必要知识。分别标缺资料、条件负担、技能或规则缺口；一次错误不足以唯一定位，也可多环节同时有问题。
4. 按障碍给不同修复：未启动则设触发器；条件多则外化清单或用工具；缺规则则学习或请适任者；目标偏移则重设问题。最后指定能改变结论的反证，检查分析是否允许更新。

## 最小成果与停点
产物是第一反应—重开触发—分析目标—资源规则缺口—修复动作图。至少有一处有证据的障碍和针对性下一步，即完成诊断；修复建议、执行与再次表现分开，不以解释得通或更自信验收。证据不足时保留多种功能解释，不给人贴能力标签。

## 工具箱接口
明确微技能交练习工具，资料缺口交核验工具，目标偏移交立题或开放判断工具。无需将所有小事升级为三层分析；功能定位清楚后就把后续任务交给更具体工具。
