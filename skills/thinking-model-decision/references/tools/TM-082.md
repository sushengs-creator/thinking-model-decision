# TM-082 · 存量—流量模型

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
新增提高但总量下降，处理更多却积压增加，或不清楚总数怎么变时用。存量不总越高越好，积压可能正是要减少的对象。需要系统边界、期初状态、期间全部进出和单位；口径不明时问：“你说的总量在什么时点按什么规则统计，哪些情况算进入或离开？”

## 转换动作
1. 固定边界、期间和状态定义，区分外部进出与内部转移。同一对象从甲组到乙组，对组是流量，对全体只是转移；活跃状态池的进入退出必须定义，不能直接把滚动月活当固定存量套算。
2. 列期初存量，以及新增、回流等全部流入和流失、失效、报废等全部流出。统一人数、件数等单位与时间；流率先按期间累计，变化的流率分段算，不能把期末速率乘整个期间。
3. 以期初加流入减流出对期末，处理反复进出与重复计数；残差先查漏记、分类、估值或口径改变，不直接解释为业务流失。流入下降只要仍多于流出，存量还会上升，须区分水平和变化速度。
4. 比较增加流入、减少流出和主动清理不良存量的候选动作。相同净变化可能有不同成本、可行性与副作用；算出缺口不证明流量为何改变，保留待查机制。

## 最小成果与停止
交付边界单位说明、期初—流入—流出—期末表、对账差异及干预入口。账能对上或残差来源已明确到待核项即可完成；指标是滚动窗口、分类不断变化且无法转换时停用简单恒等式，先改口径。变化建议、实际投入和存量结果分别记录。

## 工具箱接口
流量为何变化交因果调查；存量反过来影响进出交反馈回路；在途流量重复追加交延迟效应；要选增流入还是减流出交边际和机会成本。记账关系只负责直接增减，不把对账完成当成原因已查明。
