# TM-143 · 第三选择

状态：v2运行文件；来源与试跑范围以tool-index.json为准

## 触发与近邻
两个选项都不理想、合作只剩各执一词，或怀疑某条“不能改”只是默认条件时，检查二选一怎样成立，再决定是否创造新方案。与TM-102第一性原理共享约束核查，但聚焦已有选项、各方目标与共同验方案；与WW-6.14第三物不同，后者提供可共同修改的对象，有共同草稿不等于有更好方案。已证实的真取舍不强行造第三路。

## 最小输入与追问
原A／B及不满意处、想保护的结果、期限与可用资源、各方说过什么、哪些条件被视为不能改。默认先问最关键的一点，如：“让你觉得目前只能这两种做法的条件是什么，它是怎样确认的？”已知便不重复问；之后再依回答检查目标或条件。涉及对方需要时问其实际表达与核实办法，不替他回答；个人选择无需虚构另一方。信息不足可先交付前提核查和条件候选，不把假设写成共识。

## 转换与分支
**保留基准与搜索边界。** 先记录当前可行基准、最迟决定点和探索上限；用户未给上限时提出待确认值，不伪造承诺。不可逆期限、必要履约与现实危险先处理，探索不自动暂停责任。临近截止按真实截止时刻倒算当前余额，扣除阅读、分析和已执行所耗时间；余额不明给压缩分支，不把提问时的完整时长重新分配。余量不足先用已知目标与责任作取舍并完成回复，不再展开新一轮搜索。

1. **从“两格”回到结果。** 将A、B分别连接到它保护的目标与代价。标明目标是本人偏好、对方明确表达还是推测；不能为凑新方案悄悄降低目标。产物是原选项—目标对照。
2. **核查支撑二选一的前提。** 形成简短记录：前提／依据／已证实或待查／可否变更及谁有权限／答案变化会怎样改变选择。先查最可能改变行动的一条；未证实不等于可任意改，人的需求须向本人核实。若关键限制均已确认且目标不能兼得，转入真实取舍，不重复建议已被排除的远程、换人或延期。
3. **移动有依据的条件，形成可评论候选。** 查范围、时间、顺序、分工、形式或资源；明确改了什么、保护什么、增加何种代价及由谁承担。多方问题允许相关人修改标准、提出替代或拒绝；尚未参与的候选标为待共同核对，不称双赢。若只是让对方接受自己的要求，退回核实目标与权限。
4. **与A／B用同一口径验候选。** 比较核心目标、硬约束、依赖风险、全周期资源及接受状态。分阶段要分列近期与最终交付，并合计搜索、已用、沟通、准备、实施、补做、维护、复盘成本；跨周额度分别确认，不能只报第一阶段成本或把延期说成原工期没变。未知保留分支，不凑分数。通过条件检查也只说明可进一步协商或执行，效果须另观察。

## 最小成果与验收
交付“二选一前提核查＋同口径候选比较”：哪条前提被确认或推翻，因此增加／淘汰哪个选项；新候选或没有更好方案的结论；谁下一步核实、协商或执行什么，时点、成本、依赖与可观察证据；继续／停止／转回基准的条件。新选项只有真正改善用户认可的目标、守住约束且代价可接受，才可优先；原方案或合理妥协也可胜出。提出、接受、执行、结果分开记录，不以谈得愉快或对方口头认可认定问题已解决。

## 停止与工具箱接口
达到搜索期限或资源上限、继续问不会改变行动、关键条件确实不可兼得，或新候选不优于可行基准时，停止扩展并说明应取舍什么。基准不清、关键价值冲突时交方案取舍；权限和已有职责不清交TM-142；容量与变更代价不清交WW-1.4；不知道值不值得继续查交WW-3.5；各方只在人身对抗时可用WW-6.14的共同草稿承载分歧。仅按缺口交接，不能将全部关联工具固定串联。历史故事及52%／32%数字不作本次成功率依据。
