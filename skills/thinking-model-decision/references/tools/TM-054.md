# TM-054 · 贝叶斯更新

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
新消息让用户准备改口，或多条利好是否足以支持原判断时用。目标价值冲突、证据是否值得购买、投入能否承受，不能由后验直接回答。需要事件及期限、证据出现前的判断、新证据及来源。旧判断缺失时问：“看到这条消息以前，你原来怎么判断，依据是什么？”无法回忆就记未记录，不倒推先验。

## 转换动作
1. 固定可判定事件，保留有竞争力的其他解释；核对原判断的对象、时期与口径。参考类失配先重建基线，不能把修正基线伪装成新增证据的效果。
2. 登记证据来源、时间、共同原因及是否已经进入原判断。转述同一消息不重复计权。逐个解释检查“若它成立，这条证据是否常见”；两边都常见则区分力弱，只知道某解释下罕见不能宣布另一解释成立。必要时画“解释—证据常见程度—依据或未知”空表帮助补缺。
3. 输入可靠、两假设互斥且覆盖问题时，用后验赔率＝先验赔率×似然比，再将赔率换回概率；似然比不能直接乘概率，相关证据不能直接连乘。缺输入则记上调、下调、不变或暂不更新及理由，同时保留原判断强弱。仍可能成立的经验假设不锁成零或一。
4. 对照已有收益、损失与行动门槛，检查变化是否足以改行动。未跨门槛可维持行动；门槛未定只给判断更新。列下一条真正有区分力的证据，不自动安排持续搜集。

## 最小成果与停止
交付事件、原判断、新证据、竞争解释、更新结果、行动是否改变、再更新条件。每项变化可回指新增信息、重复来源已处理即可完成，允许“不足以更新”。遗漏解释或环境改变时重新建模。计算、建议、接受与执行状态分开。

## 工具箱接口
基线缺失交给基准率；需要决定是否买下一条证据，交给信息价值；需要投入选择，交给期望值和约束工具，不把概率上升当批准。
