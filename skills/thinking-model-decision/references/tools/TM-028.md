# TM-028 · 保留独立判断并把异议安全带入讨论

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
群体一致时隐去异议，或附和后又把妥协解释成原本认同时用。与多数一致可能有充分依据，沉默也可能是承担压力后的合理策略；不要求当场冒险反对。输入讨论前判断、会上新证据、表态压力与职责；关键追问：“你改变想法之前，出现了哪条新的信息？”

## 转换动作
1. 找回并记录原判断和理由，没有事前记录就说明是回忆。将后来变化分别标为新证据、规范压力或暂无法判断，不逼用户证明自己始终独立。
2. 做私下选择检验：若没人知道自己的表态，是否仍会选同一项？答案变化提示压力成分，不能证明少数意见正确。原判断同样需要可靠证据审查。
3. 把异议改成具体前提、未处理风险或可核反例，再选择与职责、后果相称的渠道：书面补充、个别核对或请求暂缓表态。区分想说、建议说与已经反馈，不能代替用户宣称已表达。
4. 组织层面若有条件，可先独立写意见、主持者后表态，并记录异议如何处理。共识来自检验后的决定；决定后按明确职责执行，不等于必须在内心完全同意。

## 最小成果与停点
交付原判断、新证据、压力因素、待处理异议与最终决定状态。观点变化来源清楚、重要信息有合适进入渠道，即完成；不以勇敢反对或大家改口验收。若表达有明显代价，先保留记录和边界；证据更新可合理支持多数方案。

## 工具箱接口
具体异议可交证据核验，表达代价可交参与者与安全反馈工具，已决定事项可交执行工具。只有同源行动不断累积时，才增加羊群视角，不把所有一致当同一种机制。
