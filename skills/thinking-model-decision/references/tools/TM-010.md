# TM-010 · 把逐次加码的要求重新分开决定

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
小忙变大忙、免费尝试后不断加码，理由只剩“前面都答应了”时用。技能增长后的自愿升级可能合理，明确威胁或欺骗也不能归成用户自愿锁住自己。输入原承诺、后续要求、新增时间或权限、当下意愿；关键追问：“这次新增要求里，哪些是你最初并未答应的？”

## 转换动作
1. 按顺序列出每一次请求与实际答应范围，分别标建议、接受和已经做完的部分。前一项完成不自动产生后一项义务；不要把对方期待写成用户承诺。
2. 将当前大要求独立摆出来：“若没有前面的小承诺，现在是否愿意接受？”若答案变化，继续辨别来自真实信任、技能积累，还是“我既然是热心的人就必须继续”的一致性压力。
3. 重新核对这一步的收益、时间、风险和退出影响。原本已承诺部分可协商交付，新增加部分保留独立选择；若信息曾被隐藏或存在施压，直接处理透明度和边界，不以心理效应替对方开脱。
4. 为时间、费用、权限等范围升级设置一次清楚确认，给出可执行的接受范围、替代帮助或拒绝表达。用于自我小步行动时也保留停止权，不将一次开始变成必须不断加码。

## 最小成果与停点
产物是承诺链、此次新增成本和接受／拒绝／待协商的独立依据。范围与选择权清楚即可结束，不以最后答应或关系保持融洽验收。发现最初就已约定完整范围，改为检查原承诺可履行性；新信息到来后允许重谈。

## 工具箱接口
明确范围可交给沟通或排期工具；双方目标冲突时才引入参与者与协商工具。本工具不输出隐瞒成本、诱使他人一步步服从的设计。
