# TM-058 · 安全边际

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
排期刚好、资源刚够，一处偏差就可能使承诺落空时用。多留一点不自动安全，过去最大偏差也不是真实上限。需要不可承受的失败线、基准状态、可信不利偏差及缓冲代价；底线未明时问：“出现什么具体结果，你就无法继续承担这个方案？”专业标准约束的边界不能自行编造。

## 转换动作
1. 在同一尺度上列失败线与基准，算原始余量。时间估计纳入准备、沟通、交接和复查；备用资源核实是否真的可用，不能把未获承诺的帮助当现有缓冲。
2. 从同类记录、关键依赖及假设失效构造可信不利区间；同源风险联合压测，找最先失效的节点。同尺度时以原始余量减不利偏差展示剩余边际，这只是情景算术，不能转换成未经依据的失败概率。范围无法估计时先缩暴露或补关键资料。
3. 对准薄弱处改结构：缩范围、谈期限、移除单点依赖、备份或保留退出。比较缓冲成本及机会损失，避免每项资源一律囤积。已有余量不得成为额外冒险的理由。
4. 为实际消耗设置预警和对应动作，写清谁能收缩、何时复查。正边际也要列仍未覆盖的风险；普通波动即可越线时，不按原方案承诺。

## 最小成果与停止
交付失败线、基准、不利偏差、剩余余量表，以及补缓冲、缩小、退出或继续的条件建议。可核实的压力情景已检查、剩余风险被明示即可完成。边界、关键成本、相关性变化或备用资源用掉时重算；异常尚未导致失败也算重评信号。建议、资源落实与实际运行状态分开。

## 工具箱接口
若目标本身值不值得尚不清楚，交给价值与取舍工具，安全余量不能替代目标判断。将最脆弱依赖交给约束或项目执行工具；若准备继续收集偏差数据，仅把能改变承诺的缺口交给信息价值工具。
