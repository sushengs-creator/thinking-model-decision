# TM-102 · 第一性原理

状态：v2运行文件；来源与试跑范围以tool-index.json为准

## 触发与近邻
被“只能这样做”卡住，需要重新检查达成目的的手段时使用。不是把东西拆到材料就得到答案，也不是用“本质”压过经验、他人权利或既有职责。

## 最小输入与追问
希望达成的结果、现行做法、声称不可改变的条件及依据、过去选择理由、当下资源权限。关键追问：“如果不沿用这套做法，最怕失去的具体结果是什么？”若连目的也未明确，先澄清目的。

## 转换与分支
1. 把现行步骤逐项连接到它原先保护的结果。没有解释的步骤先标待查，不因看不懂就删；分开事实、硬约束、历史惯例和行为假设。
2. 对所谓底层事实检查凭据与成立条件。说不出必然性便降为待验证假设；涉及人的响应，不能像物理定律一样确定推演。
3. 保持目的，提出不同实现手段。回查它们过去被排除的原因：若成本、工具或协作条件已变，重新评估；若条件未变，不能仅靠换说法宣称创新。
4. 给候选补上工艺、训练、转换、维护和配合成本，检查有权改变的范围。选可回退局部验证关键假设，同时保留原做法保护的功能。

## 最小成果与验收
交付一张“目的—约束—惯例—假设”表和至少一个有资源、依赖、验证办法的替代路径。验收看原功能是否保住及实际代价，不看拆得多深或用户是否赞同。

## 停止与工具箱接口
关键约束无依据或无法测试时，保留条件方案；出现安全、权利或责任缺口先修复，不能用创新免除。成本范围可交敏感性分析，待证行为假设可交证据工具，多方配合问题可交参与者或协商工具。
