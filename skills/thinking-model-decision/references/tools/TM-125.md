# TM-125 · 相邻可能

状态：v2运行文件；来源与试跑范围以tool-index.json为准

## 触发与近邻
远期想法难落地，或“时机未到”却说不清缺什么时使用。当前可用条件决定眼前能实现的新状态，一步完成又会改变后续条件；可行性与值得做须分别判断。

## 最小输入与追问
谁在何期限为谁交付什么、真正可调用的技能数据工具权限协作、成本与关键未知。关键追问：“如果明天动手，哪项关键操作目前确实做不了？”听说过、买到或学完不能自动记为可用。

## 转换与分支
1. 缩定本回合的可检查结果，盘点已可用、可取得但需投入、待验证、当前缺失的条件。接入、学习、数据质量和审批都算依赖，不藏进“一步”。
2. 找阻断承诺的关键连接，用最小测试验证并预定通过与尚未证明的标准。其他依赖仍保留；局部跑通不意味着整体可行，失败先查具体原因再改路径。
3. 同时检查这一步是否服务目标、需求有无依据、成本能否承受。可做但没人需要时转核需求；权限不足先请求相应支持，不能越过授权完成更远动作。
4. 完成后重新盘点可复用作品、已核数据、真正掌握的技能或可调用关系，并记录消耗的资源、失去的选项。写出下一项具体操作与仍缺条件，远期机会只记假设。

## 最小成果与验收
交付“当前条件→验证任务→新增能力→下一步候选”的证据链、执行者与复查点。新增能力要以能完成原先不能做的操作来核验，可以无实物，但不能只凭学习完成或工具购买。

## 停止与工具箱接口
关键条件未满足则停在可支持范围，不把“只差一步”变成无限研究。需求与价值可交目标/用户任务工具，关键未知交信息价值，资源消耗与关闭路径交二阶或可逆决策；路径推进不预言最终成功。
