# TM-111 · 共同知识模型

状态：v2运行文件；来源与试跑范围以tool-index.json为准

## 触发与近邻
行动相互依赖，单方先动会受损，内容已经清楚却不确定别人是否准备时使用。各自知道不等于知道他人也知道；现实协议只把关键状态公开到风险可接受，不能证明无限递归的严格共同知识。

## 最小输入与追问
必须同步的角色、同一版本安排、准备证据、公共渠道可靠性、协调权限及回退条件。关键追问：“谁没有准备好，会让你的启动产生什么具体损失？”独立低风险任务不启用全套协议。

## 转换与分支
1. 固定必要角色、协调人和替补，写明共同要依赖的命题、动作、版本与例外。先核实内容真伪；传遍群体的错误只可能形成共同信念。
2. 在共同可见且可访问的位置记录各角色 READY/WAIT。READY 需指实际准备完成，不能只是已读；每人知道其他角色可见并理解状态同义。
3. 条件齐备由有权协调者发唯一 GO，否则 HOLD；约定谁发布、如何确认当前版本。计划时刻到达本身不等于获准启动，公开表态也不能证明真心赞成。
4. 预先决定缺人、超时、断线和版本冲突如何暂停、升级或回退。启动后再检查实际产物与完成状态，发现差错按约处理并修正准备要求。

## 最小成果与验收
交付知识状态缺口、公开准备表、启动及异常规则。必要角色能识别当前版本、彼此准备状态和合法信号；提议、接受、准备、启动、完成分别留证，不以群里一致回复替代执行验收。

## 停止与工具箱接口
关键角色不可达或无协调权限时保持等待并解决条件，不能逼表态。含义分歧交共同基础，承诺与权限交言语行为，方案尚未选定交协调博弈；若利益不同，公开信号不能替代协商。
