# TM-100 · 委托代理模型

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
让别人代表自己办事，并给对方一定决定权时调用。普通卖方不自动是代理人；目标是获得委托净收益，不是把任何偏差消灭。最小输入是委托事项、决定权、双方目标、报酬及验收办法；先问：“你交出去的具体决定是什么，对方哪些事可以自己定？”

## 转换动作
1. 写清目标、底线、自主决定范围、需报告和重新商定的变化。并列双方利益、时间尺度与承担后果，指出可能偏离的位置；存在利益差异或信息差不证明代理人恶意。
2. 为关键行动与交付设置适量证据和验收来源。执行者可以提供材料，但不应独占目标定义、事实记录与完成判定；必要时用独立复核。照片、汇报和单次样本只支持它们实际覆盖的范围。
3. 比较报酬、阶段交付、长期合作和退出安排。奖励要顾及可归因结果与多任务，防止易量化成绩挤掉重要工作，也不把运气全转给执行者。将监督、保证履约和剩余偏离损失合并考虑，避免重复计入，并与亲自做或其他安排比较。
4. 约束委托方：按约支付、允许报告坏消息、不临时改目标或无限加任务。检查管得更细是否损害速度、适应和合作；把准备、沟通、核验及修正时间算入管理投入。

## 最小成果与停止
交付“最小授权书”：目标、权限、底线、报酬、信息、验收、变更与退出。各项足够支持双方行动即可完成，不追求面面俱到的控制。没有代办和自主决定权时改用交易或信息工具；任务、角色、激励和成本变化后重谈，而非默默扩权。

## 工具箱接口
签约前难核实的属性交给信息不对称；隐藏行动是否真的变化交给道德风险和因果证据；自己做或外包的总成本交给交易成本。授权草案、双方接受、实际履职、验收通过和最终效益分开记录，验收通过仍不代表所有长期目标已经达到。
