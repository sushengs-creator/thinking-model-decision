# TM-150 · BATNA

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
只按预期价格或对方让步决定是否成交，不清楚谈不成去哪，或把待落实机会当退路时使用。需要当前协议、真实期限、不成交后的路径、可行性与依赖、完整成本风险、预算和本人价值排序。优先问“这份协议谈不成，你实际能采取什么行动，哪些已经确认？”

## 转换与分支
1. **固定不成交后的世界。** 列具体路径、开始时点和仍需履行的责任；协议内改价/改范围不混作协议外替代。不成交、保持现状、继续寻找均可成为真实路径。
2. **查路径是否够得着。** 标已确认、待第三方确认或不确定机会，核对资源资格、报价范围、期限和执行时长。继续寻找可评估，未来理想offer不能登记成确定收入；没有现成备选也不等于必须接受。
3. **比较出最佳替代。** 用相同时间和成本口径，按用户价值、硬约束及风险比较，保留非金钱维度；不把所有替代相加或重复扣机会成本。不能排序时指出关键未知，给出查什么及两种答案如何改变决定。
4. **生成接受条件。** 将眼前协议整体与最佳替代比较，预算另作能否支付门槛。只有数值和换算偏好有依据才计算保留值，否则给条件组合。接受边界不是开价、客观市价或对方肯让的证明；保留用户的责任、健康及不可接受条件。
5. **把退路做成行动。** 从真实失效时刻倒算确认、付款/签约及缓冲；不把提问时余额重新计满。比较继续谈或找的收益、延迟、搜索费及失去选项风险。锁备选需计取消条款和占用资金；报价、资格、偏好变化就重算。

## 最小成果与验收
交付替代表（证据/依赖/完整代价/风险/期限）、当前最佳替代、协议接受条件、最迟决定点与执行步骤。给接受/继续谈/退出的条件依据；拟定、对方同意、预订/签约和结果分开。条件已经够用或到点须决定时停止，不以无限找更好替代拖失窗口。汇入主流程HTML方案。

## 边界与接口
BATNA不保证谈成，也不自动回答对方还会让多少；不虚构筹码或施压。替代不理想仍须尊重硬约束与本人价值，不据此劝接受伤害。不是每条BATNA都有受保护进入权或零成本。

资源取舍扩大到其他用途时交TM-064；希望保留进入权或分阶段承诺时交WW-3.9；不知道下一次询价是否值得时交WW-3.5。按缺口接续，不重复算同一成本。
