# TM-059 · 逆向思维

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
“怎样做好”太宽泛、已经很偏爱一个方案，或必须先避开致命失败时用。不是别人做什么就反着做，也不是发现风险后什么都不做。需要目标、当前方案、不可接受结局和可控制因素；目标未清时问：“这件事最要保住的结果是什么，怎样才算没有保住？”

## 转换动作
1. 选一个适合当前问题的反向入口：从失败结局找成因、从反面证据检验判断，或从确定终点反推必要条件。不要把三种用法全铺开。先允许列具体行为和依赖，不急着替喜欢的方案辩护。
2. 把“会失败”的标签展开成可观察链条：哪个行为或缺口通过什么机制毁掉哪个目标。分别标已见迹象与推测，优先找破坏性大且正在发生、能够控制的少数环节。没想到风险可能只是经验或表达不足，不能算安全证明。
3. 把失败路径转换为不做清单、前置条件、预警及触发动作；控制不了的因素改为降暴露、备替代或重新谈承诺。终点倒推时给准备、等待、沟通和复查留空间，不只排核心作业时间。
4. 回到正向目标检查：堵住路径以后，方案是否仍能创造用户要的价值，是否误杀了正常可承受试错。新的关键事实出现时允许修改禁令，不能把临时防范永久化。

## 最小成果与停止
交付少数关键失败链及各自对应的防范人、条件和动作，保留尚未处理的未知。致命路径已有具体应对或明确不可承受，即可结束；如果所有内容仍是泛泛担忧，停下补现场信息，别继续穷举灾难。防范建议被接受、落实和降低损失各是不同状态。

## 工具箱接口
失败链要核实真实因果时交给证据工具；条件明确但缺安排时交给执行工具；堵住失败后仍缺有吸引力的方案，交给选项生成或需求澄清。该工具不独立证明成功，也不强制把任何日常困惑改成风险审计。
