# TM-083 · 反馈回路

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
同样问题反复出现、短期解决后反弹，或投入越多越糟时用。一次外部冲击、两个数字同时变化，不足以证明存在闭环。需要目标、时间范围、历次行动结果、资源限制与可观察变量；路径不清时问：“这次结果出现后，你们下一轮的行动或条件具体怎样改变了？”

## 转换动作
1. 选一个反复变化的变量为起点，沿结果追到下轮决策和行动，逐箭头写机制及证据。只有路径返回起点才标回路；没返回保留因果链，未证实箭头标假设，不为了画圆补原因。
2. 判断绕一圈是放大原变化的增强回路，还是抵抗偏离的调节回路。增强可以加剧衰退，调节也能维持不良状态；标明目标、延迟、容量与竞争回路，不能用正负替代好坏判断。
3. 比较切断关键连接、减慢放大、建立竞争回路等候选干预，找有权限且后果可承受的位置。识别谁得益、谁承担新增负担，不靠抑制记录量伪造问题减少；多个回路可能同时限制效果。
4. 需要验证且能安全撤回时，选一个主要假说，确定观察期、结果及代价上限；观察窗口服从延迟。变量不按预期走，先查箭头、执行和时滞，再改动作。不可试行则通过既有记录和机制证据限定判断。

## 最小成果与停止
交付文字回路图、待核验箭头、主干预点及实施或补证安排。闭环能解释重复现象、主要未知和复查方式明确即可完成，图本身不能证明主因。无闭环证据就停用；范围、容量或竞争机制改变时重画。不凭R/B标签预测精确速度和拐点。

## 工具箱接口
积累量对不上交存量—流量；纠偏过头且有在途动作交延迟效应；要比较干预位置交杠杆思维；需证明改变有效交反事实因果。假说、接受的动作、实际执行与反馈分别保存，不强制所有问题走小试。
