# TM-162 · 比较优势

状态：v2运行文件；当前来源、卡片与实际试跑范围以tool-index.json为准。

## 触发、近邻误用与最少输入

一个人两样都快，是否应该全部承担；较慢的人能否通过交换任务贡献；家务、小团队分工或外包只比速度却忽略替代产出。首先确认最关键一个问题：“要让双方各自省时、让合计投入最低，还是按同一截止时间完成？”已有目标不重复问。只问个人兴趣、只有一种任务或单方耗时资料，不足以确认比较优势。

最少读取两方×两任务的同质单位耗时、两方真实需求、当前基线、分割规则、各自可用工时/开始与截止时间，以及交接、检查、返工等增量成本。补充资源/技能限制、效率随数量改变的区间、报酬和双方愿意接受的条件。质量不等时先定义验收与返工，不把未合格产出按相同单位计算；不知道时间价值时不编钱和分钟的汇率。

## 判断方向，不直接全量分配

同一方每单位X的机会成本＝X耗时÷Y耗时，单位是Y数量；比较两方同方向比值。机会成本较低的一方是多做X的候选，另一方是多做Y的候选。倒算Y时说明单位，不能混用分子分母。一个人两项都有绝对优势不排除另一人在一项有比较优势。

令甲的X/Y时间为aX/aY、乙为bX/bY，且aX/aY<bX/bY。不计额外成本、固定效率时，正交换量x个X换y个Y要让双方严格省时，需aX/aY<y/x<bX/bY。端点有一方持平。比值相等时，这个严格区间为空；不能据此否定其他合作机制，也不能虚构由比较优势产生的收益。若比值次序反转，应交换候选承担方向，不能沿用身份标签。

这个区间只筛方向。需求、整数件数、成本、产能及意愿可能使实际可行集合为空；“谁放弃少”不构成无条件任务分配命令。不要求专业化到底。

## 逐人核候选数量与成本

用已知需求列少量候选；小范围整数题可完整枚举，说明覆盖范围。若甲替乙做x个X、乙替甲做y个Y，必须x≤乙需要的X、y≤甲需要的Y，且交付单位可实现。双方其余需求仍由原承担者完成，不能只计算代做部分。

对每个候选，分别写每人：原任务耗时 → 新的全部生产耗时 → 新增沟通/交接/检查/返工/疲劳成本 → 净节省。固定时间模型中：甲净省=y×aY−x×aX−c甲；乙净省=x×bX−y×bY−c乙。双方严格省时要求两个结果都>0；合计节省不能掩盖一方更累。判断固定方案能承受多少协作成本时，各人的上限就是该人未扣成本的节省，达到上限只是持平。

效率不是固定值时按所做数量分段计算。例如前10件每件6分钟、第11件起9分钟，做11件应为10×6+1×9，不是11×6，也不把全部11件按9分钟。原安排与新安排分别按适用产量核算；用边际耗时重审机会成本，不以旧平均率证明新方案。技术改善时重新测同质效率，再更新比值、方向、基线与交换量。

无偿互助、总投入优化与付费外包分开。若一人净省为负而另一人愿补偿，须改变并确认目标、费用/时间价值和本人意愿；不能悄悄把“双方省时”换成“总账省钱”，也不能把尚未支付、未同意的补偿算成已获益。

## 检查能否完成与实施

每人的生产、协作和自己剩余任务均计入可用工时。将总人时与日历完工时间分列；只有同起点、独立并行、无等待且交接已计入时，全部完成耗时才是较大的一人工时。存在交付依赖、共享设备、异步起点或等待时按时间线计算。缩小交换量会带回自做任务，必须重算完整工时，不保证自动满足容量。

列候选表后，按已确认目标筛选或比较，不擅自加权平均个人得失。双方获益也不自动等于公平，更不能从团队/国家的总收益推出每个成员获益。若已知数据不足，给条件分支和最小补测/确认动作；不只留下问卷，也不填造生产率或偏好。未确认同意、质量或技术的候选不得称已可实施。

最小交付包括目标/假设、带单位的机会成本、实际交换数量、每人新旧账、总人时与完成时点、容量和意愿检查、下一步负责人/时限/成本及重算条件。资料已足时形成一份方案及需要的HTML行动报告，不额外要求用户先挑模型。

达到当前决策所需的核查即可停。没有满足目标的整数方案、成本侵蚀某人收益、超容量/期限、质量失败或有人拒绝时，停止旧方案，明确调整需求、期限、交接或经同意的补偿后再算。需求变化先重算可交换量；工具、技能、疲劳或可用替代用途变化再更新机会成本。未经授权不通知他人、不重新派活或支付费用。
