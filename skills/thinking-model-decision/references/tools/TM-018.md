# TM-018 · 拆开顺畅故事与可核验因果解释

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
事情刚发生就有一个太顺畅的单因故事，并据此决定行动时用。故事连贯不代表错误，缺少已知原因也不代表随机无因；叙事写作本身无需被消灭。输入发生的事实、现有解释、材料来源与要采取的行动；缺口问：“哪一条已知事实，是这个解释还没有说清的？”

## 转换动作
1. 左栏列带时间和来源的观察，右栏列“因为……所以……”解释。把推测动机、未来走向和补出的背景移到右栏，未知处留空，不用好听的衔接替代材料。
2. 找被现有故事漏掉的事实，并提出至少一个同样能解释现象的竞争机制。数量不必凑多，重点是它是否导向不同的处理方式；无资料就写候选，不随手给各故事分概率。
3. 检查解释能否被观察反驳：什么情况出现会不支持它？同一原因若成功失败都能事后解释，要补具体条件，而非直接断言必错。区分发生先后与因果作用。
4. 选会改变当前行动、且可取得的关键证据，例如退出发生在流程哪步，而不是继续润色总故事。取证后保留原解释记录并更新，不倒写成早已预见。

## 最小成果与停点
产物是事实与叙事分离表、竞争解释、下一条区分性证据及暂定行动。主要因果跳跃已显露，行动不再依赖未经标明的故事，即可停；无需找齐世界的全部原因。若证据支持多因素共同作用，就保留组合解释，不强求唯一元凶。

## 工具箱接口
候选因果链可交机制检验或小试工具；取证明显只挑支持时才用反证检查。若问题已经转为如何讲清经验证的经历，可交表达工具，不反复审判连贯性。
