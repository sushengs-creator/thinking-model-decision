# TM-020 · 用同类实际结果校准工期和交付承诺

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
反复低估工期或预算，仍以“这次顺一点”排满理想路径时用。范围突变、资源被撤或故意压低承诺需要单独处理，不能一概怪个人乐观。输入可验收交付、资源、依赖和类似已结束项目；缺口问：“做到什么程度才算交付完成，谁会确认？”

## 转换动作
1. 固定本次完成口径，找任务类型、资源条件与复杂度相近的已结束案例，包含延期或未完成者。先看真实处境相似度，不只挑梦想中的成功样本。
2. 列实际耗时分布、范围和常见阻塞；案例少时说明局限，给条件范围。历史最大值不是未来最坏上限，不能把原文比例或统一加倍当通用缓冲。
3. 回到当前项目，逐项记录偏离基线的硬证据，如已实测复用、已确认人员或新增审批，再拆排内部任务。把等待、联调、返工留在实际会发生的环节，缓冲须有对应原因。
4. 预演交付失败最可能卡在哪里，设重新估算的触发点。目标日期、当前预计和对外承诺分别记录；硬期限不变时优先讨论缩小可验收范围，不用许愿挤掉依赖时间。

## 最小成果与停点
交付参考类基线、调整依据、交付范围、依赖和复估节点。预测能追到实际记录，关键依赖有检查条件，即完成本轮；制定计划不代表已按期交付。出现范围变化或未获资源应重估，若承诺受激励扭曲，停止仅做认知纠偏。

## 工具箱接口
校准后的范围可交任务拆解与资源协调工具；参考案例过少可先设计小试估时。与参考类预测共享同一份数据，不重复运行后当作两个独立佐证。
