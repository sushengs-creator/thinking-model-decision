# TM-084 · 延迟效应

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
动作发出后看不到结果，就反复追加，后来又集中超量时用。拖延是尚未行动，延迟可能在观察、执行或系统响应；不能把无效措施永远解释成还没到。需要行动时间线、在途承诺、过程指标、历史见效范围与安全线；缺在途信息时问：“现在有哪些已经决定或发出、但结果还没有完全体现的动作？”

## 转换动作
1. 画行动—执行—系统变化—观测—下次决定链，标时间花在哪一段。区别信息传递慢、组织执行慢与系统自身响应，不一律把必要审查当可砍流程。
2. 建在途台账，列数量、预计生效范围、可撤回性及已兑现部分，估计全部兑现后的状态。只盯当前缺口会重复下手，延迟期间也要检查途中是否真的在推进。
3. 用历史或流程拆解给延迟区间，安排复核。匹配反馈速度与噪声控制追加幅度、频率：在途已够则暂停重复追加，不足且可回退时补小量。更多监测不等于更频繁干预，时间预算含准备协调与检查。
4. 设置即时安全线和过程信号，越线先减险，不等最终效果。到期仍不见效，依次查执行、测量和原判断；记录实际开始生效时间与量，更新下一轮估计。时间顺序吻合只是因果线索，晚到结果不能自动归功最近动作。

## 最小成果与停止
交付带时间范围的链路、在途台账、下一复核点、追加量与立即干预条件。已能回答路上有什么及会把状态推到哪里即可完成；没有已发行动或可信响应机制时停用等待解释。环境、执行进度、风险边界改变时提前改判，不死守复核日。

## 工具箱接口
需核算在途最终影响交存量—流量；多次纠偏形成振荡交反馈回路；到期需要暂停权限交停止规则；争论到底谁造成效果交因果工具。承诺、执行、到达和观察效果分栏，不把已下单当已补足。
