# TM-152 · OODA环

状态：v2运行文件；来源与实际试跑范围以tool-index.json为准。

## 触发和最小输入
局面在变，方案反复改而解释没检查；团队各自更新但不同步。利用当前目标、旧判断及日期、新信号、已有行动、反馈延迟、权限与期限。只补一个影响行动的缺口：“这条新信息具体改变了你原来哪项判断？”不先讲一大段概念。

## 从旧理解到新动作
先列旧判断及原依据，把新信号分为支持、挑战、尚不能区分，标来源、发生时间、获取延迟。挑战时提出具体的可查解释；支持时允许维持；未知时保留分支。多次动作无效先检查实施、执行偏差及见效窗口，不能直接判解释错误。

选一项能推进当前任务的动作，有学习需要才另列它检验什么。写权限、总资源、谁承担代价、能否撤回、谁能叫停。高代价先证据或演练，不借对抗故事欺骗别人，也不为速度跳过必要许可；必要履约本身有价值。

分别估计局面变化速度、反馈延迟、见效时间，设常规复查与重大变化即时重看条件。反馈分支：未执行→查实施条件；已执行但过早→按约等待并监测风险；足够窗口仍无效→核对执行与竞争解释；改善→记录支持但不确证因果；副作用超限→停或收缩。新信息支持原方案时继续，不反复变向。

将结果写成一张更新记录：旧判断／新证据／维持或修改理由／新动作／下次触发。团队同步证据版本、方案及检查时间；收到、同意、执行、效果分开。反馈未发生不得补造。无需每轮机械从O到A顺序走完。

## 最小成果、停止与交接
交付一次有理由的判断更新或维持、现实动作和反馈安排；能说明下一步为什么变化或不变即可结束本轮。无新增信息、继续取证不值成本、风险不可接受或期限到来时停止重跑并处理必要事项。

WW-3.16与本工具同机制，不重复运行；团队协调可交WW-6.9，但共同承认不证明内容真实；支配规则需检验时再交TM-130。OODA不是精确因果鉴定或样本量计算工具。把产物交回主流程形成方案与HTML，不能把四步列表当已解决。
