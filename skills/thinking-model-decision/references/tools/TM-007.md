# TM-007 · 找出旧流程锁定点并设计可回退迁移

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
旧流程效果不佳却因技能、接口、用户配套而难换时用；“一直这么做”只是线索，单纯习惯或仍划算的长期投入不自动构成锁定。输入现有路径、替代方向、不能中断的功能及已知依赖；缺口先问：“如果明天切换，最先会有哪件具体工作做不下去？”

## 转换动作
1. 沿当前障碍回溯最初选择，只记录可证实的来由。将已付投入与未来仍会发生的迁移、培训和维护成本分开，不为解释现状编一条必然历史。
2. 画出自我强化关系：使用人数带来规模收益、熟练度减少操作成本、接口要求相互兼容、各方因预期别人继续使用而跟随。标出每个连接的实际证据，以及旧方案今天仍提供的价值。
3. 比较继续维持、局部桥接与完整迁移的未来收益和风险。旧投入已经花掉，不能再次计费；失去现有兼容性却是真实未来代价。若替代尚未证明关键功能，先留为候选。
4. 选一个能隔离的连接点试改，例如新任务走新表、旧任务保留出口。明确数据核对、责任人、回退方式与扩大迁移的门槛；失败时修连接或回退，不为证明创新继续推全量。

## 最小成果与停点
产物是强化关系图、三条未来路径比较和一个可回退试点。锁定点与现有价值分开、切换有验证门槛即可结束诊断；试点提议、接受、执行与运行结果分记。若没有强化关系，仅是个人习惯，改用习惯或执行工具。

## 工具箱接口
接口清单可交给迁移规划工具安排顺序；未来方案代价可交取舍工具。只有试点跨团队时才引入参与者协调，不预设所有旧路都该被打破。
