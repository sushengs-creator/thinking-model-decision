# TM-022 · 看清不操作会发生什么并主动取舍

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
试用自动续费、授权预选或流程默认状态未经讨论就继续生效时用。合理默认能省力，主动设定且符合需要的预设无需一律关闭。输入当前选项、到期结果、设置者、变更代价与本人目标；缺口先问：“如果你现在什么都不做，接下来会发生什么？”

## 转换动作
1. 列出默认值、触发时间和不操作的后果，将“没选”改写成实际仍会发生的状态。区分设置已生效、只是页面勾选和用户已主动确认，不把界面展示当完成修改。
2. 检查保留原因是操作麻烦、把默认当专业建议，还是把现状当已拥有权益。分别查清变更步骤、独立依据及真实损失；不能仅凭平台设定推断它适合当前用户。
3. 假设无预设，按真实需求重新选择，再补回切换导致的数据、提醒或协作影响。默认服务双方利益也可能合理，关键是费用、用途与退出条件是否清楚。
4. 输出保留、修改、待查三类项目及触发日期。若为他人设计默认，明确告知选择及后果，提供容易退出或主动选择途径，不将设计者自认为有利的目标强加给所有人。

## 最小成果与停点
产物为默认状态、后果、受益者、主动选择理由与待执行清单。每个重要默认有明确去留依据或信息缺口，即完成分析；修改建议、用户接受、操作完成与后续状态分别记录。发现退出造成关键功能损失先重评，不为追求自主而盲关。

## 工具箱接口
需要操作的设置交执行工具并核验保存状态；长期费用交总成本比较。只有大量工作流互相依赖时才加入迁移工具，不把一次勾选扩成全面系统改造。
