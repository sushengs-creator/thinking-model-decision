# TM-017 · 分开亲手完成的成就感与成果使用价值

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
因为亲手完成，便觉得成果比独立反馈更好，甚至认定别人也应同样重视时用。创作成就感与纪念价值可以真实存在；仅因拥有或尚未完成却不甘放弃，要区分近邻机制。输入本人做了什么、完成状态、服务对象与质量要求；缺口问：“这个成果交给别人后，需要帮他完成什么？”

## 转换动作
1. 将“我投入并做成了”的个人收益与“别人用它得到什么”的外部价值分栏，保留两者。完成可增强能力感，但不据此宣布所有人都必然高估，也不套固定倒U曲线。
2. 假设相同作品出自别人，按同一事前标准再评价。记录改变的是质量判断、感情价值还是保留意愿；不能用作者身份做减分，更不能把关系投入简单说成自恋。
3. 获取与用途对应的反馈：匿名比较、实际任务完成情况或具体缺陷记录。区分赞美投入与认可效果；若方案不好但部分模块有效，保留有效部分，不强求全部推翻或全部留下。
4. 决定保留、修改或停做，并说明每项依据。若用于学习动机，可建议本身值得且能完成的小制作；成就感属于额外收益，作品价值仍需独立复核。

## 最小成果与停点
交付作者视角、独立标准、使用反馈和修改决定。完成以关键用途能被检验、情感与质量各有位置为准，不以接受批评或放弃原作验收。若真实用途就是纪念或练习，应调整评判标准；若反馈不足，停在待验证而非猜别人不懂。

## 工具箱接口
可观察缺陷交迭代与执行工具；迁移或重做代价大时接未来成本比较。只有冲突涉及多人贡献与认可，才加参与者协调，不用模型给作者贴固执标签。
