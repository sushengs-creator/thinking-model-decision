# TM-025 · 把人格标签还原为行为情境与责任

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
从一次不回复、迟交或语气不好跳到“他就是这样的人”时用。补情境不取消责任，也不能要求受持续影响者等所有原因查完才建立边界。输入可观察行为、影响、已知角色条件与历史记录；关键追问：“这一次具体发生了什么，和原来约定差在哪里？”

## 转换动作
1. 用时间、动作与结果替换人格标签，另列自己的情绪和解释。“六小时未回”可核对，“不重视我”仍是解释，二者不能悄悄合并。
2. 提出少量可检查的情境原因，如信息没到、权限不足或优先级冲突，明确标假设并查记录或询问。只列想象中的借口并未完成分析，也不必为凑三种替对方编故事。
3. 比较不同时间、不同场景是否重复，核对相同资源与责任条件。条件到位仍反复失约时，针对执行和沟通模式处理；条件持续不具备时，优先处理系统阻塞，允许人和情境共同起作用。
4. 分别给出系统修补、具体行为要求与必要边界，并约定下一次能观察什么。例如材料到齐时点、提前告知规则和替补安排，不用“变负责一点”代替可执行要求。

## 最小成果与停点
交付行为—情境证据—责任范围—改进与边界四栏。解释不再跳到整个人，责任和下一观察点清楚，即完成本轮；不要求谅解或继续合作。出现持续伤害或明确失约可先保护边界，不以查情境无限延后处理。

## 工具箱接口
系统卡点交流程或资源工具，责任争议交参与者协调，明确要求交反馈与执行工具。若只是知名背景污染各项能力评分，再转分维度评价，不用同一解释包办。
