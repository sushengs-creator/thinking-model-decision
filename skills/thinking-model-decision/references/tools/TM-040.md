# TM-040 · 验证我喜欢是否真的代表目标人群

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
把自己的偏好或同圈朋友的赞同扩展成“大家都想要”，据此投入资源时用。自己的体验可作起点，明确目标群体已独立表达的真实共识也可以使用。输入目标人群、本人偏好、已问对象与准备行动；关键追问：“你说的大家，具体包括哪些人？”

## 转换动作
1. 把普遍判断降为可检验假设，写明哪类人在什么场景会选择什么；另列已观察到的信息。“我觉得合理”支持个人理由，尚不支持多数比例。
2. 核查样本是朋友、重度参与者还是目标总体，补看沉默、不使用和反对者。便利样本可发现需求差异，不能用几人试用就可靠估算总体支持率。
3. 用中性问题追问最近行为与原因，必要时安排透明自愿的小试。区分不需要、不知道、门槛高、没资源与不敢说；不使用不必然代表不喜欢，口头同意也不等于愿意实际投入。
4. 做共识不足检查：若同意者比预期少，方案还能成立吗？按需要设计小范围、分众或逐步扩展，让投入不必押在想象的多数上，并写明何种新证据足以扩大范围。

## 最小成果与停点
交付目标人群—假设—样本限制—行为验证表及稳健行动。普遍性主张有边界、缺口与决定相连，即完成；不要求否定自己的偏好，也不以用户赞同助手验收。更广且可靠的新记录到来时更新；完整小组共识只能在该小组内表述。

## 工具箱接口
样本缺口交调查工具，分众需求交选项工具，已验证方案交执行。若只是怕公开不同而跟随，转群体表达压力；本工具关注自我投射，即使没人表态也可能需要运行。
