# TM-099 · 交易成本

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
报价便宜却反复解释、验收和返工，或在自己做、外包、固定合作之间选择时调用。交易成本不是所有成本的别名，也不能假设内部协调免费。最小输入是同一交付、候选安排、质量责任及主要投入；先问：“这些方案要完成的是同一项什么交付，质量和责任要求是否相同？”

## 转换动作
1. 统一质量、时点、责任和使用频率，再列可行安排。除一次交易和内部完成，也可有固定合作、框架协议或混合分工；交付范围不同，先校准范围再比较价格。
2. 分列直接采购或生产成本、外部搜寻议价与监督成本、内部组织协调成本、切换退出成本。时间涵盖准备、沟通、验收和复查；同一损失不在风险费、返工费与机会成本中重复计算。缺数列范围和来源，不虚构精确总价。
3. 检查专用投入、未来变化和重复交易：资源换人后是否仍有价值，条件变化能否重新约定，反复协作能否省事。三者是解释条件，不是自动选择自制的公式；可通过接口、权属和退出安排降低锁定。
4. 先排除不能满足硬约束的方案，再比较合理区间和压力情景，明确谁承受交付失败和重谈代价。只有小范围合作能消除关键未知时才试行；概率不明的风险不能随手定一个费用加入总价。

## 最小成果与停止
交付“可比治理成本表”：共同交付、成本分类、区间依据、锁定与退出条件、选择及改判线。关键成本方向足够清楚即可完成；范围不可比或关键责任不明时暂停排序。规模、频率、专用投入或执行能力变化后重算。

## 工具箱接口
质量难核实交给信息不对称；委托后的权限和验收交给委托代理；多做一次或改合作规模交给边际分析。条款建议、双方同意、合作开始、实际投入和净节省分开记录，不把低报价或签约本身写成节省已经实现。
