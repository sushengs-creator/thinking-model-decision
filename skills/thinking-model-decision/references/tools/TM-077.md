# TM-077 · 可逆决策

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
小事审批太久，或大事被“错了再改”带过，需决定能否先试、投入多少时用。方案价值与目标冲突不能只凭可逆性决定。需要拟采取的一步、受影响者、损失、反馈时点与恢复办法。退路含糊时问：“如果做错，谁能在多久内恢复到什么状态，哪些损失仍留下？”

## 转换动作
1. 展开自己、用户及合作方的资金、时间、数据、权益与信任后果。把发现错误、退出窗口关闭、恢复完成放在同一时间线上，标最大可信损失与残余影响；技术撤销不能代表全部后果恢复。
2. 分别判断损失能否承受、反馈是否清楚及时、发现时是否来得及恢复，不能加总评分掩盖严重风险。条件充分提出轻量行动；不足则缩金额、期限、范围或人群，同时检查缩小后能否回答原问题。无法拆小且关键后果不可恢复时提高证据门槛，等待也要考虑新信息到达与机会损失。
3. 把退路写实：触发信号、最晚退出时点、权限、人员资源和恢复目标。必要备份、迁回流程先核实，未验证退路标依赖。反馈分不清原因时先改观察办法，不能把“做了”当“学到了”。
4. 到承诺节点选择扩大、维持、暂停、退出或正式承诺。每次扩大范围、延长期限前重查恢复窗口。证据够用且持续承诺有价值时，不无期限停在体验阶段。

## 最小成果与停止
交付本次范围与投入上限、各方残余损失、反馈信号时间、退路权限资源及下次承诺点。退路可描述、依赖明确且反馈赶得上窗口即可形成安排；否则交补证或缩小建议。损失越界、反馈失真、退路失效时立即改判。提案、用户确认、执行、反馈分列。

## 工具箱接口
需付费保护未来进入权时交期权；反馈是否值得获取交信息价值；方案本身是否有用交目标与取舍工具。有退出条款只是一条待核实信息，不据此直接宣布可以放心试。
