# TM-046 · 在重要问题提前收工前补最关键的一次检查

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
重要问题的第一个答案很顺，就以“很明显”结束检查，或现成答案偷偷替换原问题时用。省力本身必要，熟悉、低代价、可撤回的选择不需完整分析；慢想也会犯错。输入原问题、快捷答案、关键条件、后果与可逆性；缺口问：“这个判断若错了，最难补回的后果是什么？”

## 转换动作
1. 按重要性、复杂性、不确定性、可逆性和错误代价决定检查强度，不把命中几项变成风险分数。一个严重不可逆后果就值得复核；低代价熟悉任务可以说明理由后停止。
2. 写回真正的问题，与当前答案实际回答的内容并列。例如受欢迎没有回答适不适合，听过没有回答会不会做；找到被省略的条件，而不是泛泛要求再认真一点。
3. 按问题类型选择最小有效检查：条件题逐项核对全部约束；解释题找可区分替代原因；选择题比较可行备选和失效条件；学习题合书复述并举适用或不适用例。不要全部机械叠加。
4. 核查旧经验来自稳定环境、长期实践与及时反馈，标本次条件变化。对重复高后果流程固定复核点；工具可承担整理计算，来源、适用范围和结果仍须检查。

## 最小成果与停点
交付原问题、快捷答案、遗漏条件、补查结果及停止理由。与后果相称的关键检查已完成，即结束；不以花时长、写长文或推翻直觉验收。发现关键资料错误或条件变化时重开；缺规则或分析能力时改为补工具，不责备省力。

## 工具箱接口
被发现的因果缺口交解释工具，估计缺口交证据工具，学习缺口交练习工具。入口只选必要检查，不把全部思维模型列成必须执行的清单。
