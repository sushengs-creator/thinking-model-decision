# TM-128 · 概念转变模型

状态：v2运行文件；来源与试跑范围以tool-index.json为准

## 触发与近邻
原题改对，换题却沿用旧理由，或将反例都当例外时使用。关注产生答案的解释是否修订；已经理解却执行不了，需查技能、意愿和环境，不能把不同意都叫顽固。

## 最小输入与追问
明确问题、原预测与理由、真实结果、新解释及当前疑问。关键追问：“你原来凭什么这样判断，现在最说不通的是哪一步？”先留理由，不只留下对错，也不预设教师或 Agent 的解释必然正确。

## 转换与分支
1. 记录原预测、旧解释、实际结果和疑问，核查题意、数据、计算与观察条件。证据有疑问先查证；操作失误或陌生知识缺口先处理，不强造概念冲突。
2. 按卡点比较旧解释不足、新解释能否理解、为何值得相信、还能预测什么。四个方向可交叉，不是必须顺次过关；允许图示或演示，理解与认可分开。
3. 选择一个能区分新旧解释的小变式，先预测、说明理由再核对。检查是补条件、重组还是替换旧解释，避免把“总会变大”换成另一个绝对规则；新增陌生知识过多就缩小变化。
4. 隔时或换例再查理由与表现，稳定后减支架；旧解释继续主导则返回有证据的卡点。旧直觉偶尔出现不抹去已有学习，一次成功也不证明长久改变。

## 最小成果与验收
交付实际使用的解释、证据缺口、所需支持、可区分变式及下一次调整标准。验收看新条件的预测和理由，认同讲解、原题答对或自述“懂了”均不充分；原因不明可保留并列解释。

## 停止与工具箱接口
新解释证据不可靠时先停止说服；已经解释与迁移成功却做不到就转条件处理。关系组织交图式，争议证据交更新或溯因工具，动作差错交练习；不把反例演示当现实执行完成。
