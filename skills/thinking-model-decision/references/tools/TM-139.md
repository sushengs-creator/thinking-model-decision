# TM-139 · 团队心理安全

状态：v2运行文件；来源与试跑范围以tool-index.json为准

## 触发与近邻
求助、报错、异议可能带来羞辱排斥，或问题说出后无人处理时使用。心理安全是对人际风险的共享判断，各岗位体验可不同；沉默也可能因渠道慢、材料难找，不能只凭领导承诺或一个人胆大评定团队。

## 最小输入与追问
一次真实卡点、向谁求助、预期后果及实际回应、权限与任务标准。关键追问：“当时为什么选这个求助方式，后来具体发生了什么？”分别记录本人经历、见过他人经历与推测；未开口就没有此次接收者回应证据。

## 转换与分支
1. 还原事件并保留竞争解释。入口难找先改入口，熟人更快先查响应安排，担忧报复再查具体依据和其他成员体验；不得用诱导问题逼出恐惧答案。
2. 选择当事人可接受的私下、书面或公开渠道，说明可见范围与保密限制。已有报复先保护和修复环境，不能强迫认错或许诺无法兑现的匿名；改变条件的责任交有权者承担。
3. 接收者先核对问题，再修操作、训练或材料，说明采纳、待查或拒绝的依据。保护提出问题本身，同时保留明确公平的工作标准与失职责任，不把安全等同于免验收。
4. 给问题指定处理人、动作、期限与复查任务，把更新反馈给提出者；再看下一次同类任务能否改善。增加报告可能只是发现更多，需区分报告覆盖、实际差错和任务差异。

## 最小成果与验收
交付事件证据与未知、可用渠道、具体回应、处理责任及任务检查。提议、已被接受、已处理、效果分别记录；发言更多、气氛好或点头不能证明安全提升及工作解决。

## 停止与工具箱接口
若核心是工具、资源或规则无效，转对应问题；有现实危险先保护求助。知识接续交交互记忆，反馈方式交反馈干预，反复规则问题交双环学习；不把修复环境全压给沉默者。
