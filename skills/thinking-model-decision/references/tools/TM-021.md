# TM-021 · 先恢复原问题再选择合适的方法

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
第一反应总是上表格、加奖励、做培训或用某熟悉方法，尚未明确问题就进入实施时用。重复有效规范可以是专业，不能为了多模型而强行换法。输入原困惑、第一反应、期待改善的结果与已知障碍；关键追问：“如果暂时不能用你想到的这个方法，你最希望解决的事是什么？”

## 转换动作
1. 并排写原问题和当前方案所回答的问题，检查“该不该做”是否被换成“怎么做”，“为何没效果”是否被换成“如何加大力度”。保留被改写前的目标与不做选项。
2. 提取熟悉工具暗含的原因。例如提出培训，往往假设障碍是不会；要求打卡，可能假设障碍是缺动力。将这些标为待验证假设，再核查是否其实缺权限、资源、清楚任务或协作条件。
3. 依据不同机制生成少量真正不同的做法，允许保留熟悉方法。为各法写适用前提与失败条件，不只更换名字，也不机械凑三种；过去成功只能证明过去条件下有效。
4. 用现有证据选先验证哪个机制，再选与它匹配的工具。条件不足时，下一步可以是询问卡点或查看记录，而非立刻实施整套方案；设看见何种反馈就换法。

## 最小成果与停点
交付原问题、隐含改写、候选机制及有条件的工具选择。问题定义不再由工具预先决定、选法依据可检查，即完成；不以工具数量或新颖程度验收。若成熟标准正好覆盖问题，保留它；若客观接口锁定使方法换不了，改查路径约束。

## 工具箱接口
清楚的机制缺口交给相应证据、激励、资源或参与者工具；已明确的行动交执行工具。本工具负责纠正入口选择，不持续给整个工具箱加模型。
