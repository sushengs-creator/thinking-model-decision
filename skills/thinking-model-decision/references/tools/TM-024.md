# TM-024 · 补全体验过程或改善关键节点与结尾

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
一次活动、旅行或服务结束后，整体评价被高光、糟糕瞬间和结尾主导，或要改善下一次体验时用。先确认是有清楚起止的连贯经历；多年关系不能缩成两个瞬间。输入体验范围、过程记录、强烈片段与结尾；缺口问：“你现在更需要评价这次经历，还是设计下一次体验？”

## 转换动作
1. 定义开始结束及用户要完成的任务，分别记最强正面、负面片段与离开时感受。峰值不一定美好，记忆评分也不等于整个过程的负担。
2. 评价分支：暂时拿开峰值与结尾，补入等待时长、费用、重复麻烦和稳定质量，再比较原总评是否需要调整。补过程不是否认快乐，而是让决定用到被回忆省略的部分。
3. 设计分支：先守住基本质量，优先消除严重负向峰；再找与用户任务有关的成就点、被照顾时刻与清楚结束。不能延长痛苦来制造更轻松的结尾，也不用赠品遮住质量缺陷。
4. 同时收集过程记录与结束后的评价，观察改善的是实际等待、完成情况还是回忆印象；两者分开报告。若好评继续而堵点未改，不能宣布服务问题已经解决。

## 最小成果与停点
评价产物是全过程账与峰终记忆对照；设计产物是底线、关键节点、收尾改进及核验指标。关键过程未被高光遮住、建议能对应具体环节，即完成本轮；实施和效果须后续确认。经历边界模糊或涉及长期判断时退出两时刻简化。

## 工具箱接口
过程卡点可交流程或约束工具，改进清单可交执行工具。只有需比较不同服务投入时再接取舍，不默认把全部资源押在最后一个惊喜。
