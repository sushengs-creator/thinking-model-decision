# TM-093 · 涌现

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
每个人局部做法看似正常，却反复形成没人单独设计的拥堵、分化或协作模式时调用。结果意外不自动说明涌现；规则固定也可能形成涌现，不必先证明参与者学习。最小输入是整体模式、局部行为、互动记录和出现条件；缺信息先问：“你观察到的整体模式具体是什么，在哪些时间和条件下反复出现？”

## 转换动作
1. 明确微观单位、宏观模式和时间范围。先问整体是否只是各部分数量相加；区分“人数多了”与互动生成的新结构，避免只用抽象词重命名现象。
2. 追出局部动作如何改变邻近者或下一轮的处境，再怎样汇成整体。每条连接附观察或待查假设，同时比较共同外因、中心逐项指令和单点故障；不同机制可以共存，不因发现互动就排除其他原因。
3. 找到可改的局部规则、连接、反馈或边界，说明若机制成立，哪些模式应改变，什么结果会削弱解释。仿真出现相似图形只能展示可能机制，不能证明现实由同一机制生成。
4. 需要且适合时做有边界的改变，同时观察整体模式和被转移的等待、负担或损失。没有预期响应就回查连接；同时改动很多条件时，不能把改善归给其中一个规则。

## 最小成果与停止
交付“局部互动到整体模式链”：现象、生成连接、替代解释、可辨别的改动及观察口径。把一条关键机制说清并给出可证伪条件即完成；仅有一次偶然，或共同原因已足够解释时暂停涌现判断。新的反例出现后改判，整体结果也不能成为无人负责的借口。

## 工具箱接口
没有逐项指挥的秩序形成可交给自组织；参与者还会学习规则时交给复杂适应系统；闭环方向和延迟交给反馈工具；需要归因时交给因果证据工具。建议、采用、执行和观察到的模式变化各自保留状态。
