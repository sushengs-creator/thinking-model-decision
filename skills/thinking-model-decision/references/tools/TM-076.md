# TM-076 · 有限理性

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
选项越看越多、每项资料都不完整，认真比较仍做不了决定时用。有限理性不是偷懒，也不是没有标准的“差不多”；选项少且信息清楚可以直接择优。需要要解决的问题、硬条件、错误后果、可逆性、截止日和搜索成本；边界不清时问：“这次选择必须满足哪些条件，做错后实际会损失什么？”

## 转换动作
1. 先按错误后果与恢复能力确定核验强度。低损失可改可以轻量，高代价难回头需要更多独立资料；后果重大不能靠一个人的“已经想清楚”略过必要审核。
2. 用用户认可的硬条件筛短名单，再聚焦真正影响使用结果的少数差异。把记忆和计算负担交给列表、计算或结构化试用；经验快筛仅在机制相近且反馈可靠的环境有资格使用。
3. 在看结果前规定足够好标准、必要搜索覆盖与截止时间。完成必要核验后出现达标项，可以停止开放搜索；不能为了赶快选中而当场降低硬条件，也不以想象中的完美选项让比较永久继续。
4. 达标后仍犹豫，比较下一条信息可能改变的行动与继续付出的成本。条件适合时用低损失行动取反馈，保留纠错路径；不可逆选择则补关键证据。选择后根据实际反馈调整标准过高或过低，不因外观小差异重启全部搜索。

## 最小成果与停止
交付候选短名单、满意标准、必要核验、搜索停止点和纠错办法。达标且必要检查完成就形成建议；未达标则扩大正确方向的搜索，而非默认选最省事项。期限内仍缺关键条件要明示限制。建议选中、用户确认、实际使用及反馈分别记录。

## 工具箱接口
不清楚是否值得继续查交信息价值；不清楚能否先做交可逆决策；价值冲突不能靠筛选解除时交取舍工具。满意化只是解决有限理性的一种策略，不能替代必要专业判断或真实承诺。
