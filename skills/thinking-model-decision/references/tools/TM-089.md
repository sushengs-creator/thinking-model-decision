# TM-089 · 网络效应

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
用户涨了体验却没变，或平台冷启动不知先补哪一侧时用。总注册量、单位成本下降、跟风和不愿切换都不自动等于网络效应。需要参与者类型、城市品类时段等相关网络、现有用户体验及价格功能变化；适用性不明时问：“如果功能和价格不变，只改变相关参与者，谁的哪项使用体验会变化？”

## 转换动作
1. 定相关网络，排除对当前用户几乎无影响的远处或不活跃参与者。把角色、连接和局部密度画出来；新增同类人可能帮助也可能竞争，新增另一侧或配套者可能改善选择与匹配。
2. 逐对建立“谁增加—影响谁—通过什么—哪个指标—方向”矩阵，查看等待、匹配成功、内容质量、骚扰和收益等实际价值。各侧分别评价，不用平台总量盖住某侧受损。
3. 用既有变化或可行比较检验现有用户体验，排查改版、补贴、渠道及供给质量同期变化。只有规模增长而指标未变时，不声称网络效应增强；早期正作用也可能随密度饱和或拥堵反转。
4. 按证据选择补稀缺角色、集中一个相关网络、分层分配、限流或扶持关键配套。同步观察负向同边竞争及退出，不能只追供给数量；未证实路径则先补能区分解释的记录。

## 最小成果与停止
交付网络作用矩阵、价值指标证据、补谁或限谁的条件建议。已能说清在何局部网络谁影响谁即可完成；只因他人采用而跟风但使用价值不变，转查社会信息或阈值。角色构成、价格、容量改变时重新判定方向与强度。

## 工具箱接口
跟进顺序问题交阈值；扩大后是否自维持交临界质量；即时供需匹配受容量限制交瓶颈；成本下降但用户间无作用交规模经济类工具。招募建议、实际相关参与者变化和体验改善分别记录，不把注册数当效果。
