# TM-068 · 决策—结果分离

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
一次成败后要评价能力、追责或改流程，容易用结局倒推当初对错时用。过程合理不免除善后，结果不好也不能一概归运气。需要带日期的事前信息、选项目标、假设与承诺、执行日志和结果；记录缺失时问：“当时有哪些材料能显示你们知道什么、为什么这样选？”不允许事后补写“早已想到”。

## 转换动作
1. 暂时遮住结果，依当时可获得资料检查问题是否找对、备选是否可行、信息与推理是否可靠、权衡是否明确、资源是否承诺。记录不全时标无法还原，不能用现在知道的事苛求过去，也不能把填过表当合理证明。
2. 拿回结果，对照实际执行、环境变化和原已知风险。未落实资源与当初就不现实的安排分开；执行困难不能成为吸收所有失误的标签。列各解释的支持和反证，不凭空分配“运气占几成”。
3. 识别结果是否提供独特信息、是否连续出现相似偏离。原假设下罕见是重查信号，还须比较其他解释下是否更常见；重复失误不能永远叫偶然。分别决定保留或更新概率、因果假设、执行办法与决策规则。
4. 并行安排真实损失的控制、补救和责任处理。好过程与坏结果可并存，侥幸成功也不豁免不当程序；评价与善后互不替代。

## 最小成果与停止
交付事前质量评审、结果分解的证据与未知、四类更新及补救动作。每项修改能追溯新证据即完成；缺日志不能强判当时品质，先做有限复盘。后续同类模式、补充执行记录或环境信息出现时重评，不能从一例推终身能力。

## 工具箱接口
需调整概率时交贝叶斯，需估行动贡献时交反事实因果，需让未来承诺可执行时交停止规则。各工具收到的是具体缺口和证据；提出改法、团队采用与实际效果分别留痕。
