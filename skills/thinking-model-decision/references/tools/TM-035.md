# TM-035 · 让分散贡献通过交接和反馈进入下一轮行动

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
能人和消息都不少，贡献却在交接处丢失，问题每轮重来时用。一次简单、责任清楚的任务无需搭全员系统；连接更多不自动变聪明。输入共同结果、角色、一次真实问题流转、决策权限及反馈载体；关键追问：“上次有人提出这个问题后，下一位具体是谁，收到了什么？”

## 转换动作
1. 选一个反复问题，画发现、验证、排序、执行、结果回流的实际节点。先找无人接收或反复转手处，不先加人、加群或开会；共同目标也须核对，避免各自优化不同结果。
2. 为每个节点写输入、输出、接收者、时限和存放位置，并确认相应权限与资源。只有任务分工还只是流水线，输出必须能被下一节点直接使用。
3. 建立结果回流：原始坏消息保留、验证结果可追溯、改动有版本和理由、必要时可撤回。明确上一轮哪条结果改变了下一轮安排，只有汇报和存档不算形成反馈。
4. 小范围跑一个周期，同时检查交接是否真正完成、问题是否复发、来源是否独立多元。多名成员复制同一结论不是多份证据，信息更快流动也可能更快放大错误。

## 最小成果与停点
交付责任与反馈流转图、一条可复用问题记录和优先修补断点。关键贡献有接收人、结果能回到决策，即完成设计；运行改善需后续数据验证，不以消息数量验收。若仅增加流程成本而未修断点，应缩减结构；紧急专业任务仍保留适当纠错渠道。

## 工具箱接口
具体堵点交约束或流程工具，反馈放大与延迟交系统工具，节点任务交执行工具。参与者目标冲突时才先做协调，不把所有问题都归成信息不畅。
