# TM-096 · 反脆弱性

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
想通过小扰动发现问题、积累改善，或有人用“扛过去就会更强”劝人加压时调用。存活、恢复、分散风险和损失较小都不足以证明反脆弱。最小输入是受益对象、冲击、结果、累计代价和参照；先问：“和没有这次冲击本来可能达到的状态相比，哪项结果实际变好了？”

## 转换动作
1. 说清谁受益、谁承受损失，排除毁灭性下行和向无辜者转移代价。检查多次小损失、相关失败、时间与疲劳的累积；优先消除脆弱依赖，不为了验证理论主动伤害人。
2. 区分两条路径。结构路径须说明何种下行受限、上行开放的结构会因波动而改善平均结果，不能仅凭口号推定；备份和多样性通常先支持韧性。学习路径则需“发现问题—修复—复测”闭合，暴露缺陷本身不是成长。
3. 只有能提供有用信息且风险可承受时才安排有限扰动，明确累计上限、核心功能保护和停止责任。把准备、修复、沟通与复查计入成本，修复后用相近条件复测；原文生物、医疗或投资类比不能直接转成个人行动建议。
4. 与合理的无冲击参照比较，区分自然进步、恢复原样和额外改善。参照不足就限定结论；没有修复、反复暴露同一问题或代价越界时停止，不能把加大压力当作补救。

## 最小成果与停止
交付“受限损失与修复复测方案”：对象、暴露、损失归属、机制、参照、修复证据及停止线。明确能否受益和如何检验即可完成；仅证明恢复则改判为韧性，无法限制损失则停用主动扰动。条件、累计损失或受益对象变化后重判。

## 工具箱接口
保住最低功能交给韧性；额外改善的归因交给因果证据；小成本保留选择交给实物期权。试验建议、接受、实际执行、发现问题、修复和收益分开记录，不把完成演练写成已获得反脆弱性。
