# TM-033 · 把大家都知道转成有人接受并完成的任务

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与最小输入
多人知道问题却没人确认承接，“大家关注一下”反复出现时用。已有明确职责且正在执行的团队不必全员围上来；人数多不直接证明无人帮助。输入具体动作、紧迫程度、适任角色、授权与回执渠道；关键追问：“现在有没有人明确确认由自己处理这件事？”

## 转换动作
1. 写清问题与已知影响，分别标已有人处理、无人确认和情况不明。区分没注意、判断不急、以为别人负责及怕做错，不能看见没行动就归为冷漠。
2. 将笼统请求变成一项可完成任务，写对象、输出和时间，再匹配具备能力与权限的角色。请求发给某人只是分派建议，不等于对方接受；无权分派时向协调者提出明确需求。
3. 确认对方是否收到、愿否承接、资源够不够。不能承接就定备选、缩范围或升级协调，不继续向全群重复同一句话，也不把已读当开工。
4. 建立收到、开始、完成的状态回执，验收具体结果。紧急或危险场景选能力范围内的确认、求助等安全动作，不要求无训练者冒险介入或重复干扰专业处理。

## 最小成果与停点
交付任务—负责人—接受确认—截止—结果回执及无人承接的升级路径。责任已有人确认、完成口径明确，即完成分派诊断；真正完成须另见产物。若接受后仍做不到，改查资源、能力或依赖，不能继续用责任分散解释一切。

## 工具箱接口
明确任务可交排期与执行工具；反复交接丢失可交协作流转工具；无人敢提出问题才需表达安全视角。个体行动比例与群体至少一人行动是不同指标，结果记录须使用对应口径。
