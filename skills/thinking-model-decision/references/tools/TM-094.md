# TM-094 · 自组织

状态：v2运行文件；来源与试跑范围以tool-index.json为准。

## 触发与输入
成员按局部信息行动，逐渐形成无人逐项安排的分工、路径或秩序时调用。自组织不等于放任，也不保证最优和公平。最小输入是反复出现的秩序、成员信息、互动痕迹和负荷；先问：“哪些分工或行为会自己反复出现，大家当时依据什么信息行动？”

## 转换动作
1. 划定参与者、连接、时间和任务边界，追踪一个动作怎样直接影响他人，或通过留下的痕迹影响后来者。痕迹协调只是其中一种机制，不把所有自主行为都归为同一路径。
2. 比较共同刺激、上级逐项指令和单点原因能否解释秩序。中央设置目标与边界可以和自组织并存，但分散执行命令本身不是自组织；识别哪些反馈放大选择，哪些约束抑制失衡。
3. 检查旧信号和旧路径是否把系统锁住。可考虑信息更新、信号衰减或有限探索，说明探索代价和保留稳定服务的方式；选择一个有根据的规则、信息、反馈或边界改动，不以取消全部管理代替设计。
4. 比较不同负荷下的表现；适合试行时保持可回退，观察质量、等待和负担转移。无人认领的困难任务需要明确兜底；模拟有效不等于实际安全，准备、沟通和复查也纳入投入。

## 最小成果与停止
交付“秩序形成与局部规则方案”：当前生成机制、失衡位置、拟改规则、边界和恢复条件。能解释关键模式并明确一次可执行调整即完成。没有互动形成秩序的证据时停用；负荷变化、探索造成损害或规则被学习后重新判断。

## 工具箱接口
整体模式的生成解释交给涌现；参与者学习和策略变化交给复杂适应系统；分工责任及兜底权限交给委托代理；放大、抑制和延迟交给反馈工具。拟议规则、成员接受、实际运行以及秩序改善分别记录，不能用“自然形成”替代结果检查。
