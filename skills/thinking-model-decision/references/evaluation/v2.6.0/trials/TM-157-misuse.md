## 真实请求（原样）

请用 TM-157 检查我同事的用户预测，给我今天可以推进的动作；本次用 Markdown，不需要 HTML。平台最近两周各有200个活跃账号，两张活跃名单交集140人。最新注册总数600，这期间有新增和注销，我们还没冻结完整队列，也没核清两周都没出现的人。同事用140÷200=70%作留存，用60÷600=10%作回流，认为反正两周总数相同就说明同一批核心用户稳定，用这两个数一直推八周就可以。他还想把一次一周召回活动观察到的20%回流率用于此后每周，并断言是活动造成的；活动没有对照组，短期停用和长期停用人群的占比也变了。

我还收到一个单独的排班玩具例子想核查数学结论：固定100人，本周60人到场、40人不到场；从下一周起每个人都必定在“到场/不到场”两状态间切换，不存在新人或缺测。同事说它有50%的平稳比例，所以迟早每周都会是50人到场。

请判断哪些数字现在能算、哪些结论站不住，是否足以承诺主平台八周后的活跃人数，以及先补哪一份数据最有用。我们今天最多能花45分钟整理记录，暂不投入新的营销费用。不要替我编主平台缺失的概率，也不要用“多收集资料”四个字结束。

## 实际原答

**现在不足以承诺主平台八周后的活跃人数。** 今天最有用的工作，是把“第一周起始账号名册＋两周活跃记录＋新增、注销和缺测标记”合成一张逐账号对账表，先补全转移分母。45分钟内可以完成或明确卡在哪里，无须投入新的营销费用。

我用 TM-157 检查队列、转移分母、概率能否跨周沿用，再单独核算排班例子。两个例子的参数不能互相借用。

现有名单能确认这些数：

| 可计算项 | 结果 | 实际含义 |
| --- | ---: | --- |
| 两周都活跃的账号 | 140 | 两张名单的交集 |
| 只出现在前一周的账号 | 200－140＝60 | 下一周未出现在活跃名单，具体是未使用、注销还是记录缺失需核查 |
| 只出现在后一周的账号 | 200－140＝60 | 其中可能包含新增账号和老账号回流，尚不能全算回流 |
| 至少一周活跃的账号 | 200＋200－140＝260 | 两张活跃名单的并集，并非完整队列 |
| 前一周活跃账号在后一周再次出现的比例 | 140÷200＝70% | 该相邻周的观察比例；若身份匹配、活跃口径和记录覆盖可靠，可作为本次活跃延续率的描述 |

因此，70%的除法本身成立；问题在于把一次观察直接当作可沿用八周的转移率，并且把剩下30%全部解释成同一种“不活跃”状态。完整两状态模型还必须处理注销和缺测。两周总数相同，也只说明数量相同：已经看到60个账号离开活跃名单、另60个进入，不能说同一批核心用户一直稳定；140人也只是连续两周出现，不能据此认定长期核心用户。人员轮换本身同样不能证明平台必然恶化。

`60÷600＝10%` 虽然算术没错，**却不是这里的回流率**。回流率应为“同一队列中，前一周不活跃、后一周活跃的老账号数”，除以“该队列前一周不活跃的账号数”。目前分子60混有新增的可能，分母又用了最新全体注册数，时间与状态均不对齐。不能改用`600－200＝400`就补救，因为600不是已经对齐的前一周完整队列，两周都没出现者及账号进出尚未核清。

主平台现在不能填满可信的两状态转移表：活跃到活跃有140这个名单观察值；前一周活跃但下一周未出现的60人还要分清去向；不活跃到活跃的人数、出发时不活跃总数，以及两周都不活跃的人数仍待补。新增、注销、缺测必须另列，不能悄悄塞进四格表。即使取得这张表，它也只支持对应队列和期间的估计，并不会自动成为全平台八周预测。

同事关于召回活动还有两处跳跃：

- 一周观察到20%，不能当作其后每周的回流率。它最多描述当次、按当次定义和正确分母统计出的结果；活动结束后应使用新记录估计，不能把活动期的数字永久延长。
- 没有对照组，且短期、长期停用人群占比改变，不能断言20%由活动造成。即使两类人各自回流率都没变，混合比例变化也可能改变总体回流率；季节、自然回流及其他同期变化也可能解释结果。

这里要分开检查两件事：停用时长等历史是否会在“当前不活跃”之外继续提供预测信息，这是状态划分是否够用的问题；同一套概率在不同周、活动前后是否还能成立，这是概率能否跨期沿用的问题。不能用两周总数相同同时替代这两项检查，也不能在小样本下轻易宣称其中任一项已证实。

排班玩具例子则可以完整算清。按“到场、不到场”的顺序，转移矩阵为：

```text
P = [[0, 1],
     [1, 0]]
下一周到场人数 = 100－本周到场人数
```

| 周次 | 到场 | 不到场 |
| --- | ---: | ---: |
| 本周，第0周 | 60 | 40 |
| 第1周 | 40 | 60 |
| 第2周 | 60 | 40 |
| 第3周 | 40 | 60 |
| 第4周 | 60 | 40 |

之后偶数周60人、奇数周40人，一直交替。50%确实是平稳比例：如果初始正好50／50，再交换仍为50／50。但当前60／40不会趋近它。这条链周期为2，平稳分布存在不代表从任意起点逐周收敛。每连续两周的平均到场人数是50，也不等于每周最后都会有50人到场。这里是确定性玩具规则，因此60与40是按设定确定的计数，与主平台的概率期望预测不同。

今天建议由你或已获准访问记录的同事按下面顺序整理；分工是建议，尚未实际执行。总计45分钟，新增营销费用0元：

| 时间预算 | 动作 | 完成标志 |
| --- | --- | --- |
| 5分钟 | 明确两周起止时间、活跃定义、账号主键；确定以第一周开始时的在册账号冻结起始队列。 | 表头和队列纳入规则写清；沟通确认计入这5分钟。 |
| 15分钟 | 取得起始完整账号名册，关联两周活跃日志以及注册、注销记录；若没有历史名册，先查能否用账号时间戳重建。 | 每个起始账号有唯一一行，不仅包含曾经活跃者；新增账号另表列出。 |
| 15分钟 | 标记两周活跃状态、退出与缺测，核对140、60、60，区分后一周新增与老账号回流；有现成字段时附停用时长及活动触达标记。 | 四种去向能够计数；不能判断的格保留“未知”，并记录缺了哪张表或哪个字段。不要以缺日志一律代替不活跃。 |
| 5分钟 | 核对分母、队列人数及进出记录是否对账，查看短期／长期停用人数及回流计数，先不强行细分出小样本概率。 | 明确哪些转移率可以估，哪些仍不能估；注销作为退出单列，缺测单列。 |
| 5分钟 | 写出并保存当日交付：对账表、可算的描述指标、不能承诺八周人数的原因，以及下一项最具体的补数任务。 | 有一页可复查结果和一个明确缺口，复查与结论整理不留到预算外。 |

建议对账表至少保留：`账号ID、起始时是否在册、注册时间、注销时间、前周活跃、后周活跃、两周记录是否完整、停用时长（可得则填）、活动触达（可得则填）`。起始队列中注销者单列退出，新增单独统计；若继续分析开放平台，就需要把进入和退出过程纳入模型，不能仍把600人当固定总量。

如果今天已有整理耗时，应先从45分钟额度中扣除，压缩导出整理范围，保留最后的核对与结果记录。若历史名册无法在预算内恢复，当天就交付缺口清单，明确需要“第一周开始时完整在册账号快照或可重建它的注册／注销时间戳”，并记录应由哪个数据负责人协助；负责人未确定就标为待确认，不假装已经有人接手。

完成对账后，先判断能否形成一个完整、可比较队列的下一周期预测；活动周与非活动周分开记录，并按下一周实际结果校准。若退出、缺测或关键分母仍无法解释，继续暂停精确外推。八周人数只能在队列进出、状态定义和逐周概率假设明确后作为有条件情景呈现，不能升级为承诺。活动因果效果需要另行安排可比参照或合适的对照设计，这不属于今天新增投放的授权。
