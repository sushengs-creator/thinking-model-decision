## 修正

1. `docs/USAGE.md` 残留“一个主模型，最多三个补充”的旧限制。已改为按需要选择互补工具，并要求实际产物接续；来源摘录中的旧句保留，由框架适配规则明确覆盖。
2. `library-state.json` 的预览验证历史仍标 `valid_for_current_revision: true`。已改为 false；r62 的8工具试跑不能证明r63的142工具重构。
3. 当前维护示范仍使用已入库的TM-134。已改为未来TM-143结构示例，要求先有真实文稿，日期及来源必须替换为实际信息。
4. 本轮公共文件隐私静态检查原先未包含JSONL后缀。已补入，实际模拟记录按公共文件同样检查。
5. 独立实际回应评审指出TM-027 A将“报名”写成“购买”；运行文件原有区分正确。共同入口与运行协议补充报名、付费、参与、效果分层，保留初次回答并安排新执行者复测。
6. 同一评审指出TM-037 A将“原计划一场”写成“原来可承受的一场”。共同规则补充意向、可行性与资源可承受的区别，原始回应保留。
7. 完整入口HTML将D5复盘写成“本周内”，实际生成日期下D5已跨周。入口和报告规范补充预算周期、跨周条件与相对日期核对，安排新完整入口复测，不能只改加法或追加资源。

## 核对范围

- 入口对简单事实、翻译、暂停、纯倾诉、直接报告、后续更新与维护分路；一个主要问题后等待实际回答。
- 七类视角是覆盖检查，不是七模型套餐；来源中的主辅数量不覆盖当前编排。
- 对TM实际读运行文件和卡，对WW读正文；检索分数只表示词面召回，不表示置信度或适用性。
- 工具冲突须改变方案；整体时间与费用包含准备、沟通、复盘及已用成本；他人接受与实际结果不能由助手代写。
- HTML默认在形成建议时交付；单轮追问、暂停、维护回执与用户指定无文件例外成立。
- 原文/卡/运行文件指纹独立；新增登记默认预览，显式写入要求外部备份。脚本只保证备份在当前技能目录外，其余自动发现目录需维护者确认。
- 同步前对所有基线文件检查并发修改，保留私人评估文件和新增文件，先备份再写入、逐项读回。此项为脚本复核，执行成功另以同步回执为准。

未以本复核替代142工具逐项实际回应、独立评审、完整入口测试、最终ZIP核验或部署读回。
