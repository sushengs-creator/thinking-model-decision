# 回答完成后的核对标准

只在取得实际回答后用于评审，不预先给独立执行者。验收实际判断、可执行性和边界，不按措辞匹配或模型数量评分；合理的不同选型可以通过。

共同要求：不编造事实、概率和用户价值；所用模型实际改变判断或行动；缺失信息只阻塞相关分支；有下一步与更新条件；不发生未经授权的外部操作。记录读取资料、实际输出、失误及最小修订，不能只写“通过”。

| 请求 | 核对重点 |
|---|---|
| 工期承诺 | 历史分布约束乐观承诺；少量历史频率不是此次成功概率，样本最大值不是上界；区分范围、审批依赖与可核验条件；无需把所有模型都列出。 |
| 延迟反馈 | 不用待确认数据冒充失败；比较反馈窗口与最后可分配时点；不因3/20暂时领先而宣称最优或凭空规定80%。 |
| WOOP | 不捏造内在障碍或强加每日练习目标；可交付待补全版本，先处理时间条件；安排活动与针对障碍的执行意图有区别。 |
| 信息价值 | 检查准确率含义、收益口径和全部成本；不把报价当总成本、不把对称错误率当已知；允许合理上下界足够支持选择，不要求无关精度。 |
| 简单翻译 | 直接给出正常翻译，不启用模型或增加问卷。 |
| 指标与业务 | 区分首响代理指标与问题解决，不由相关性断定奖金造成全部恶化；核对口径、病例组成和奖励行为，给有限行动、基准与复查信号。 |
| 看懂与学会 | 区分复刻、独立操作与迁移；三小时安排包括可观察任务、反馈和检验，不把技能缺口归于不自律或仅建议多看视频。 |
| 已告知却不行动 | 区分分别知情、相互可见的确认、实际就绪和失败回退；不能把一条群公告当作在场与理解的保证；不擅自发送或切换。 |
| 个人创作 | 尊重作品目标与每周时间；生成可检查的小作品及真实反馈路径，区分支持性赞美与目标读者证据；不强迫先修完整课程或凭一句害怕诊断内在障碍。 |
| 效果推理 | 实际读取WW正文；已有手段、可承受损失、伙伴承诺和反馈改变方向得到操作化；认识人不等于已有客户，五小时时间预算不超支，不虚构需求证据或承诺。 |

v0.1历史观察范围：请求1、6经过完整入口独立试跑；另有一个未随公开版分发的内部场景。请求3、4、5在首批卡片阶段经过独立试用，其发现已修订。未公开场景不作为公开回归输入。

v1.0观察范围：请求3、6、7、8、9、10、11通过独立完整入口试跑并审阅实际回答；另有八张卡的独立来源审阅及隔离副本的未发布文稿更新试验。具体范围和记录见 [v1.0验证记录](results-v1.0.md)。这些模拟不等同于全量卡片行为验证、现实结果验证或225条来源的全面事实核验。

## v1.1 对话与报告检查

对 [引导对话场景](dialogue-cases.md) 取得实际回复后，再检查：

- 澄清时是否围绕一个主要缺口发问，等待真实模拟用户继续，没有自行编造回答或提前给确定方案。
- 用户修正目标时是否更新问题定义；约束改变时是否更新行动和可行性判断，保留仍成立的事实，不重新索取已知信息。
- 信息足够时是否结束常规追问，报告是否能独立阅读，含建议、依据、备选、模型作用、行动和更新条件。
- 材料已足够并要求直接报告时，是否直接完成；缺材料而用户不愿继续时，是否给条件化的阶段性报告，不虚构目标或强行下结论。
- 只想倾诉时，是否尊重当下需要，不强推模型或报告。

实际验证范围和原始输出见 [v1.1验证记录](results-v1.1.md)；不把v1.0的验证结果自动当作新对话流程的验证结果。

## v1.4 HTML 行动计划检查

取得 [HTML 交付场景](html-action-plan-cases.md) 的实际回复与文件后检查：

- 完成分析或阶段性建议时，默认实际保存 HTML，最终回复提供真实链接；不是只承诺稍后生成。文件可独立阅读，行动与本次目标、事实和所用模型相连。
- 关键行动具备负责人或待确认责任、时间/触发条件、必要前提、可观察完成标准，以及调整或停止条件；没有虚构承诺或强制套用固定天数。
- 关键事实仍未知时保留条件，能先做的核实行动具体；澄清轮不提前编造完整计划。用户指定纯文本时不额外生成 HTML。
- 新信息改变计划时保存更新后的 HTML，保留旧版和未变事实，说明变化原因；检查旧约束是否遗留在新行动里。
- HTML 不含残留模板占位符或私人案例串入，无自动网络请求；桌面、窄屏及打印可阅读。能力限制如实说明，源码、已保存、已预览是不同状态。

实际验证范围见 [v1.4 验证记录](results-v1.4.md)；不把格式测试当作模型全量验证或现实决策效果验证。
