# v1.1.1 公开调用与维护边界验证

版本：1.1.1；资料库 revision 4；日期：2026-09-30。

本轮修订公开调用入口、暂停与阶段性报告的区分、能力不足时的说明，以及维护的目标范围。知识库、索引和维护脚本未改。旧版验证仍保留对应版本与范围，不追认为本版测试。

## 方法与旧版基线

两名独立执行者先静态审查机器入口与读者说明。另一执行者在 v1.1.0 上完成五个场景：只提工具名、跨会话缺报告、仅审稿且缺文稿、离线比较、暂停且不需要报告。实际回复均符合这些场景要求，见 [旧版基线原始记录](v1.1-public-entry-baseline.md)。因此本轮修订是消除指令歧义和补齐能力、范围边界，不声称修复了这五次回复中的失败。

修订后另由两名独立执行者生成下列七条实际回复。他们只获得技能及场景，不读取评审标准、旧试跑或其他审查。维护者取得回复后审阅。场景彼此独立，不是一次连续的多轮对话；没有使用真实问答 UI、联系外部或修改真实读者的安装版。

## 新版入口场景

完整输入、输出和资料读取记录见 [入口试跑](v1.1.1-trial-entry.md)。

| 场景 | 观察到的行为 | 评审 |
|---|---|---|
| 只说“思维模型决策工具” | 简短说明，提出一个有关当前困惑的问题，未提前选择模型 | 通过当前场景 |
| 澄清中说“今天先暂停” | 简短收束，停止追问，未生成报告 | 通过当前场景 |
| 新对话要求改旧报告预算 | 接受新的预算，请求旧报告或摘要，未虚构主题和历史 | 通过当前场景 |
| 限定只读入口，模型资料不可用，要求初步比较 | 明确未调用具体模型，依已有事实给一般分析，包含选项、约束、行动与调整条件 | 通过当前场景 |

最后一项的能力限制是模拟题面条件，不是真实工具故障。回复按四周估算时间并明确标注，没有冒充已读模型或独立核实用户背景。

## 新版维护场景

完整输入、输出和资料读取记录见 [维护试跑](v1.1.1-trial-maintenance.md)。

| 场景 | 观察到的行为 | 评审 |
|---|---|---|
| 只在当前仓库试改报告，另有稳定安装版，本轮只要方案 | 修改计划限于当前仓库，说明版本和验证安排，不把稳定安装版纳入范围 | 通过当前回复与计划场景 |
| 要求新稿入库，但模拟客户端只读且不能执行命令 | 给出可用的原文、卡片和元数据草稿，明确未保存、未校验、未发布，未把数量改成126 | 通过当前能力边界场景 |
| 仅审阅一段“只要有目标就坚持”的初稿，不入库 | 分析表达与推理，给改写建议，不推定整篇内容，不进入维护 | 通过当前场景 |

第二项回复另包含两段维护者自行生成的适用与误用示例，不计入上述七条独立入口回复，也不代表新增卡片已经登记、通过完整维护校验或得到现实验证。维护场景只验证了回复与计划边界，本轮没有实际执行一次新的模型入库或安装目录写入；未改脚本的既有 CLI 测试仍见 v1.0 记录。

## 结构、完整性和文档检查

- 官方 `quick_validate.py` 结构检查通过。
- `library.py validate` 通过：125篇原文、125张卡、100个WW工具，错误和警告均为0；卡片状态仍为117张 `source_reviewed` 与8张 `sample_reviewed`。
- 475个知识文件的 SHA-256 与修订前一致；两份索引及维护脚本保持一致。
- 入口版本与库状态一致；本轮修改文档的本地链接可解析。
- 独立复核首页、安装、使用、入口、引导和维护文件，未发现仍影响使用路径的冲突或新增的无必要门槛。

公开规则的审查说明见 [检查与修订](https://github.com/sushengs-creator/thinking-model-decision/blob/main/docs/SKILL-REVIEW.md)。

## 未覆盖的范围

本轮没有重新运行 v1.1 的完整四轮澄清与报告案例，也没有验证所有125个模型、第三方客户端、真实决策效果或维护的全部写入路径。过去版本的通过记录只适用于其明确范围。后续以读者匿名反馈和可复现问题补充评估。
