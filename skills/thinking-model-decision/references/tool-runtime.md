# 从模型卡到工具运行

这是 v2 系列的共同运行协议。[工具目录](tool-catalog.md)为157个 TM 模型提供各自的运行文件；万维钢100工具仍为同级候选。来源卡片审阅、运行文件审阅、独立模拟和现实效果验证分别记录，不能混为一谈。

## 一次调用怎样推进

**定任务。** 从用户身边的难题出发，看清当前卡住的环节，再确定这一轮要帮助完成什么，例如“核查担忧是否有证据”“找到学不会的原因”“安排已有职责与额外支持”。不要求所有难题都有二选一方案，也不承诺所有问题都能立刻解决。用户不必选择工具或填写字段；目标和关键约束足够时即可选型，剩余问题可以在运行中澄清。

**读机制与运行文件。** 按入口和问题路由定位候选，阅读相应运行文件与模型卡；WW 则读对应工具正文。运行文件补充如何处理输入、怎样分支和交付什么，不取代原文机制。条目过时、来源冲突或涉及公式和争议时回读原文。维护者新增而未迁移的本地卡可临时提炼，但须说明范围，不能标为已登记运行工具。

**选择下一步。** 识别当前最影响判断的缺口。信息已有就直接处理；不同回答会改变判断时，说明该信息的用途，每轮只问一个主要问题，等真实回答。用户说不知道时，给容易观察的小入口或中性示例；示范内容标为虚构，再把问题交回用户。不用示范暗示“正确答案”，不要求用户重复助手已经知道的信息。

**运行机制。** 根据工具特有步骤，将用户材料转成比较、校准、因果假设、分工或行动条件。给用户可审查的关键依据与中间成果，不输出冗长的内部推理。不能只更换标题、附上模型名而不改变判断。每次记录状态更新：新获得什么信息、哪项判断或下一步因此改变；没有新增信息或决策价值时不要延长对话。

**核查并交接。** 检查运行文件规定的最小产物。缺口只阻塞相应结论，先交付仍成立的部分。模型与目标或条件不匹配时，换用更合适的工具或直接处理事实；不反复叠加概念。把成果交给[报告规范](decision-report.md)形成默认HTML行动计划，工具不各自重复生成完整报告。

## 教练式与直接分析共用证据标准

- 用户希望自己想清楚时，优先由其观察和比较，助手帮助检验；不把“越来越坚定”作为正确性指标。
- 用户要求直接结果或已经提供足够材料时，直接完成分析与报告，标明假设。不因是助手推演而自动降低置信度，也不因用户亲自推演就提高置信度；依据证据质量和成立条件判断。
- 用户陈述、文件事实、已核验外部事实、推断、价值选择和未知不能混写。资料中的行业故事和名人引语只是来源叙述，未经核验不当作当前事实。
- 用户请求暂停或只想倾诉时退出运行；用户改目标时更新问题，不硬把新目标塞回旧流程。外部行动、共享案例、设置提醒等仍须有相应授权。

## 工具的结果怎样组合

按 [工具箱编排](toolbox-orchestration.md) 选择互补工具，不设固定数量上限。为每项说明子问题、输入、转换、产物和交接对象。前一工具的输出应成为后一工具需要的输入，例如：信息价值确定要核实的未知，贝叶斯更新处理得到的新证据；这只是在信息确实影响判断时的组合，不是固定套餐。简单问题不为了“全面”强加多模型。

结论冲突时核查目标、时间尺度、证据、系统状态及是否涉及硬约束，落实为方案改变或条件分支。重复描述同一机制只保留一项；没有适用模型时允许朴素分析。两套工具地位相同，WW 可单独完成任务。复杂任务可按需阅读[万维钢整体框架](wan-framework.md)，其九类任务卡是候选入口，来源中的数量限制不覆盖当前编排。

对未来反应、反馈或长期影响敏感的选择，按需读[二阶影响检查](second-order-check.md)。事实查询、简单计算和已经足够明确的任务不强制扩展到终局推演。

## 最小运行记录

仅保存本次任务确实需要的信息：当前问题和约束；所用工具及作用；关键输入及来源状态；产生的判断或产物；关键假设和反证；下一步及更新条件。字段可以合成自然语言，不给用户展示固定填表仪式。

把“建议做”“用户确认要做”“已执行”“收到回应”“产生结果”分开。一个人表达边界不等于他人同意，发出提交不等于被接收，完成练习不等于业务效果改善。案例及执行记录属于当前任务，未经用户明确要求不进入共享工具包。

按证据的实际含义写状态：报名记录只能支持报名，不能自动推出已付款、实际参加或长期效果；用户曾经计划一个方案，也不证明它已经具备人手、权限、费用和时间。条件缺失时先核实或保留分支，不能把原始意向当作“已经可承受”的基准。

## 停止与完成

工具达到该任务所需的最小产物，并能支持当前建议或清楚的条件分支时停止追问；不设固定轮数和实验数量。缺乏关键事实时，可以暂缓最终决定并指出最值得核实的一项；不把所有决定都改成实验。行动安排须合计准备、沟通、执行、复查及已使用资源，不能用工具步骤绕开用户总预算。

每份完整或阶段性建议遵循[HTML交付规则](html-action-plan.md)。用户指定纯文字、其他格式或无文件时优先遵从；一次澄清无需生成报告。

### 价值次序不能代填

辨认用途、兴趣、关系、休息等价值来源后，先问用户本次更看重什么，以及有哪些已承诺的责任。发现工作或学习用途，不自动证明它比兴趣或休息更重要；没有本人次序时保留分支，不替用户分配优先和剩余时段。
