# 两套模型的对应与冲突处理

跨库关联保存在各卡的 `user-index.json → card_metadata.relations`，用 `library.py show TM-编号` 可按需读取；卡正文也保留来源和区别。关联来自对包内原文及对应 WW 条目机制的比较，未核验原课程讲稿。没有登记关联，表示本轮未建立对应，不表示两者绝无关系。

以下八组是调用方式的示例，不是全部映射。完整的人类可读索引见 [跨库关系目录](relation-catalog.md)。目录只用来找候选；实际调用读相关卡和 WW 条目，不需要每次加载全表。

“共用过程”不删除来源。表中只涉及名称和工作机制，不能推断两位作者表达、证据与适用范围完全相同。

## 冲突怎么裁决

1. 先查是否在回答不同问题：可行性、期望收益、损失底线、价值偏好不是同一维度。
2. 对齐期限与机会：同一次尝试在剩一轮和剩十轮时可能价值不同；一次性承诺不能直接套重复试验。
3. 对齐假设：环境是否稳定、反馈是否可比、信息是否相关、损失能否恢复。
4. 回到证据：来源冲突时列出冲突和不确定性，查询必要事实；新卡不是自动高于原文，原文也不是自动高于可靠的新证据。区分原文提炼与操作化限定，不把修正悄悄归给原作者。
5. 给出有条件的选择及切换信号，不用“各有道理”结束。若要持久修订模型关系，依更新流程保留修订原因。

不把共同的同义工具算成两个独立支持理由。反证工具的任务是主动寻找能推翻主判断的事实，而非再包装一次同方向结论。
