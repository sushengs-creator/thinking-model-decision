# TM-158 · 排队模型

版本：0.1｜源版本：1｜角色：拆开处理与等待，核查进件、服务能力和波动，在适用条件内比较减负、提速、降波动的方案。来源已提炼，试跑状态以索引为准。

## 适用问题与最少输入

明明平均能忙过来，待办却越积越多；人一直忙，客户还在等；想比较少收重复件、改善工具、调整排班或稳定处理时间，哪种办法更能缩短全程。最少需要任务和系统边界、观察时段、进件及完成记录、可用服务时间、服务台数量与分工、到达/开工/完成时刻、排队规则和目标。先问影响判断的一点：“拿最近一件事来看，从什么时候开始等、什么时候真正开工、什么时候办完？”用户已有这些信息时不重问。

三个时刻只能描述该件，不能证明长期规律。涉及暂停、交接、返工时另记各段，不能把开工到完成全算成服务时间。想算精确等待，还需要到达与服务时长的分布、独立性和稳定性依据；只有两个平均数时先给观察方案与条件情景。

## 原文机制【原文提炼】

处理时间不等于从需求出现到办完的总时间。有限服务能力与到达、处理时长的波动相遇，会产生等待；同样平均负荷，波动和排队安排不同，等待也可不同。空闲时段不能直接挪到未来吸收突发需求。在常用的稳定单服务台模型中，负荷越接近容量，平均等待对小幅变化越敏感；不能据此给所有岗位规定统一利用率。

三类改善分别改变实际进件量、有效服务能力、到达或服务时长波动。减少重复劳动不等于让需求排到入口外，改善等待感受不等于缩短实际时间。改善需要同时看全程、完成量、未完成任务的年龄、拒绝或退出、质量返工与成本。

## 从排队记录到选择【本轮操作化】

1. **把队伍画全。** 明确从哪里算需求出现、到哪里算完成；列入口外等待、内部队列、正在处理、暂停与重做。对相同时段记录期初未完、新进、完成、撤回/转出和期末未完，并核对 `期末 = 期初 + 新进 − 完成 − 其他退出`。转出只代表离开本环节，不自动代表需求解决。整个流程与单环节的边界分别标明。
2. **统一时钟与容量。** 到达率 λ 是同一边界、同一时间单位内的进件率；单台服务率 μ 是有活可做且服务台可用时的平均能力，平均服务时长为 `1/μ`。实际完成率受缺活、休假、中断等影响，不能直接等同 μ；名义每件12分钟也不说明每个日历小时可做5件。有休假/插单/批量处理时，即使折算了平均有效能力，也未自动恢复简单模型前提。多台还须区分共用队伍、独立队伍、技能限制与能否并行。
3. **先判定可以算什么。** 本工具的 M/M/1 定量分支要求：单台、独立同分布的指数到达间隔（齐次泊松到达）、独立同分布的指数服务时间，二者独立；先到先服务、有活即做、无中断或批量处理、无限等待容量与顾客源，参数在分析期可近似保持，且 `λ < μ`。这些是本工具采用的标准情景条件，不是所有排队方法的必要条件。短期从空队列启动、每天关门清空等瞬态情景不能直接当稳态平均。前提未知就标条件，不把“很随机”当指数分布证明；前提明显不符就改用逐件记录、合适的多台/休假/有限容量模型或事件模拟。
4. **在条件内计算，分开名称。** 单位统一后令 `ρ = λ/μ`。M/M/1 的平均排队等待 `Wq = ρ/((1−ρ)μ)`，平均总停留 `W = Wq + 1/μ`；系统平均在制数 `L = λW`，只等待的平均件数 `Lq = λWq`。`L` 含正在处理的任务，不能叫成纯等候队长；稳定状态下实际长期吞吐约为 λ，不能用 μ 替换 Little 关系里的流率。Little 关系须在同一边界、同一统计口径和可用的长期平均条件下使用，不是任意时点积压除到达率就能承诺等待。若只把服务改成固定时长，且其他 M/D/1 条件成立、λ和平均服务时长不变，`Wq = ρ/(2(1−ρ)μ)`，为对应 M/M/1 的一半；普通模板优化未必做到这一点。
5. **不稳定时转积压账。** 对这些无限容量稳态公式，`λ >= μ` 时停止报有限稳态平均，等号也不能套。用实际进出账确认积压变化、异常峰值及任务年龄；若给定持续到达大于能力，可报告长期增长压力，不能说每一瞬间都单调增。先处理可避免需求、产能、积压优先级及必要协商；拒收、弃队或有限容量会改变系统，不能凭队内稳定宣称服务成功。也不能把此条件泛化为所有模型：如规律到达且固定服务的其他安排应另行分析。
6. **用同一个终点比较。** 留现实基线，对每个措施说明改变 λ、μ、波动或排队结构中的哪一项，以及证据和持续期。加人改变服务台数量，不把两人的合计能力塞进单台公式；提速会同时影响服务和排队等待。比较全程时间/尾部超时、需求解决量、质量、外部等待、完整费用与人员时间；若任务种类或数量不同，先解释可比性，不拿“少办了”冒充效率提高。有明确目标和预算才排序，没有用户认可的时间价值不编净收益。投诉下降可单列体验改善，不能折算成省时。

## 最小成果、停止与下一步

交付一张边界与时段说明、一份进出守恒账或逐件时间分解、可用/不适用的模型分支、基线和方案的同口径比较、下一步与复查信号。前提不足时，最小成果就是能解释当前堵在哪里、还缺哪项记录、怎样在既有资源内补齐；不用假精确数字装满报告。

先取一件能定位等待的记录，需改流程再按可承受时段连续记录到达、开工、完成、暂停和返工；同时跟踪新增、完成、未完及可用工时。淡旺季和高峰需分开，一周记录只是线索。选择范围明确的改善后对照相近需求与任务结构，记录实际等待、超时、质量、完成量及入口外等待；前后变化不是自动因果证明。预定负责人或待协商角色、时间和总资源预算。足以支持当前决定即停止加复杂度；到达/服务分布、班次、队列规则、需求种类变化，或实际结果持续偏离时重估。

## 虚构演示【编辑推演，未实际执行】

一台持续可用的审核服务，在明确满足稳定 M/M/1 教学条件时，λ=4件/小时、μ=5件/小时：ρ=0.8，Wq=48分钟，W=60分钟，L=4件，Lq=3.2件。若真正消除重复件使λ降为3，其他前提保持，则Wq=18分钟、W=30分钟；若维持λ=4、μ=5而服务时长固定为12分钟，在M/D/1条件下Wq=24分钟、W=36分钟。这些是条件计算，不是两种现实措施已能做到的承诺。新增人手须按新的服务结构重算；若真实问题从入口前开始，入口外时间也应计入。
