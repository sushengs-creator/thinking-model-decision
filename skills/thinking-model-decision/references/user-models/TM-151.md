那天晚上，你问了五个为什么

孩子这次考试又没考好，你坐在他书桌对面，压着火，开始问。

为什么考这么差？因为没复习。

为什么没复习？因为作业太多，写到十一点，腾不出时间。

为什么作业写到十一点？因为写得慢，中间还玩手机。

为什么玩手机？因为管不住自己。

为什么管不住自己？因为不够自律。

问完了。你得到了一个结论：这孩子不够自律。接下来，还是那句「以后认真一点」。

可这五个答案里，哪些是你核对过的，哪些只是你的猜测？「管不住自己」和「不够自律」，又增加了多少信息？

如果没有看试卷，没有了解他写作业的过程，这串追问很可能只把原来的印象说得更完整。问题出在哪里，依然不知道。

5Why 最容易让人误会的地方就在这里：问得越来越深，看上去像在分析，实际上可能一直没有离开猜测。

五问问完，你手上多了什么

同样是考试没考好，我们换一种做法。

假设你先和孩子一起看试卷，发现最后两道大题空着。空着不等于不会做，也可能是来不及，所以还得问当时发生了什么。

孩子回忆，自己在前面一道难题上停了很久。你请他讲讲：卡住以后做了什么，为什么没有先跳过去？他说，自己以为试卷前面的题总比后面容易，前面都没做出，后面更不用看了。

现在，你有了一个具体的待检验解释：他把「按题号做」当成了「先易后难」，可能因此在一道题上耗掉太多时间。

接下来可以和他商量，在相近难度的限时练习中，遇到卡题先做标记、暂时跳过。记录在卡题上用了多久，后面的题完成得怎样。如果跳过后仍然不会做，就还要检查知识掌握情况。

了解了具体的答题过程，才知道接下来查什么、试什么。孩子的回忆是一条线索，还需要和试卷、练习表现相互核对。

追问之后，你应该更清楚哪些事已经知道，哪些还不确定，下一步怎样查。

5Why 到底是什么

5Why，也叫「五个为什么」，是一种通过连续追问、越过表面现象去追查问题原因的方法。

其中最容易被忽略的一点是，它真正的要求是每一步都要能回答「依据是什么」。问够五次这件事，本身没什么意义。

这套方法出自丰田。提出它的，是丰田汽车工业公司副社长、丰田生产方式的创始人大野耐一（Taiichi Ohno）。他在《丰田生产方式》里设想一台机器停止运行，追问过程可以概括为五步。

为什么机器停了？过载，保险丝熔断。
为什么过载？轴承润滑不足。
为什么润滑不足？润滑泵供油不足。
为什么供油不足？泵轴磨损、松动。
为什么泵轴磨损？没有滤网，金属碎屑进入了泵。

保险丝熔断解释了机器怎样停下来，但只换保险丝，并没有处理造成过载的条件。继续追问，才会把检查方向推进到润滑、泵轴和滤网。这就是它的作用：把上一层答案中尚未解释的部分，变成下一步要调查的问题。

我们把这个定义拆开来看。

问几次没有定数。上面那个例子凑巧是五步，实际要看问题，问到能查清为止，不必凑够五次。

每一层的答案都得找到依据撑着。依据可以来自已有记录、现场观察、当事人的叙述或进一步检查，不必每问一次就找一份新材料。推理可以帮你提出解释，证据才能帮助你判断解释是否站得住。

「根因」这个词很容易让人以为，最底下必定藏着一个最终答案。提出一个可能原因之后，还需要找依据。即使已经想到一个能做的改进，也不能反过来认定原因找对了。

反过来流程跑得通，原因就找对了吗？

精益企业研究院资深顾问约翰·舒克（John Shook）讲解这个方法时，建议用「因此」把原因链反向检查一遍。他也举过问三次、八次的例子，意思是次数不固定。

拿机器的例子来说，把流程从后往前跑一遍，就从滤网缺失、碎屑进入开始，看它们怎样造成泵轴磨损，再影响供油和润滑，最后导致过载、停机。每一环都问：前一步怎样造成了后一步？

这个动作能帮助发现漏掉的环节。但流程跑得通，只说明这条链前后自洽，还不能说明事情真是这样发生的。滤网是否缺失，碎屑是否进入，磨损是否影响供油，都需要检查。

回头看孩子的例子。「不够自律，因此玩手机」，听着顺，信息却很少。手机是拿来查题、聊天，还是玩游戏？用了多久？是否影响了作业进度？这些都不知道，就还不能解释这次考试。

反向检查时，不要只看流程顺不顺，还要问：在当时的条件下，这一步是怎样发生的？有什么依据？

某个因素也未必每次都会造成同样的结果。要判断它在这一次是否起了作用，不能仅凭一句「一定会」或「不一定」。

四份材料包漏装，到底该查什么？

下面用一个虚构的教学例子，把取证和追问放在一起。数量和记录都为演示而设。

社区办手工活动，你负责准备二十四份材料包。发放前逐袋检查，发现四份缺彩纸。

先把问题写具体：这次二十四份材料包中，有四份缺少清单要求的彩纸。然后把那四份单独放好，查它们在哪里、由谁、按什么要求装的。

假设核对分工记录、两张工作台的清单，并请装袋者讲述操作过程后，你得到这些信息：第一张工作台装了二十份，使用新版清单，材料齐全；临时加开的第二张工作台装了四份，用的是不含彩纸的旧版清单，装袋者说自己逐项照单准备。

这些信息支持把「第二张工作台沿用了旧清单」列为重点原因，比「大家太马虎」具体得多，也解释了为什么漏的是那四份。

继续问：为什么第二张工作台拿到的是旧清单？

查文件发送记录和打印件，再向负责准备的人核对，发现新版只发进了活动群，现场留下的旧打印件没有收回，第二张工作台直接拿来用了。

再问：为什么旧打印件没有收回？

假设任务安排中只分配了「群内发新文件」，没有指定谁负责更换现场纸单；相关人员讲述的过程也与此一致。这时，「更新要求没有落实到现场纸单」就有了具体依据。

注意，任务单没写某件事，并不能单独证明没人做过。这里还要与实际打印件、操作过程相互核对。如果说法对不上，就把分歧记下来，继续查。

眼下先补齐四份材料包，重新核对这一批。下一次准备前，活动负责人指定一人收回旧单、放好带版本日期的新单，装袋者开工时确认所用版本。

开工前，负责人检查每张工作台所用的版本；发放前，仍按新清单逐袋核对，并记录发现的缺项。此后几次活动继续观察：旧单是否还会混入，漏装是否再次发生。

追到「这个人不行」，还缺了什么？

如果第一步就停在「装袋的人太马虎」，旧清单可能根本不会进入讨论。

前 Etsy 技术运营负责人约翰·奥尔索（John Allspaw）在2014年的《无尽的「如何」》中批评过这种追问方式。它容易把讨论收窄到个人缺点，忽略人当时掌握的信息和工作条件。他主张多找几个人，各自讲讲当时在做什么、看到了什么，把事情怎么发生的拼出来。

他要的是换一种问法。给5Why多添几条分支，解决不了这个问题。

科学作家万维钢讲过一个词，叫基本归因谬误。说的是我们评价别人的行为时，容易高估他这个人的因素，低估他所处环境的因素。别人迟到，我们想的是这人不守时；自己迟到，我们想的是路上堵车。5Why 最容易掉进这个坑，因为往下追问的时候，人身上总有挖不完的东西，而环境里的东西得去看才知道。

回到材料包的例子，可以问装袋者：「你当时拿到哪张单子？怎么确认材料齐了？有没有人告诉你清单更新了？」

这些问题能帮助还原当时的过程。如果他拿到的确实是旧单，就要调查旧单为什么仍然可用；如果拿的是新单却漏了一项，也需要了解那一项是怎样被跳过的。

人的行为当然可以进入原因分析。问题在于，「没核对清单」是可以核查的行为，「责任心不强」则把许多不同的情况混在一起。

调查不必预先替谁开脱，也不该预先认定谁有问题。先把当时怎么做、为什么那样做弄清楚，才有依据讨论改进和责任。

5Why 这么流行，就一定管用吗？

方法流行，不能代替有效性证据。

医疗安全研究者艾伦·卡德（Alan J. Card）在2016年在线发表的《5Why的问题》中，针对医疗根因分析提出了严厉批评。其中一条容易被忽略的是，追到链条最远端，未必就是最该动手的地方。在他看来，原因可能就在前面某一环，改起来更省力，一味往下追，反而把人带离了干预成本最低的位置。他还提到另外两点，单一路径会遗漏因素，单一根因会缩窄改进范围。他主张在根因分析、尤其患者安全领域弃用这一工具，保留其教学价值。

不能把这项批评概括成「再问一条链就好了」。同样，大野的机器例子能说明追问思路，也不能凭这一例就证明5Why在各种问题上都有效。

结合这些限制，本文建议这样使用：处理过程可核对、后果较轻的日常问题时，用连续追问帮助确定接下来查什么。遇到多人、多环节相互影响的问题，特别是严重事故，要扩大调查，不能靠几层问答下结论。

无论问到哪一层，解释都要接受事实检验。把一句猜测填在链条末端，不会使它自动变成根因。

找到能改的地方，就可以停了吗？

在材料包例子里，查到没有人负责更换纸单，可以先采取措施。但继续问「这项职责为什么没有安排」，仍可能发现相关的分工问题，不能直接说已经换了话题。

暂时停止调查和已经解释完全部原因，是两回事。

对这个后果较轻、能够补救的例子，可以先修复查到的缺口，同时记下尚未查清的部分。活动负责人需要确认分工，下次准备时还要检查措施是否落实。

如果没有证据了，就写「尚未查清」；如果超出了自己的权限，就写清需要谁继续处理。不要把查不到或改不了的地方，自动当作分析的终点。

「沟通不畅」也许是一个大家都能接受的说法，再问下去却会让人难堪。但如果连漏了什么信息、影响了哪一步都没说清，调查就还没有完成。

停问的时候，目前有哪些依据，哪些问题还没回答，准备先做什么，什么时候回来检查，这四件事得说清楚。对于后果严重或原因仍有重大争议的事件，这些临时措施不能代替进一步调查。

同一次漏装，还能从别处查起

材料包漏装，可以沿着「为什么没放彩纸」追查旧清单；也可以问：「装完以后，有没有机会更早发现？」

后一个问题调查的是检查环节。它与漏装怎么发生有关，但不是同一个问题。

假如有人提出「那天人手少，所以省了核对」，先把它当作待核实解释。去看当时有没有安排核对、由谁做、是否真的省略，以及省略与人手之间有什么联系。单看人数少，不能直接推出检查一定被省掉。

也要留意已经做好的部分：这个例子是在发放前发现漏装的，说明最后的逐袋检查发挥了作用。改进时应保留它，再处理上游旧清单的问题。

不同分支可以给出不同的改进位置，不一定要汇合成一个「终极原因」。要选择哪项措施，取决于它针对的风险、依据、实施成本和可能带来的新问题。

原因较多时，可以先借助鱼骨图。它和5Why分工不同，鱼骨图负责把人员、材料、流程等可能因素铺开，列出方向；5Why负责挑其中一条有线索的分支往下查。铺开的这些都还只是待查的可能，画上去之后还要一条条验证。

多问几条链，可以减少遗漏，但没有「两条就够了」的保证。

下次追问，先记住这三句话

5Why 模型提醒我们一件事，追问的价值不在于问得多深。它在于每一层后面有没有一份能拿出来的东西。没有依据的那一层，只是猜。

所以下次追问，先记住三句话。

第一句：这一层的依据是什么？

先把问题写成能核对的事实，再区分观察、记录、回忆和推测。把流程从后往前跑一遍，检查有没有跳步；接不上的地方，写下还要查什么。也要留意哪些材料可能推翻自己的判断。

第二句：还有什么解释，这条链没有回答？

比较相近情况下出错和没出错的过程，看看究竟有哪些不同，听听其他参与者讲当时各自在做什么。不要为了把链条写整齐，删掉与当前解释不一致的信息。

第三句：先改什么，改完看什么？

写清谁来做、何时检查，以及还有哪些问题没查完。既看措施有没有执行，也看问题是否减少。一次没再出错，不能证明原因已经找全；若仍然反复，就带着新记录回到原来的判断。

回到孩子那次考试，第一步可以很小：先一起看那张试卷，听他讲当时卡在哪里。

问了五个为什么还没找到原因，也许是因为每个答案都只是顺口接上的。下一步不一定是第六问，也可能是去核对一件一直没有看清的事。

模型档案卡

| 模型名称 | 5Why分析法（五个为什么）。 |
| --- | --- |
| 一句话定义 | 通过连续追问，越过表面现象、追查问题原因的方法；追问次数不固定，答案需要证据支持。 |
| 来源与代表著作 | 与丰田生产方式密切相关。大野耐一在《丰田生产方式》中用机器停转的例子说明这套方法。精益企业研究院的约翰·舒克在讲解中补充了反向检查的「因此链」。 |
| 核心动作 | 从具体问题出发，沿可能原因继续追问，逐层核对依据。反向检查可以帮助发现跳步，不能单独证明因果。 |
| 解决什么问题 | 分析停在表面症状，或停在「某个人不行」的笼统判断，无法形成具体调查与改进方向。 |
| 调用提醒 | 这一层有什么依据？还有哪些解释？先改什么，改完怎样检查？ |
| 边界 | 「能改」不等于原因正确，问得深不等于措施更有效，多条链也不保证找全原因。复杂问题需要更多视角、证据和系统调查；不能用5Why单独得出心理诊断或问责结论。 |
