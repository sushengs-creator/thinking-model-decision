人都配上了，为什么还想私下换？

设想社区办了一场羽毛球结对活动，一个老手带一个新手。三名新手甲、乙、丙，要与三名老手A、B、C组成三队。

组织者让新手按报名顺序挑搭档，选定就不能改。乙先到，选了A；甲随后赶来，也想选A，但位置已经满了，只能选B；丙最后到，与C组队。

名单很整齐：甲—B、乙—A、丙—C，谁也没落单。

但甲更想跟A打，A也更愿意带甲。两人只要私下商量，就有了另组一队的理由。至于原来的搭档乙和B愿不愿意，是另一回事。

人都配上了，却仍有两个人更愿意选彼此。

这就是稳定匹配模型要检查的问题。

上面是一个教学假设。先约定：六个人都愿意参加，每人只能有一个搭档；每人的偏好顺序是固定的，不会中途变；新手都能接受三位老手，老手也都能接受三位新手，只是各有不同的选择顺序。后面的比较始终使用同一套偏好。

有人不满意，就算安排不稳定吗？

甲想换搭档，还不够。如果A更喜欢现在的乙，甲再想也无法与A另组一队。

稳定匹配，是在现有配对都可接受的前提下、不存在阻碍对的配对安排。阻碍对（blocking pair）指这样一对人：两人分属配对的两侧，目前没有配在一起；相较于各自现在的搭档，两人都更想选对方。

其中最容易被忽略的一点是，它检查的不是谁不满意，是有没有两个人同时想换。

我们把这个定义拆开来看。

第一层，它看的是“一对人”，不是“一个人”。不是问甲对B满不满意，是问甲和A这一对，愿不愿意改成彼此。

第二层，这一对必须两边都点头。A如果更喜欢现在的乙，甲再想也组不了队，这就不算阻碍对。

第三层，只要有一对成立，整份安排就不满足稳定性。不问有几对，也不问有多想，其他人都很满意也不影响这个判断。

这里的“稳定”，含义很窄。它不要求人人都拿到第一志愿，也不要求所有人都满意。它检查的是：有没有一对人，可以通过选择彼此，让两人各自得到更喜欢的结果。

因此，有人不满意，安排仍可能稳定。反过来，大家嘴上都没意见，也不能证明稳定：或许有两个人更想选择彼此，只是还不知道对方也这样想。

有阻碍对，也不意味着现实安排马上就会散。两人可能不知道彼此的想法，也可能受合同、退出成本或组织规定约束。模型指出的是改配的意愿，不能代替对实际行为的判断。

早来二十分钟，为什么就把搭配定死了？

把六个人的偏好写出来，问题就清楚了。下表从左到右，表示从最想选到最不想选，没有并列。

| 新手 | 希望选择的老手 |
| --- | --- |
| 甲 | A → B → C |
| 乙 | A → C → B |
| 丙 | B → A → C |

| 老手 | 希望选择的新手 |
| --- | --- |
| A | 丙 → 甲 → 乙 |
| B | 甲 → 丙 → 乙 |
| C | 乙 → 甲 → 丙 |

回头看先到先得的结果：甲—B、乙—A、丙—C。

甲把A排在B前面；A把甲排在乙前面。甲与A就是一个阻碍对。

其实还有一对。丙把A排在第二位，C排在第三位；A把丙排在第一。两人现在分别配着C和乙，也都更想选对方。丙与A同样是阻碍对。

找到一对就足以说明这份安排不稳定，这里有两对。先到先得留下的问题，不止一处。

乙比甲早到二十分钟，便把A的名额锁住了。甲到来后，即使甲和A都更愿意选彼此，也无法重新比较。

问题出在过早锁定：到达顺序决定了谁先占住位置，而且定了就不能改，双方原本的偏好没有得到充分考虑。

先到先得当然有用。取号办事、购买同一种商品时，按顺序来容易执行，也能减少争议。但一名老手带谁、一名新手跟谁，都有自己的想法。这时，只按到达顺序定下搭档，就可能留下阻碍对。

这里还有一个容易忽略的代价：如果让甲改跟A，乙可能会失去自己最喜欢的搭档。不能因为甲和A更高兴，就说所有人都变好了。

稳定匹配要处理的是双方选择之间的冲突，它不承诺让每个人都得偿所愿。

先暂定，再确认，怎样让双方有机会比较？

现在换一个规则。组织者提前收齐名单和偏好，约定统一确认的时间。在计算结束前，所有配对都只暂定。

先让新手提出申请：每人从最喜欢的老手开始；老手从目前收到的申请里暂定最喜欢的一位，拒绝其余人；被拒绝的新手继续找下一位。

这个程序叫延迟接受算法。延迟的是最终确认，过程中依然要及时比较和拒绝。

按刚才的偏好表跑一次：

第一轮，甲、乙都向A申请，丙向B申请。A更喜欢甲，于是暂定甲、拒绝乙；B暂定丙。

第二轮，乙向自己的第二志愿C申请，C暂定乙。三名新手都有了暂定搭档，流程结束。

最终得到：甲—A、乙—C、丙—B。

如果换成先看乙的申请、再看甲的，A起初会暂定乙。但甲的申请一到，A仍会换成自己更喜欢的甲，乙再继续申请C。先被暂定的人，仍要和后来的申请者一起比较，这正是“暂定”与“录取”的区别。

这套程序为什么能得到稳定结果？假设结束后，一名新手仍更想跟另一位老手搭档。因为他按偏好从前往后申请，一定先找过那位老手，被拒绝之后，才退到现在的选择。

那位老手拒绝他时，已经有了更喜欢的人。以后即使换人，也只会换成自己更喜欢的。因此，到了最后，这位老手不会更想选回这名新手，两人就不能构成阻碍对。

这段推理对其他人也一样。

在这个标准的一对一模型中，只要参与者固定、偏好明确且不临时改变，也没有并列，按规定把流程跑完，先处理谁的申请不会改变结果。统一收集信息有助于实际组织，但算法不要求所有申请在同一秒发生。

如果有人只愿意接受部分搭档，就只申请这些人。直到每个申请者要么已有暂定搭档，要么已经被所有可接受的对象拒绝，流程才结束。后一种情况下，有人会落单。

这也不是鼓励现实中无限拖延、随意反悔。暂定期间和确认时间需要事先说清楚；已经正式生效的承诺，不能拿“算法还在比较”作借口推翻。

都是稳定结果，为什么换一方申请就不一样？

仍用同一张偏好表，这次让老手提出申请。

A最想带丙，B最想带甲，C最想带乙。三人的第一选择正好不同，一轮就得到：甲—B、乙—C、丙—A。

这也是稳定结果。因为每位老手都得到了第一选择，没有哪位老手还愿意改选别人，自然也不会出现双方都想另配的阻碍对。

两种结果并排看：

| 谁提出申请 | 甲的结果 | 乙的结果 | 丙的结果 |
| --- | --- | --- | --- |
| 新手提出申请 | A，第一志愿 | C，第二志愿 | B，第一志愿 |
| 老手提出申请 | B，第二志愿 | C，第二志愿 | A，第二志愿 |

乙的结果没变，甲和丙却在新手提出申请时得到更喜欢的搭档。

这体现了延迟接受算法的一项性质：在一对一、固定且无并列偏好的条件下，提出申请的一方，每个人得到的都是自己在所有稳定结果中能够得到的最好选择。

“所有稳定结果中”不能省略。乙最喜欢A，最后却得到C。为什么乙和A配不成？因为A的排序里，丙和甲都在乙前面。一旦让乙占了A，A就会想换成丙或甲，这样安排本身就不稳定了。所以乙—A这个组合，在任何稳定结果里都不会出现。

“提出申请”也有特定含义：它是算法里负责依次发出申请的那一侧，不是现实中谁先发消息、谁先表白。更不能据此推论，主动的人在任何关系里都占便宜。

两套结果都稳定，究竟更照顾哪一侧，需要组织者事先选择，并向参与者说明。数学能告诉你规则会产生什么结果，不能独自替你决定哪一种结果更值得追求。

招聘和择校，为什么也会被过早承诺卡住？

美国住院医师匹配市场曾遇到过类似问题。医院为了抢到学生，不断提前发出录用邀请；学生还没充分了解其他机会，就要决定是否接受。即使后来尝试统一接受时间，极短的回复期限仍让双方难以从容比较。

1952年，美国开始用集中匹配来确定实习安排。医院和学生提交各自的排序，由统一机制协调结果。1997年，NRMP董事会决定采用新设计的申请人提出申请算法，并从1998年开始使用。实际系统还要处理夫妻联合申请等复杂情况，不能把课堂上的简化结论原封不动套进去。

纽约的高中择校，则遇到了录取协调不充分的问题。旧流程里，有学生同时收到多份录取，也有大量学生最终被安排到没有填报的学校。

2003—2004学年，新设计的匹配机制开始运行，用于2004年秋季入学。据参与设计者后来的回顾，首年被安排到未填报学校的学生约为3000人，而前一年约为3万人。这里比较的是“被分到未填报学校的人数”，不是所有学生的满意度，也不能把全部变化归功于某一条算法规则。

波士顿的问题更贴近“过早锁定”。旧规则先处理第一志愿，并把录取立即确定下来。没拿到第一志愿的学生，再去竞争第二志愿的剩余位置；即使他在第二志愿学校的优先顺序更高，也不能替换已经录取的人。

家长因此要盘算：第一志愿究竟该填最想去的，还是更有把握的？2005年，波士顿决定改用延迟接受机制，减少这种策略性填报的负担。

这里的学校排序，往往来自学区、兄弟姐妹在读等优先规则，不等于学校像一个人那样“更喜欢谁”。算法可以按优先规则运行，但规则是否合理，仍需另外讨论。

日本也在2003年引入住院医师集中匹配，最初采用医生提出申请的延迟接受算法。这个例子说明，类似程序可以用于不同制度环境；实际落地仍需处理当地的名额和政策约束。

这些改革各有背景，共同值得借鉴的一点是：让双方有机会在确定结果前比较选择，减少过早承诺造成的错配。集中处理也不意味着要把每个人的偏好向其他参与者公开。

从七页论文到真实制度，中间补上了什么？

1962年，数学家戴维·盖尔和劳埃德·沙普利在《美国数学月刊》发表《大学招生与婚姻的稳定性》。论文共七页，给出了寻找稳定匹配的延迟接受程序，并证明了相关性质。

要注意先后顺序：美国1952年的集中匹配实践，比这篇论文发表还早十年。后来，经济学家阿尔文·罗斯研究这段历史，分析稳定性如何帮助解释匹配机制的运作，并与合作者参与实际制度的设计和改进。

2012年，罗斯和沙普利共同获得诺贝尔经济学奖，获奖理由是稳定配置理论与市场设计实践。

理论回答的是，在明确条件下，怎样找到没有阻碍对的安排。现实制度还要回答：参与者愿不愿意加入，能不能理解填报方式，哪些承诺必须遵守，哪些特殊情况需要另外处理。

稳定性提供了一项重要检查，但制度能否运作，还取决于这些具体条件。

没有阻碍对，为什么仍不等于公平？

回到球场。新手提出申请和老手提出申请，都能得到稳定结果，但甲和丙的处境不一样：新手提出申请时，甲拿到第一志愿A；老手提出申请时，甲掉到第二志愿B。

稳定性只检查有没有双方都愿意改配的组合。应该更照顾新手还是老手，参与资格和排序是否合理，都不能靠“结果稳定”来回答。

如果接收方的排序本身偏向某些人，算法可以严格照表执行，并得到相对于这张表稳定的结果。但它不会因此证明这张表公正。审查排序依据，是组织者仍然要承担的工作。

稳定也不保证人人有位置。换一个场景：四名新手，三名老手，至少一人会落单。如果没有老手愿意用这名落单者替换自己的搭档，这份安排仍可能稳定。此时比较的对象，是“跟某人搭档”和“没有搭档”。

更不能把所有分配问题都当作本文的一对一配对。一个人要上多门课、几个人必须一起进同一团队、员工交换多个班次、器官交换涉及多人接续，都可能需要不同的模型和约束。

即使一个机构可以接收多人，也要检查它是否能按固定排序逐个选人。如果它看重的是某几个人必须共同到位，基本算法的保证就不能直接照搬。

下次做配对，先把哪几件事问清楚？

假如你要组织导师结对，可以从四步开始。

先确认两边在选什么。每名学员是否只跟一位导师？导师带几人？哪些组合不可接受？如果选择会受团队搭配、时间冲突等因素影响，先把这些限制写出来。

再收集排序，查找阻碍对。拿出暂定名单，问一名学员：在可接受的导师里，你是否更想跟当前搭档之外的某位？再核对那位导师是否也更愿意接收他。一方想换还不够。若导师有多个名额，且能按固定排序逐个选人，还要看是否有空位，或愿不愿意替换当前某位学员。

若准备使用延迟接受，先公开程序。约定谁提出申请、怎样处理并列、暂定结果什么时候确认。不要把第一轮暂定当成最终承诺，也不要只修眼前一对就宣布全局稳定：一次改配可能影响其他组合。

最后单独检查公平与遗漏。谁落单了？谁在现有规则下始终排在后面？排序依据是否合理？需要补名额、改资格，还是调整优先规则？这些问题要另作判断。

在球场例子里，甲—B、乙—A、丙—C看上去已经安排完毕。真正把甲和A的想法放到一起，才看见名单留下的冲突。改用暂定后确认的程序，可以消除这类阻碍对；选择哪一侧提出申请，则会影响谁得到更喜欢的结果。

稳定匹配模型提醒我们一件事：一份名单排得整整齐齐、没人当场反对，并不说明它排好了。要判断的是有没有两个人私下都更愿意换成彼此，以及这套排序和程序本身偏向谁。

所以，拿到一张配对表时，先查有没有未配在一起、却都更愿意选择对方的人。查完以后，仍要追问：这套排序和程序，对参与者公平吗？

模型档案卡

一句话定义

稳定匹配，是双方都能接受、且不存在阻碍对的配对安排。阻碍对是尚未配在一起、却都更愿意选择对方的一对。

来源

戴维·盖尔、劳埃德·沙普利1962年的《大学招生与婚姻的稳定性》提出延迟接受程序；阿尔文·罗斯把它接到市场设计上。两人共获2012年诺贝尔经济学奖。

解决什么问题

双方都有选择、名额有限时，查一份安排有没有留下互相更愿意改配的组合。

核心机制

申请方按偏好依次申请，接收方暂定最合意的人选、拒绝其余，被拒者继续。所有人都有了着落或已被全部拒绝，才确认结果。

调用口诀

先查双方是否都想改配，再查排序和程序是否公平。

适用

导师结对，以及符合条件的招聘、内部转岗、住院医师匹配、学校分配。

边界

保证建立在一对一、固定且无并列偏好等条件上。稳定不保证满意、不保证人人有位置、不保证公平或总收益最高。落单者与“不配对”比较，所以有人落单仍可能稳定。排班、课程组合、器官交换不能直接套用。
