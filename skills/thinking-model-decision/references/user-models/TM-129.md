# **思维模型129：交互记忆系统——一个人离职，为什么像带走了整个团队的记忆？**

我们设想一个离职交接场景。

老张在公司待了三年，参与过不少大促活动。离职时，他写了十几页交接文档，新同事接手后，还是经常卡住。活动上线前一天，渠道突然要求改素材。新同事翻遍文档，也查不到这个渠道审核素材通常需要多长时间，只能干着急。

文档写着“活动前要跟渠道确认排期”，却漏了老张在合作中摸出的经验。这个渠道通常周五下午才集中回消息，最好周四就把初版发过去。

这类经验可以记录，也需要更新。如果它只在老张脑子里，离职时没留下，团队就损失了一部分知识。

还有一种情况。负责渠道的同事清楚最新排期，接手者却不知道可以问他，仍在翻老张留下的旧说明。信息还在团队里，只是需要它的人没找到。

所以，交接时除了补齐文档，还得弄清谁掌握哪些知识，以及接手者怎样找到这些人、用上他们的经验。

交互记忆系统研究的，就包括这样的协作问题。

## 一群人各记一部分，怎样才能一起用得上？

社会心理学家丹尼尔·韦格纳（Daniel Wegner，哈佛大学）与合作者于1985年提出这一概念，韦格纳在1987年作了系统论述。

**交互记忆系统由成员各自的记忆，以及使这些记忆能够共同发挥作用的交流过程构成。**放到团队中，就是成员分别掌握不同知识，并通过交流决定新信息交给谁、由谁保存，需要时怎样取用，再把各人的信息结合起来。

其中最容易被忽略的一点是：**知道一个专家的名字，离拿到可用的答案还有几步。你得联系上他，核对答案是否适用于眼前的问题，再看看能否与其他信息对上。**

我们把这个定义拆开来看，有三层意思。

第一层是“各自掌握”。一个活动团队里，有人熟悉资格规则，有人会查任务数据，积分发放程序则由另一位同事负责。每个人各有专长，遇到自己不熟悉的问题，知道该向谁求助。

第二层是“交流过程”。新信息要有人接收和保存，相关同事也要及时知道变化。假如资格规则更新了，规则负责人就得把与数据、程序有关的改动告诉相应同事，并更新记录。否则，下次查积分异常，几个人可能还在按不同版本解释同一件事。

第三层是“共同发挥作用”。知识得能用到具体任务里。“谁懂什么”可以画成一张知识地图，但它只能说明知识在哪里。文档还可以保存规则和案例，留下查找路径，帮助新同事少走弯路。发现例外后，需要有人补充记录；规则变了，也要通知会用到它的人。

这些分工可以在长期合作中逐渐形成，也可以通过明确协商建立。任务变了、人换了，就得重新检查原来的安排是否还合适。

## 问题没解决，究竟卡在了哪一环？

来看一个假设场景。用户完成活动任务后，没有收到积分。

团队里，有人管规则，有人查任务数据，还有同事负责发放程序和门店对接。解决问题需要的信息分散在他们手里。

根据交互记忆系统的思路，我们可以用四个问题来检查这次协作。

**找对人了吗？拿得到信息吗？答案可靠吗？信息对得上吗？**

这是本文整理的工作检查方法。四问听起来相近，查的却是不同问题。

**第一种，找错人了。**

负责人以为数据同事能查所有任务，便一直催他。可他只负责线上任务，这位用户参加的是门店任务，完成记录需要找门店同事确认。

催得再急，也得先弄清对方能查什么。问“谁懂数据”还不够，最好说清具体任务，再问这类记录由谁维护、最近谁实际处理过。大家都把某位同事当专家，只能说明看法一致，还要核实他是否熟悉眼前这类问题。

**第二种，找对了，但取不到信息。**

大家知道程序同事熟悉积分发放，可他正在休假，暂时联系不上。团队没确定谁能代为处理，其他人也不知道记录存在哪里。

这时要找能接手的人，或者寻找可用的处理记录。如果查询需要权限，还得确认谁有权限。找到替代来源后，也要问清它能回答哪些问题。有人愿意帮忙，总是好事，但还得确认他掌握哪些信息。

**第三种，专家回答了，但答案不适用。**

程序同事记得，用户完成任务后就会收到积分。但那是旧版流程，现在已经改成次日统一核验。他回答得很肯定，大家也一直信任他，这次却需要先核对规则版本。

这一问检查的是答案本身还能不能用。对方依据什么作判断，所依据的规则现在是否有效，这次的情况又是否符合适用条件，都需要问清。

尊重同事的经验，也可以核对他这次判断的依据。过去答对过，能给我们一些信任他的理由；条件变了，仍要重新确认。同样，一次答错也不必急着给人贴标签。先看材料是否齐全，再查有没有版本变化，或者问题是否超出了他的专长。

**第四种，每个人说得都对，合起来却错了。**

规则负责人解释的是本次活动的资格条件，另一位同事查的却是上次活动中同名任务的记录。两份信息各自正确，放在一起就对不上了。

这一问检查不同来源的信息是否在说同一件事。用户和任务编号先对齐，时间段、规则版本也要核对。第三问查一条答案是否适用，第四问查几条答案能不能放在一起用。

四类问题可能同时出现。检查到哪一步卡住，就先补哪一处。

## 各自都会做，为什么还要一起练？

看过这四种情况，就容易理解共同练习的用处。各人会做自己的事，还得试一试，几个人一起做时能否顺利配合。

1995年，Liang、Moreland（匹兹堡大学）和Argote（卡内基梅隆大学）让参与者学习装配晶体管收音机。一部分人一起训练，另一部分人各自训练。一周后，他们以三人小组共同回忆装配程序，再实际装配。共同训练的人仍与原来的同伴组队，各自训练的人这时才组成小组。

一起训练过的小组回忆的程序更多，装配质量也更好。研究者观看任务录像，评估成员的专长分工、对彼此知识的信任，以及实际配合情况。分析结果支持交互记忆系统在其中发挥作用。

个人知识仍然重要。共同练习可能帮助成员进一步了解彼此掌握了什么，学会在任务中使用对方的知识。

不过，熟悉的配合方式遇到新安排，也可能出问题。

韦格纳与合作者在1991年的实验中，让参与者与自己的恋爱伴侣或陌生人配对。研究设置了指定记忆领域和不指定的条件。两人一起看材料，学习时不交流，随后分别回忆。研究者把两人正确回忆的项目合并去重，计算配对表现。

没有指定分工时，原伴侣配对比临时配对表现更好。在指定分工的条件下，两类配对的比较结果反了过来，临时配对表现更好。这里的指定领域，并没有按每对参与者的实际专长作优化安排。

这个结果提示，外部安排可能干扰已有的记忆协作方式。至于怎样给新团队分工更有效，这项实验没有给出明确答案。

放到团队工作中，除了确认各人会做什么，还可以一起处理一次任务，看看信息能否顺利传递。分工调整后，也要留出机会重新熟悉彼此的做法。

## 人换了，知识分工为什么还停在过去？

人员变动会让原来的配合方式面临考验。

Lewis（佛罗里达州立大学）等人在2007年的实验研究中发现，部分成员更换后，小组可能继续依赖原有的知识分工，知识交流因此变得低效，影响任务表现。补充实验还发现，让老成员在任务开始前重新审视原有分工，有助于改善知识交流和团队表现。

这给交接提供了一个具体的检查方向。新人擅长什么、还缺哪些经验，要重新了解。原成员也得确认，过去由离职同事保管的信息，现在归谁负责。岗位表里的姓名换好了，这些事未必已经安排妥当。

甚至在换人发生之前，分工也可能受到影响。Blanchet和Michinov（法国南布列塔尼大学）在2017年做过一项学生短时组装实验。有些小组事先得知，一名成员将被替换。在人还没有换掉时，这些小组在训练中形成的专长分工就已经较弱。这个结果提示，成员变化的预期可能影响当前协作。

工作中，如果已经确定有人要离开，可以提前盘点他负责的知识，确认谁准备接手。接手者暂时还处理不了的部分，也要安排人补位。这样有助于及时发现尚未有人接手的事项。

分工之外，大家仍需要理解共同目标。活动的任务编号、规则版本等基本信息，也要事先对齐。否则，找到专家之后，双方还可能花很长时间才弄清楚对方在说什么。

## 下一次求助，先说清哪些信息？

回到积分异常。准备在群里问“积分怎么又没到账”时，可以先把问题写具体。

先说明用户参加了哪个活动、完成了哪个任务，再补上完成时间，以及当前规则约定的到账时间。已经查过哪些记录，也一并告诉对方，省得几个人来回重复查询。

沿用前面的假设，这个用户参加的是门店任务。你先找到掌握记录的门店同事，查看门店是否已确认任务完成。如果他不能及时查询，就找有权限的备份人员或其他可用记录。

接着，请规则负责人核对资格条件，请程序同事说明当前发放流程，再按同一任务编号把查到的信息对齐。

假设核查后发现，当前规则要求任务完成后次日上午核验，通过后当日发放。这个用户今天才完成任务，门店已确认，资格也符合。目前还是当天，后台显示等待核验。

眼下能判断的是尚未超过约定处理时间，后续是否正常发放，还得继续看。负责跟进的同事需要记下两个检查时间。到了核验期限仍未完成，就查核验进度；已经核验通过，超过发放期限还没到账，就查发放记录和异常原因。

这次新确认的内容也要留下来。比如，门店任务的确认记录在门店系统里，下次遇到同类问题，可以先到那里查。又比如，发放流程已经改为次日核验，活动说明也要跟着更新。

这些记录可以交给实际负责的同事确认。规则负责人维护活动说明，涉及程序的内容请程序负责人核对。门店同事补上记录的查找位置，以及谁可以代为查询。更新之后，要同步给以后会接手这类问题的同事。

其他需要多人知识协作的任务，也可以用四问来检查。如果信息已经对齐，专家仍有分歧，就比较各自的依据和需要验证的条件，继续核实。四问能帮助找出协作卡在哪里，不能保证每次都得到唯一答案。

如果团队根本没人掌握必要知识，就要学习或寻求外部帮助。主要障碍来自资源、权限或利益冲突时，则要处理对应的问题。

## 文档交出去了，怎样才算真的交接了？

老张离职前，除了写文档，还可以和接手者一起处理一次真实问题。

让接手者从找记录开始，说明自己为什么采用这条规则。遇到例外时，试着联系相关同事；如果联系不上，再看看能不能找到替代来源。

这样试一遍，容易看出交接还缺什么。可能是文档少了一条说明，也可能是接手者还不认识关键联系人，或者尚未取得查询权限。发现哪一处不足，就在离职前尽量补上。

团队能做成多少事，既取决于成员掌握的知识，也取决于这些知识能否在具体任务中被取得、核对和使用。

下次遇到“团队里明明有人懂，问题还是解决不了”，可以先问一遍。

**找对人了吗？拿得到信息吗？答案可靠吗？信息对得上吗？**

处理过后，把新确认的知识保存下来，让相关同事知道分工和查找方式有什么变化。

交接是否完成，有一个实际的检验。下次类似的问题出现时，接手者能不能顺着留下的线索，把事情继续做下去？

交互记忆系统提醒我们一件事：团队里有人懂，不等于团队能用上这个懂。知识分散在每个人脑子里，能不能被找到、被核对、被正确拼合，取决于成员之间那张“谁知道什么”的地图是否准确、是否还在更新。下次遇到“问题解决不了”，别急着说“加强沟通”。先问四问，找到卡在哪一环，再决定补什么。团队真正的能力，不在于每个人知道多少，在于这些知识能不能在需要时被取得和使用。

**模型档案卡**

**模型名称**
交互记忆系统（Transactive Memory System，TMS）

**一句话定义**
成员各自的记忆，加上使这些记忆能共同发挥作用的交流过程所构成的系统。

**来源**
韦格纳与合作者于1985年提出，韦格纳于1987年系统论述。代表实验见Wegner等1991年、Liang等1995年的研究。

**调用提示**
遇到“有人懂却解决不了”，先明确具体问题，再依次检查四问：找对人了吗？拿得到信息吗？答案可靠吗？信息对得上吗？

**适用情形**
任务需要多个知识领域，成员之间存在实际依赖。

**使用边界**
四问用于检查知识协作，不能保证消除专业判断的分歧。缺少必要知识时，需要学习或引入外部帮助；资源、权限和利益冲突要另行处理。
