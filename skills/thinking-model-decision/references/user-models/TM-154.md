屏幕上一直黑着，观众已经坐下了

离演示还有二十分钟，观众陆续落座。文稿在你的电脑里，得投到大屏幕上。

你拿自己的电脑连接投影，到了现场才发现接口对不上。屏幕一直黑着，你开始四处找转接器。会场的人说，角落里那台公用电脑应该能连上。换台电脑，把文件拷过去，也能演示。

两条路都能让观众看到文稿，可需要的东西不一样。改用公用电脑，就不用再找转接器了，得确认文件能不能拷过去、打开以后会不会乱码、文字和图片是不是都存在，会不会错行。

可人一急，就容易认准一条道不肯换。转接器找不到，就继续找，一直问到演示快开始了。你原本只想让观众看到文稿，后来满脑子只剩「一定要找到转接器」，那台公用电脑，始终没去尝试。

事后复盘，有人会说，当时要是把任务拆得再细一点儿就好了。可找转接器这件事，拆得再细，也未必比换台电脑更快捷。

清单越拆越长，人还是卡在原地

接到一件挺大的事，人第一反应通常是先拆解成几块。范围小了，好像就知道该干什么了。

年度计划按四个季度排，学外语按词汇、语法、听力、口语来分。写在纸上整整齐齐，还能画成一张漂亮的流程图。

可真做起来，未必那么顺当。学英语时，音标教程看完了，单词背了几千个，连电视剧台词也啃了不少，关掉字幕还是听不懂。

碰到这种情况，人很容易继续往下拆。五步不够就十步，十步不够再加到二十步。清单越来越长，听力还是没有起色。

拆分能帮你看清要做哪些事，却未必能解释眼前为什么卡住。这次听不懂，到底是单词不认识，还是单词认识、连在一起就听不出来？这两件事的练法完全不一样。原因还没弄清，再添几项任务，也不知道该先练哪一项。

目标当然可以拆解。问题树、工作分解、季度计划都有各自的用处。只是拆分完以后，还得接着追问，这几件事该先做哪一件，各自需要什么条件，做了其中一件，会不会妨碍另外一件？

知道该做什么，却不知道这一步为什么做不了

卡住的时候，从你想行动的那一步开始检查。为什么现在做不了？缺的是什么？手段—目的分析就是冲这个问题来的。

手段—目的分析是一种从差距倒推下一步的办法。先比较现状和目标，找出一处差得最多、又能动手的地方，再挑一个能把这处差距缩小的动作。这个动作暂时做不了，就看看它还缺什么，把补齐这些条件当成新的小目标。条件备齐了，再回来做原先那一步。

其中最容易被忽略的一点是，子目标来自所选动作尚未满足的前提。你挑了什么办法，才会撞上相应的条件。

还是回到开头的会场，我们把这个定义拆开来看。

首先比较现状与目标。文稿在自己电脑里，观众看不到。要解决的差距是文稿还没显示在大屏上。按章节把内容分块，解决不了当前这个问题。

然后选择具体行动。把电脑接上投影，是一个可能的办法。接上、画面正常，才算把差距缩了一点。

接着检查前提条件。接口得匹配。发现对不上，就多出一个子目标，找到合适的转接器。找到以后，还得回头把电脑接上、看一眼画面，不能拿到转接器就算完。

你在做准备条件的时候，还有可能碰到新的坎。比如周一要交周报，一周的工作散在聊天群和文档里。你准备先汇总结果，却发现有一项数据还没从后台导出来，那就得先去导数据。要是自己没有导出权限，还得找有权限的同事帮个忙。

换工作也一样。假设你想进一家做 AI 产品的公司，投了二十份简历没回音。对着岗位要求把简历看一遍，发现少了能证明相关能力的项目材料。这时候才轮到判断：是把已有项目讲清楚，还是真得补一段实践。

每往下深挖一层，追问的都是同一件事。要做刚才那一步，还缺少什么？

图画不出来，卡在三张表的算法不一样

把手段—目的分析这套办法完整走一遍，总共四步：看眼下和目标的差距在哪儿；挑一个能改变现状的动作；动作动不了就查清缺什么，把缺的补上；回到原来的动作。

这四步可以压成八个字，看差、找招、补缺、返回。这里的「招」就是办法、招数，指的是具体动作。

我们开一个例子。你要在周会上讲上季度的用户增长，准备做一页汇报图。数据散在三张表里，还没有一份能直接拿来比较的汇总。开始整理才发现，三张表对「活跃用户」的算法不一样：有的算登录过的，有的只算参与过互动的。这些数字塞进同一张图，比较出来也没意义。

于是，统一口径成了眼下的子目标。要完成它，得先定下这次汇报把哪些行为算作活跃，再按同一个定义、同一个统计周期取数。数据能比了，汇报图才画得下去。

这个子目标，是准备画图时才发现的。你也可以把汇报分成同比、环比、用户结构和渠道贡献几块，但只列这几栏，未必会想到先看一眼三张表的口径。新冒出的条件是顺着具体动作找出来的。

还有一个更朴素的例子。你要在书里找一段话，只记得大概在中后段，不记得页码。离那一带还远，就一次翻几十页；觉得快到了，手会慢下来，翻几页看一眼。找到熟悉的小标题，就开始逐页找。翻过了，再往回翻。

翻书这个例子，能说明差距怎么影响你挑动作。你会按自己估计的位置，调整翻页的方向和幅度。不过这不是手段—目的分析的全部，它还多一步：选好的动作暂时做不了，怎样先把它的条件补齐？

一条一条试过去，为什么就是试不完

这套方法可以追溯到 20 世纪 50 年代末。艾伦·纽厄尔（Allen Newell）、赫伯特·西蒙（Herbert A. Simon）和克利夫·肖（J. C. Shaw）合作研制通用问题求解器，英文名为 General Problem Solver，简称 GPS。他们想造一台能对付各种问题的机器，换个题目也不用重写程序。这里的 GPS 与手机导航使用的全球定位系统没有任何关系。

先想一个最笨的办法。让计算机解题，最直接的方式是一条条试过去，试到能到终点的那条为止。

这办法很快就会撞墙。假设每一步都有两种选择，连选十次就有一千多种走法，二十次超过一百万种，三十次超过十亿种。每多走十步，可能的组合就翻大约一千倍。纽厄尔等人拿迷宫打过比方，岔路越多、走得越深，要试的路就越多，谁也试不完。

GPS 换了做法。它用手段—目的分析，先看眼下和目标差在哪儿，只挑跟这处差距有关的动作去试，把大量无关的走法挡在外面。动作需要的前提没有准备齐全，就往下增设子目标。这样能少走很多冤枉路，但不保证每次都挑到最好的那条路径。

一次只盯一个目标，为什么会卡死

按照清单做完第一项，再处理第二项，看着顺理成章。可几个子目标之间会互相影响，做到后面，有时候得把前面的成果拆掉重来。

人工智能规划研究里有个经典例子，叫萨斯曼异常。桌上有 A、B、C 三块积木。起初 C 压在 A 上面，B 单独搁在桌上。目标是从上到下依次摆成 A、B、C，也就是 C 落在最底下。规则很简单，一次只能挪一块，而且只能挪上面空着的那块。

假如先完成「把 B 放到 C 上」，直接把 B 搬过去就行。此时从上到下是 B、C、A。接下来想「把 A 放到 B 上」，才发现 A 被压在最下面。要动 A，就得先把 B 挪开、再把 C 挪开。刚才那个「B 在 C 上」，白做了。

重新回到最初的摆法。换个顺序，先把 C 移到桌上，再把 A 放到 B 上。这时 A 叠在 B 上，C 单独放着。接下来要把 B 放到 C 上，得先拿下压在 B 上的 A，刚完成的「A 在 B 上」又被拆开了。

真正能成的顺序是交叉着来：先把 C 挪到桌面，暂时不管「A 放到 B 上」，接着把 B 放到 C 上，最后再把 A 放到 B 上。三步穿插着走，一个都保得住。

这个例子说明，两个子目标没法各自做完再拼到一起。前一步做完，可能正好把后一步要用的条件堵住了。几件有牵连的事，得放在一起安排。

每个小目标都做成了，事情为什么反而做死了

积木摆错了，还能拆开重来。有些事就没这么方便。

假设仓库里有 A、B 两箱物资，都要送到会场。只有一辆车，一次正好装下两箱。燃料只够跑一趟，路上没法补，也没有别的车可用。

清单在纸上写得挺清楚。第一项，把 A 送到会场；第二项，把 B 送到会场。两箱，两条。

照着清单来，先做第一项。装上 A，开车出发。这一箱确实顺利送到了。

卸完货，回头做第二项，才发现车停在会场，燃料已经烧完，B 还在仓库。车回不去，剩下那箱也就运不了了。

只看已送达数量，进度从零变成了一，清单上还能勾掉一项。可「两箱都送到」这件事，已经做不成了。

装车、开车、卸货，每个动作都做成了，偏偏漏了一个前提：两箱得共用同一趟车，必须在出发前一起装上。

所以，一处差距缩小了，不等于整件事在变好。A 送到了，这是进展；可运送 B 的条件，也正是在这一步里被用掉的。这两件事得放在一起看。

动手之前，先看看几件事是不是在抢同一份东西，再问一句，这一步做完，后面还做得了吗？做错了，退得回来吗？要是会花掉补不回来的预算、错过唯一的机会，或者损伤别人的信任，就值得动手前多核对一遍。

事情推不动，先把目标和现状写清楚

事情推不动的时候，先把目标和现状各写一行，再去看缺的具体是什么。

目标要写到能看出做没做到。「把演示做好」太笼统。要是眼下要解决的是投影，就写「周三下午三点前，让会议室里的人都能看清第 12 页那张图」。

现状也一样。「进度还行」等于没说。可以写「文稿在我自己电脑里，接口对不上，现场还有一台公用电脑，不知道能不能连接」。

然后挑一处差距，选一个大概管用的动作。动不了，就查它缺什么，先处理最挡路的那一项。条件备齐了，回头再做原来的动作，看看结果和想的是不是一样。要是情况变了，这个办法还合不合适，也得重新判。

顺手再看一眼，这一步跟别的步骤有没有抢东西。比如这件事派的人，同一时间段是不是还有别的活？这笔钱花出去，后面的活还够不够用？

几件互相牵动的事，要放在一起安排。这一步能帮你看清冲突在哪，但手段—目的分析本身，不会自动把顺序排好。

转接器找了很久，最初要干什么已经忘了

回到演示现场。转接器借不到，能说明的事情其实很少：你原来想的那条路，走不通了。

它说明不了「演示做不成了」。那台公用电脑还没试过，文件拷过去能不能打开也还不知道。公用电脑要是能用，文稿照样能显示出来，演示照样做得成。

人一忙起来，这两件事很容易被说成一件。「转接器借不到」，一句就变成了「演示没法做」。前一句是实话，后一句是自己替自己关了门。门一关，别的办法也就不去想了。

有时候，找转接器还会变成一件不肯放手的事。电话打了好几个，抽屉翻了一遍，又跑去隔壁会议室问。找得越久，越不甘心停下，好像一停下来，前面那些功夫就全白搭了。离演示开始还剩几分钟，反倒没顾上看。

组织里也有类似的事。某个指标本来是拿来看业务好坏，后来大家只盯着数字涨不涨，业务到底受了什么影响，反倒没人问了。一项审批原本是为了防住某个具体问题，年头久了，业务变了，流程照旧。有人提出来要改，得到的回答往往就一句，一直都是这么办的。

这时候接着问，当初设这个指标、这条规定，是要解决什么问题？那个问题现在还在吗？眼下这个办法还管用吗？弄清它本来是为哪个目标服务的，才好判断哪些该留，哪些该改。

事做完了，本事却没长在自己身上

把眼前的题解出来了，不等于对这类题也懂了。尤其刚学的时候，光是找答案就够费神，顾不上琢磨里面的道理。

教育心理学家约翰·斯韦勒（John Sweller）做过一类实验，设计都差不多：同一类题，一组把目标说死，要求求出某个指定的量；另一组不管终点，尽量把手头条件能算的量都算出来。结果后一组在后来的解题和迁移测试里表现更好。

斯韦勒的解释是，人的工作记忆容量有限，能同时记着、处理的东西就那么几样。初学者一边比较现状和目标，一边找解法，还得记住中间步骤，位置就占满了，留给琢磨题目关系的余力自然少。不指定必须算出哪个量，学生才有空从已有条件出发，看看哪些公式和关系能直接用上。当然，这只是一类任务、一个学习阶段的结论，推不成「学习目标越含糊越好」。

所以，想从做事里学到东西，做完还得停一下。刚才为什么这么走，哪些条件起了作用，换道题还能不能用？也可以找一道讲透原理的例题对着看，把解题时没顾上的关系补回来。这样，一次成功的做法才更容易变成下次能用的本事。




手段—目的分析提醒我们一件事。卡住的时候，把问题换成「我这一步为什么做不了，还缺什么」。

回到开头那间会场，还能再省一步。转接器借不到，不等于没了办法，可这道理得在事前想起来才有用。下次坐下之前，先问一句，我要的是观众看见文稿，还是非要这台电脑上投出来？把这两件事分开，公用电脑就不容易被漏掉。

每设一个子目标，都记着它是为哪一步准备的。条件备齐了，就回来；这条路不通，就换一条。别忙到最后，只记得自己还欠一个转接器。

模型档案卡

一句话定义

比较现状和目标差在哪儿，挑一个能缩小差距的动作；动作缺条件，就把补齐条件当子目标，做完了再回来接着做。

来源

20 世纪 50 年代末，艾伦·纽厄尔、克利夫·肖、赫伯特·西蒙合作研制通用问题求解器（GPS）时发展起来。纽厄尔与西蒙在 1975 年图灵奖演讲中阐述了这套思路。

核心机制

差距挑出动作，动作缺什么就长出新的小目标。条件备齐，回到原来的动作，再看看结果。

解决什么问题

目标清楚了，还是不知道下一步干什么；知道该干什么了，又说不清它为什么干不了。

调用提醒

写清目标和现状，挑一处差距，选一个动作，再看它缺什么。动手前额外看一眼，这一步会不会占掉别的步骤要用的东西，或者毁掉它们的前提。

边界

适合目标和现状说得清、能做的动作大致明确的事。它不保证找到最好的办法，也管不了小目标之间打架。目标值不值得追，得另外判；刚开始学的人用它解题，还要留点时间弄懂原理。

如果身边有人清单列了一堆，活却没往前挪，可以把这篇文章分享给他。两个人一起把现状和目标各写一行，挑一个动作，看看它到底缺什么，会不会动到别的活儿。也可以回想一下，上一次清单列完了却推不动，是下一步要的东西还没备齐，还是做这件事的时候，把另一件事要用的条件给占了？

别忙到最后，只记得自己还欠一个转接器。
